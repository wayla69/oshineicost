1. ระบบนี้ทำอะไร ใครใช้

หน้านี้คือเครื่องมือ "กระทบยอดรายได้รายเดือน" — เช็คว่าเงินที่ลูกค้าชำระผ่าน POS ของแต่ละสาขา เข้าบัญชีจริงครบ ทุกบาทไหม ก่อนปิดงบเดือนนั้น

ผู้ใช้งาน

บทบาททำอะไร
Staff/บัญชีอัปโหลดเอกสารธนาคาร/ค่ายบัตร/เดลิเวอรี ทุกช่องทางในเดือนนั้น, ตรวจผลต่าง, รับทราบเหตุผล แล้ว กดส่งตรวจ
ผู้จัดการตรวจสรุปของ staff, ใส่รหัสปิดเดือน, ส่งกลับแก้ถ้ายังไม่พอใจ
เจ้าของระบบตั้งค่ารหัสรับเงิน / บัญชีธนาคารสาขา / MID เครื่องรูดบัตร ที่ ตั้งค่าระบบ

หลักการสำคัญ

  • POS = ความจริงด้านการขาย · Statement = ความจริงด้านเงินสด · ต่างกัน = ต้องอธิบายได้
  • ทุกผลต่างต้องมีเหตุผล ก่อนปิดเดือน — รับทราบไม่ใช่ลบ ผลต่างยังโชว์อยู่ในไฟล์ Excel ที่ผู้จัดการเซ็น
  • ปิดเดือนแล้ว = แก้ไม่ได้ นอกจากผู้จัดการกด "ส่งกลับแก้"

2. ภาพรวมการทำงานต่อเดือน

  1. ต้นเดือนถัดไป ระบบดึงยอดขาย POS เดือนที่ผ่านมาจากสำนักงานใหญ่อัตโนมัติ (ทุก 06:00)
  2. Staff เลือกเดือน + สาขา ที่ต้องการปิด — จะเห็นว่าเหลือเอกสารอะไร, ช่องทางไหนต่าง
  3. อัปโหลดเอกสาร ของทุกช่องทาง (รายละเอียดในส่วนที่ 4)
  4. ระบบจับคู่อัตโนมัติ POS ↔ Statement รายวัน — เห็นทันทีว่าวันไหนต่างเท่าไร
  5. ตรวจ + รับทราบผลต่างที่อธิบายได้ (เช่น ค่าธรรมเนียม/ปัดเศษ, เงินติดในระบบบัตร) ใส่เหตุผลที่ระบุสาเหตุจริง — หรือถ้าเป็นการกดผิดช่อง ใช้ ⇄ บันทึกผิดช่อง (ย้ายช่อง)
  6. กดส่งตรวจ — เปลี่ยนสถานะเป็น "รอผู้จัดการตรวจ"
  7. ผู้จัดการตรวจ ทั้งหน้าสรุป + เหตุผลที่ staff รับทราบ → ใส่รหัสปิดเดือน
  8. ดาวน์โหลดไฟล์ Excel สำหรับเก็บเข้าแฟ้มและส่งให้สำนักงานบัญชี
💡 ส่งตรวจไม่จำเป็นต้องเคลียร์ครบ 100% — รับทราบเหตุผลครบทุกผลต่างก็ปิดได้ ระบบไม่บังคับให้ยอดต้องตรงเป๊ะ แต่บังคับให้ทุกผลต่างต้อง มีคำอธิบาย

3.2 หน้าภาพรวมทุกสาขา (หน้าแรก)

ตารางขนาดใหญ่ — แถว = สาขา, คอลัมน์ = ช่องทาง (QR/CASH/TRANSFER/CREDIT/GRAB/LM/COUPON)

  • คอลัมน์ ความคืบหน้า — แถบสีเขียว/ส้ม/แดง บอกว่าเดือนนั้นทำไปกี่ % (จาก # วันที่ ok / วันที่มียอด)
  • คอลัมน์ เหลือ N เรื่อง — ตัวเลขที่ต้องเคลียร์ก่อนปิดเดือน
  • คอลัมน์ สถานะ — กำลังทำ / รอผู้จัดการ / ปิดเดือนแล้ว
  • คลิกแถวสาขา → เข้าหน้ารายละเอียดสาขานั้น
  • คลิกช่องช่องทาง → เข้าสาขานั้นแล้วเปิดการ์ดช่องทางอัตโนมัติ

3.3 หน้ารายละเอียดสาขา

เปิดจากการคลิกแถวในหน้าภาพรวม ประกอบด้วย 4 บล็อก (เรียงจากบนลงล่าง)

  1. เอกสารประจำเดือน — chip รายการเอกสารที่ต้องอัปโหลด (เขียว = อัปโหลดแล้ว, ส้ม = ขาดวันท้าย, แดง = ยังไม่อัปโหลด)
  2. ตารางช่องทาง — 7 แถว ช่องทาง × คอลัมน์ POS / เงินเข้าจริง / ผลต่าง / สถานะ
    • คลิกแถว → กางรายวัน + ที่มา POS (รหัสรับเงิน) + ปุ่มเครื่องมือเฉพาะช่องทาง
    • ตรวจผลต่างรายวัน (กระทบยอดตามวันที่): ช่องทางที่มีผลต่างจะมีตาราง รายวัน ขึ้นมา — แต่ละวันที่ต่างกดปุ่ม รับทราบวันนี้ ใส่เหตุผลแยกราย วัน (ไม่ต้องรับทราบยอดรวมทั้งก้อน) เมื่อรับทราบครบทุกวัน ช่องทางนั้นจะเคลียร์เอง
    • คลิกเซลล์วัน → day drill: บิล POS รายใบ vs บรรทัด statement ของวันนั้น
    • ปุ่ม 🔧 จับคู่ละเอียด → จับคู่บรรทัด statement ที่ยังไม่ match กับ POS ทีละบรรทัด
  3. โอนภายใน (ถ้ามี) — เงินเข้าที่ระบบเดาว่าไม่ใช่ยอดขาย (เช่น สวีปบัญชี, โอนข้ามสาขา) ตัดออกแล้ว ดูได้ว่ามีอะไรบ้าง
  4. เหลือ N เรื่องก่อนปิดเดือน — รายการที่บล็อกการปิด ทุกแถวมี:
    • 🔍 ดูรายการ — กระโดดไปกางการ์ดช่องทางนั้นทันที
    • ⬆ อัปโหลด — ถ้าเป็นเอกสารที่ยังขาด
    • ✓ รับทราบ + เหตุผล — ยอมรับผลต่างโดยใส่เหตุผล

ด้านล่างสุด: ส่งตรวจ (สถานะ draft) หรือ ส่งกลับแก้ / ปิดเดือน (สถานะ in_review)

วิธีอัปโหลด

  2. เลือกไฟล์ — ระบบจะอ่านล่วงหน้าแล้วโชว์ตัวอย่าง (จำนวนรายการ, ผู้ให้บริการ, สาขาที่ตรวจพบ)

กางแถว CASH → ตาราง 3 ทาง โชว์ POS / สลิป / ฝากธนาคาร / สถานะแต่ละขา

พิมพ์ยอดในช่อง "สลิปนำฝาก" — บันทึกอัตโนมัติ · กด 📷 แนบรูปสลิปได้
ที่ผิดบ่อย
ฝากรวมหลายวันในใบเดียว (ระบบรองรับ) • พิมพ์ยอดผิด • ลืมฝากวันศุกร์ เงินไปเข้าวันจันทร์
รับทราบได้
สลิป-POS ต่าง ≤ ฿10 (ทอนปัดเศษ) — ระบบไม่บล็อกการปิดเดือนถ้ายังไม่ใส่สลิป แต่เงินเข้าธนาคารต้องตรง

5.3 เงินโอน

เอกสาร
สเตทเมนต์ธนาคารทุกใบที่รับเงินโอน (รหัส ANY = อาจเข้าได้หลายแบงก์ ต้องอัปทุกใบ)
วิธีจับคู่
POS รหัสโอน + ANY ↔ บรรทัด credit ที่ไม่ใช่ QR/CC/payout — ยอด+วันตรง
ตรวจอะไร
กางแถว TRANSFER → ดู chip ธนาคารที่ใช้ตรวจ (อาจมีหลายใบ) + กริดรายวัน
ที่ผิดบ่อย
ลูกค้าโอนวันเสาร์-อาทิตย์ เข้าจริงวันจันทร์ (กดเซลล์วันจันทร์ดูได้) • โอนข้ามแบงก์ ค่าธรรมเนียมหักจากยอด
เครื่องมือ
🔧 จับคู่ละเอียด — สำหรับโอนที่ระบบเดาวันไม่ออก ลากจับคู่ได้

5.4 บัตรเครดิต — 2 ขั้น

เอกสาร
สรุปยอดบัตรจากค่ายบัตร (KTC, BAY, KBANK, SCB) + สเตทเมนต์ธนาคาร
วิธีจับคู่
ขั้น 1 — ยอดรูด ↔ สรุปบัตร (gross):
  ยอดรูดในเครื่อง EDC (POS) = ยอดที่ค่ายบัตรสรุป (ก่อนหักค่าธรรมเนียม + VAT)
ขั้น 2 — ยอดสุทธิ ↔ เงินเข้า:
  ยอดสรุป − ค่าธรรมเนียม − VAT 7% = ยอดที่ค่ายบัตรโอนเข้าบัญชี
  เคส KTC พิเศษ: ค่ายบัตรหักยอด settlement บัตร KTC กับ KTB statement สุทธิ
ตรวจอะไร
กางแถว CREDIT → เห็น 3-way chain แยกตามค่ายบัตร แต่ละค่ายมี 2 ขั้นและสถานะของแต่ละขา
ตั้งค่าครั้งแรก
ใส่อัตราค่าธรรมเนียม % ของแต่ละค่ายบัตร (ปุ่ม ✎ ค่าธรรมเนียม & VAT)
ที่ผิดบ่อย
VAT 7% ที่ค่ายบัตรหักไม่เท่ากันทุกค่าย • บัตรต่างประเทศมี cross-border fee • payout ข้ามเดือน (สิ้นเดือน ↔ ต้นเดือนถัดไป)

5.5 Grab — 2 ขั้น

เอกสาร
รายงาน Grab (Excel) + สเตทเมนต์ KBANK
วิธีจับคู่
ขั้น 1: POS รหัส GRAB ↔ ยอด gross ในรายงาน Grab (รายวัน)
ขั้น 2: ยอดสุทธิรายวัน (หลังหักค่าธรรมเนียม + VAT) ↔ เงินเข้าบัญชี KBANK
  Grab โอนวันถัดไป — บางครั้ง รวมหลายวันใน 1 โอน ระบบจับให้
ตรวจอะไร
กางแถว GRAB → ตาราง payout trace: วันขาย / ยอดสุทธิ / เงินเข้า / วันที่เงินเข้า / สถานะ
ที่ผิดบ่อย
payout สิ้นเดือนตกเดือนถัดไป (ยังไม่ตรง = "รอเงินเข้า") • Grab refund บิลเก่า ขึ้นเป็นยอดลบ

5.6 Line Man — 2 ขั้น (จ่ายตามยอดสะสม ฿500)

เอกสาร
รายงาน LINE MAN + สเตทเมนต์ KBANK
วิธีจับคู่
ขั้น ① ยอดขาย POS ↔ รายงาน LM (รายบิล เดือนเดียวกัน) · ขั้น ② ยอดสุทธิ ↔ เงินโอนเข้าบัญชี — LINE MAN โอนตามยอดสะสม ฿500 ไม่ใช่ T+1 รายวันแบบ Grab: ยอดสุทธิจะสะสมจนเกิน ฿500 แล้วจึงโอน (วันเล็ก ๆ ต่ำกว่า ฿50 ก็ถูกนับสะสมด้วย) · ถ้าทั้งเดือนยอดยังไม่ถึง ฿500 LINE MAN จะโอนยอดทั้งเดือนเข้าบัญชี ในวันที่ 1 ของเดือนถัดไป — ระบบจะจับคู่เงินก้อนนั้นกลับมาให้เดือนที่เป็นเจ้าของยอดโดยอัตโนมัติ (ไม่นับซ้ำในเดือนถัดไป)
ตรวจอะไร
payout trace ในการ์ด LINEMAN — สถานะ ✓ ตรง / รอเงินเข้า (= ยอดยังสะสมไม่ถึง ฿500 หรือยังไม่อัปสเตทเมนต์เดือนถัดไป ยังไม่ใช่ปัญหา)
ที่ผิดบ่อย
เดือนยอดน้อย (< ฿500) เงินตกไปโอนวันที่ 1 เดือนถัดไป — ต้องอัปสเตทเมนต์เดือนถัดไปด้วย ระบบจึงจะจับคู่ครบ • อย่าตีว่าเงินก้อนวันที่ 1 เป็นรายได้ของเดือนใหม่ (เป็นของเดือนก่อน)

5.7 คูปอง (KTC / BAY / อื่น ๆ)

เอกสาร
สรุปคะแนน KTC, สรุปคะแนน BAY (เฉพาะที่สาขามียอดแลก)
วิธีจับคู่
POS รหัส KTCPOINT/BAYPOINT (ยอดแต้มที่แลก) ↔ ยอด settlement จาก issuer
เคสพิเศษ KTC
เงิน settlement ไม่ได้เข้าตรง — ค่ายบัตรหักออกจากยอดเงินเข้า KTB ของบัตรเครดิต KTC แทน (โชว์ "in KTC deposit")
ตรวจอะไร
กางแถว COUPON → การ์ดแยกตาม issuer / ปุ่ม 🎟️ รายละเอียดคูปอง เปิดหน้าวิเคราะห์คูปองซีรีส์ในแอป (#coupon)
ที่ผิดบ่อย
แลกแต้มเดือนก่อน settlement มาเดือนนี้ • คูปอง 3rd-party ที่ยังไม่ตั้งค่า issuer

5.8 วิเคราะห์คูปองซีรีส์ (#coupon)

หน้า วิเคราะห์คูปองซีรีส์ (⋯ เพิ่มเติม → 🎟️ วิเคราะห์คูปองซีรีส์ หรือปุ่ม 🎟️ รายละเอียดคูปอง ในแถว COUPON) ดึงข้อมูลจาก pos_coupon_day เดียวกับที่ร่างบัญชีใช้คำนวณส่วนลด — ยอดจึงสอดคล้องกันเสมอ

ข้อมูล
ส่วนลดคูปองแยกตาม ซีรีส์ (coupon_series_id) · master สาขาเท่านั้น · เลือกสาขาหรือดูทุกสาขา
ระดับเวลา
สลับ เดือน / สัปดาห์ / วัน ได้จาก gran toggle · สัปดาห์/วัน ต้องเลือกวันที่จาก date picker
ตัวเลขในตาราง
จำนวนใช้ · มูลค่าส่วนลด · MoM (เทียบช่วงก่อน — ▲แดง=ส่วนลดมากขึ้น ▼เขียว=น้อยลง) · % ของรวม
Drill
คลิกแถวซีรีส์ใด → แสดง แยกรายสาขา + แยกรายวัน ของซีรีส์นั้น · กด ✕ เพื่อปิด drill
ความสอดคล้องบัญชี
ยอดรวมในหน้านี้อ้างอิง pos_coupon_day.discount_amount — ตัวเลขเดียวกับบรรทัด "ส่วนลด/โปรโมชัน" ในร่างบัญชีรายวัน
หมายเหตุ
วิเคราะห์คูปองซีรีส์อยู่ในแอปหลักแล้ว (route #coupon) — หน้าเดิม classic.html ถูกยกเลิกใน เฟส 6 (2026-06-19)

5.9 ตรวจเงินเข้าธนาคาร — Payout Matching (#payout)

หน้า 💳 เงินเข้าธนาคาร แสดงการจับคู่ ยอดสุทธิรายวัน ↔ เงินโอนเข้าบัญชี แยกตามช่องทาง ทุกประเภท (บัตรเครดิต, Grab, Line Man, BAY Point, KTC Point) — เปิดจากปุ่ม 💳 เงินเข้าธนาคาร บนหน้าสาขา หรือ ⋯ เพิ่มเติม → บัญชี / งานสาขา → 💳 ตรวจเงินเข้าธนาคาร

ยอดสรุป
ด้านบนแสดง ยอดสุทธิรวม · เข้าบัญชีแล้ว · รอเงินเข้า (ถ้ามี) — ครอบคลุมทุกช่องทาง
แต่ละช่องทาง
การ์ดแสดงสถานะ ✓ ตรง หรือ รอเงินเข้า พร้อมรายการวันขาย / ยอดสุทธิ / เงินโอน / วันที่โอน / ช้ากี่วัน
KTC Point
แสดงแบบพิเศษ "รวมในยอดบัตร" (bank_in_credit) — KTC จ่ายผ่านยอดรวม CC ไม่มีการโอนแยก
รวมหลายวัน
Grab/Line Man อาจรวมหลายวันในโอนเดียว — ระบบแสดง "รวม N วัน" พร้อมรายวันที่รวม
ที่ผิดบ่อย
"รอเงินเข้า" ปลายเดือน = ปกติ (เงินโอนต้นเดือนถัดไป) · ดูร่วมกับ payout trace รายช่องทางในหน้าสาขา

5.10 จัดการข้อแตกต่าง — Discrepancies Admin (#discrepancies)

หน้า ⚙️ ข้อแตกต่าง คือ admin view สำหรับตรวจสอบและจัดการข้อแตกต่างที่ระบบตรวจพบ — เปิดจากปุ่ม ⚙️ ข้อแตกต่าง บนหน้าสาขา (ต้องมี session แล้ว) หรือ ⋯ เพิ่มเติม → บัญชี / งานสาขา → ⚙️ จัดการข้อแตกต่าง · ใช้คู่กับ (ไม่แทนที่) ตาราง "ตรวจผลต่างรายวัน" ในหน้าสาขา

กรอง
เลือก สถานะ (รอแก้ไข / ยอมรับ / ปรับแล้ว / ปฏิเสธ / ทั้งหมด) + พิมพ์ ช่องทาง / ธนาคาร แล้วกด "ค้นหา" หรือ Enter
จัดเรียง
คลิก header คอลัมน์ "ต่าง (฿)" → เรียงตามขนาดผลต่าง (มากสุดขึ้นก่อน / กดอีกครั้งกลับ)
Drill รายวัน
คลิกเซลล์ "ต่าง (฿)" → ขยายแถวแสดงผลต่างรายวัน (POS / เงินเข้า / ต่าง / สถานะ) · คลิกอีกครั้งซ่อน
resolve ทีละแถว
แถวสถานะ "รอแก้ไข" มี dropdown → เลือก ยอมรับ / ปรับแล้ว / ปฏิเสธ → บันทึกทันที
มอบหมาย
ช่อง "มอบหมาย…" ใส่ชื่อผู้รับผิดชอบ → บันทึกอัตโนมัติ (onchange)
Bulk resolve
ติ๊กช่อง checkbox หลายแถว → แถบสีเขียวล่างจอปรากฏ → กด "ยอมรับทั้งหมด / ปรับแล้ว / ปฏิเสธ" ทีเดียว
สิทธิ์
ต้องมีรหัส write token (🔑 รหัส) — write ที่ไม่มี token จะได้รับข้อความ "ต้องตั้งรหัสบันทึกก่อน"

5.11 ตั้งค่าระบบ — Setup (#setup)

หน้า ⚙️ ตั้งค่าระบบ คือ admin panel ที่รวมการตั้งค่าทั้งหมดของระบบกระทบยอดไว้ในที่เดียว — เปิดจาก ⋯ เพิ่มเติม → ⚙️ ตั้งค่าระบบ (ย้ายมาจาก /app/setup.html ใน เฟส 4 consolidation) · write บางส่วนต้องรหัสผู้จัดการ (X-Manager-Token)

① Payment Map
ตารางจับคู่รหัสรับเงิน POS → ประเภท/ธนาคาร/วิธีกระทบยอด · แก้ category/bank/reconcile = สิทธิ์พนักงาน (🔑 write token) · กด "Seed จาก POS" เพื่อดึงรหัสใหม่ · กด "ใช้ค่าตามตารางเจ้าของ" = ต้องรหัสผู้จัดการ
② Lane configs
วิธีกระทบยอดราย lane (ประเภท × ธนาคาร) · กด "แก้ไข" → form inline ปรากฏ → ปรับ tol/lag/merge/doc/method → "บันทึก (ผู้จัดการ)" · ต้องใส่รหัสผู้จัดการ · มีผลกับทุกรหัสใน lane เดียวกัน
③ บัญชีธนาคาร
บัญชีธนาคารของแต่ละสาขา — ระบบใช้เลขบัญชีจับเอกสารสเตทเมนต์เข้าสาขาอัตโนมัติ · กด "+ เพิ่มบัญชี" → ใส่สาขา/ธนาคาร/เลขบัญชี/ชื่อบัญชี · ลบได้ด้วยปุ่มสีแดง
④ MIDs
Merchant ID / Terminal ID ของเครื่องรูดบัตรและช่องทางแต้ม (KTCPOINT/BAYPOINT) · จำเป็นสำหรับการแยกแถวแต้มออกจากใบสรุปบัตร
⑤ Statement-code remap
แก้การจัดประเภทรหัสในสเตทเมนต์ธนาคาร เมื่อทีมตรวจพบว่าระบบจัดผิด (เช่น SDCH = นำเงินสดไปฝาก ไม่ใช่ QR) · เลือก channel ใหม่ → กด "บันทึก" → ต้องรหัสผู้จัดการ · มีผลทันทีทั้งข้อมูลเดิมและไฟล์ที่อัปโหลดใหม่ · "คืนค่าเดิม" คืนค่าที่ระบบตีความเดิม · ใช้ OTHER สำหรับรายการที่ไม่ใช่รายได้

7. ส่งตรวจและปิดเดือน

Staff: ส่งตรวจ

  1. เคลียร์ list "เหลือ N เรื่อง" ให้หมด (อัปโหลด, ตั้งค่า, รับทราบ)
  2. กด ส่งตรวจ ที่มุมล่างขวา → สถานะเปลี่ยนเป็น "รอผู้จัดการตรวจ"
  3. หลังส่งตรวจแล้วยังแก้ได้ ถ้าผู้จัดการกด "ส่งกลับแก้" ก่อนปิด

ผู้จัดการ: ตรวจและปิด

  1. เข้าหน้าสาขาที่ส่งตรวจ — บนสุดจะมี 📋 สรุปสำหรับผู้จัดการ รวมทุกช่องทาง + เหตุผลที่ staff รับทราบ
  2. ถ้าพอใจ → กด ปิดเดือน (ผู้จัดการ) → ใส่รหัสปิดเดือน + ชื่อผู้อนุมัติ
  3. ถ้ายัง → กด ส่งกลับแก้ → กลับเป็น "กำลังทำ" staff แก้แล้วส่งใหม่
  4. หลังปิด: ดาวน์โหลด 📊 Excel (Summary / Categories / Daily / Discrepancies / Cash 3-way / Coupon points)
⚠️ ปิดเดือนแล้วทุกค่าจะถูกล็อก ทั้งเหตุผลและการจับคู่ — กลับมาแก้ได้เฉพาะผู้จัดการกด "ส่งกลับแก้" เท่านั้น

7.1 การควบคุมภายในของการแก้ไข (เพิ่ม 2026-06-19)

ปรับให้รัดกุมตามหลักการควบคุมภายใน/ผู้สอบบัญชี:

  • เปิดงวดที่ปิดแล้ว (ส่งกลับแก้) ต้องใช้รหัสผู้จัดการ + ระบุเหตุผล (อย่างน้อย 10 ตัวอักษร) — บันทึกลง audit log ทุกครั้ง · เมื่ออนุมัติใหม่ ระบบจะ สร้างหลักฐานแช่แข็ง (snapshot) ใหม่ ให้ตรงกับตัวเลขสุดท้ายเสมอ
  • ทุกการแก้ด้วยมือต้องมีเหตุผล — ย้ายช่อง / ปรับ lane / รับทราบผลต่าง (รายวันและทั้งช่อง) บังคับใส่เหตุผล ≥10 ตัวอักษร (การจับคู่ด้วยมือถ้าไม่ใส่ ระบบเติมเหตุผลมาตรฐานให้)
  • ระบุตัวตนผู้ทำจริง — ถ้าล็อกอินระบบหลัก (dashboard) ไว้ ระบบจะบันทึก "ใครทำ" จาก บัญชีผู้ใช้จริง (ไม่ใช่ค่าที่หน้าเว็บส่งมา) ลงทุกการแก้ไข + การอนุมัติ — แบ่งแยกหน้าที่ (ผู้จัดทำ ≠ ผู้อนุมัติ) ตรวจจากตัวตนจริง
  • หลักฐานแช่แข็งผูกกับเอกสารต้นทาง — ตอนปิดงวด snapshot จะเก็บ รายชื่อ + ลายนิ้วมือ (SHA-256) ของเอกสารทุกไฟล์ ที่ใช้คำนวณงวดนั้น (ใบรับรองการกระทบยอดแสดงจำนวนไฟล์ที่ผูกไว้)

8. ตั้งค่าระบบ (สำหรับผู้จัดการ)

เข้าจาก ตั้งค่าระบบ ↗ มุมบนขวา · ปกติทำครั้งเดียวตอนตั้งสาขา + อัปเดตเมื่อเพิ่ม MID/บัญชี/รหัสรับเงิน

① ตารางจับคู่รหัสรับเงิน

แมปรหัสรับเงินใน POS (เช่น KNNQR) ↔ ประเภท (QR/CASH/...) + ธนาคารปลายทาง + นับ/ไม่นับเข้ากระทบยอด

② วิธีกระทบยอดราย lane

กำหนดวิธีจับคู่ของแต่ละคู่ "ประเภท × ธนาคาร" — เช่น (CREDIT × KTC) = 3-way settlement, (CASH × KBANK) = 3-way slip

③ บัญชีธนาคารของสาขา

เลขบัญชีของแต่ละธนาคาร — ใช้เช็คว่า statement ที่อัปโหลดเป็นของสาขานี้จริงไหม

④ MID เครื่องรูดบัตร / คะแนน

หมายเลข MID ของเครื่อง EDC แต่ละค่ายบัตร — ใช้แมปยอดในสรุปบัตรกับสาขาที่ถูกต้อง

📌 พารามิเตอร์ในหน้า setup ถูกล็อกด้วย Manager Token — staff เปิดดูได้แต่แก้ไม่ได้

9. รายงานและเครื่องมือเพิ่มเติม

เปิดได้จากปุ่ม ⋯ เพิ่มเติม มุมขวาบนของหน้าแรก (และบางอย่างอยู่ในหน้าสาขา/หน้าตั้งค่า) — ทุกรายงาน พิมพ์เป็น PDF ได้ (เปิดแล้วกดปุ่ม 🖨️ พิมพ์ / บันทึก PDF)

9.1 รายงานข้อผิดพลาดประจำเดือน (ทุกประเภท)

รวม ข้อผิดพลาดทุกชนิดที่พบในเดือนนั้น ไว้ในใบเดียว — ไม่ใช่แค่การบันทึกผิดช่อง · เลือกสาขาได้จากเมนูดรอปดาวน์มุมขวา (หรือดูทุกสาขา)

  • ตารางข้อผิดพลาดทั้งหมด — แต่ละแถวมี ประเภท + ช่องทาง/รหัส + รายละเอียด + ยอด + สถานะ (ค้าง = ยังต้องจัดการก่อนปิดเดือน · รับทราบแล้ว · แก้ไขแล้ว) + เหตุผล
  • ประเภทที่รวม: ยอดต่าง (POS≠เงินเข้า) · เงินเข้าเกิน (ไม่มียอด POS) · ขาดเอกสาร · เงินโอนเข้าไม่ครบ/ช้า (Grab/LM/บัตร) · รหัสยังไม่ตั้งธนาคาร · บันทึกผิดช่อง
  • รายละเอียดบันทึกผิดช่อง (ส่วนท้าย) — สรุปรายสาขา + แนวโน้ม + ช่องที่สับสนบ่อย + คำแนะนำโค้ชแคชเชียร์ + ใบเซ็นรับทราบ (พิมพ์/PDF) ยังอยู่ครบเหมือนเดิม
  • 🖨️ พิมพ์/PDF (หนึ่งหน้าต่อสาขา) · ⬇ Excel — แผ่นแรก "ข้อผิดพลาดทั้งหมด" แล้วตามด้วยแผ่นบันทึกผิดช่อง

รายงานนี้ช่วยให้ผู้จัดการเห็น ทุกเรื่องที่ต้องจัดการในเดือนนั้นในที่เดียว — บันทึกผิดช่องเป็นเพียงประเภทหนึ่ง

9.2 รายงานการจับคู่รายวันทั้งเดือน

ใช้ตรวจให้มั่นใจว่า ทุกวัน × ทุกช่องทางจับคู่กับเอกสารถูกครบ ในใบเดียว

  • เปิดจาก หน้าสาขา → ปุ่ม 🖨️ ตรวจการจับคู่รายวัน (เฉพาะสาขานั้น) หรือ ⋯ เพิ่มเติม → รายงานการจับคู่รายวัน (ทุกสาขา)
  • มี KPI ด้านบน (จับคู่ตรง X/Y · ต้องตรวจ · รอเอกสาร · POS รวม · เอกสารรวม · ผลต่างสะสม)
  • ตารางไล่ทุกวัน — แถว ✗ ต่าง / ขาดเอกสาร ขึ้นสีแดง, รอเอกสารตามรอบ สีเหลือง (ปกติ), ตรงแล้วเป็น ✓
  • แบบทุกสาขา = เฉพาะ 5 สาขาหลัก · ท้ายใบมีช่องเซ็น 3 คน
  • 📅 สรุปบัญชีรายวัน — ตารางไล่ทุกวัน × ช่องทาง บันทึกเป็น ยอดเต็ม (gross) โดย แยกบรรทัดส่วนลด ออกจากค่าธรรมเนียม/VAT/สุทธิ — staff ใช้ลงบัญชีรายวันได้ · มีคอลัมน์ รหัสบัญชี / ชื่อบัญชี (เว้นว่างไว้ก่อน เติมภายหลังที่ /api/account-map)
  • 💰 ท้ายใบมีสรุปการรับเงินทั้งเดือน — รายช่องทาง: รหัส/ชื่อบัญชี · ยอดรับเต็ม · ส่วนลด · ค่าธรรมเนียม · VAT · สุทธิเข้าบัญชี พร้อม 📒 ร่างการบันทึกบัญชี (Dr/Cr) (รายได้ลงเต็มยอด ส่วนลดแยกบัญชี) ให้ฝ่ายบัญชีตรวจตรงกับยอดที่เข้าจริง (มีประมาณการภาษีขาย output ให้ด้วย)
  • 📆 ตัวกรองรายวัน (filter by date) — มี ช่องเลือกวัน บนหัวรายงาน · เลือกวันเดียวแล้วรายงานจะ ย่อเหลือเฉพาะวันนั้น และแสดง 📒 ร่างการบันทึกบัญชี (Dr/Cr) ของวันนั้นโดยตรง — เอาไปลงบัญชีรายวันได้เลย · กด "↺ ทั้งเดือน" เพื่อกลับไปดูทั้งเดือน (URL: /api/monthly-report?...&day=YYYY-MM-DD)
  • 📑 ปุ่ม "ฉบับตรวจสอบ (ละเอียด)" (ในหน้าสาขา) — เพิ่มหลักฐานระดับบรรทัดสำหรับผู้ตรวจสอบ: รหัส POS ทุกตัว · ยอดบัตรเครดิตราย acquirer (ค่าธรรมเนียม/VAT/สุทธิ) · ทุกบรรทัดเงินเข้าบัญชี (วันที่/อ้างอิง) · Grab/LM · การจับคู่ด้วยมือพร้อมเหตุผล — ตรวจสอบได้ทุกบาท

อยากดู "บรรทัดจริง" ของวันเดียว (รายการธนาคารทีละบรรทัด) ใช้ รายงานหลักฐานรายวัน: เปิด /api/daily-report?day=YYYY-MM-DD (เว้น branch_id = ทุกสาขา)

9.3 สรุปบัญชีรายวัน (รายใบ) — แต่ละวัน = 1 ใบ

เหมือนส่วน "📅 สรุปบัญชีรายวัน" ในรายงานการจับคู่ (§9.2) แต่ดึงออกมาเป็น หน้าแยกของตัวเอง และแสดงเป็น การ์ดรายวัน (1 วัน = 1 ใบบันทึกบัญชี) ดูง่ายทีละสาขา

  • เปิดจาก ⋯ เพิ่มเติม → 📅 สรุปบัญชีรายวัน (รายใบ)
  • เลือกทีละสาขา ได้จาก dropdown มุมขวา (เริ่มที่สาขาแรก) · ด้านบนมีแถบสรุปทั้งเดือน (ยอดเต็มรวม · ส่วนลดรวม · ค่าธรรมเนียม · VAT · สุทธิเข้าบัญชี · จำนวนใบ)
  • แต่ละการ์ด = 1 วัน ไล่ทุกช่องทางของวันนั้น (เงินสด/QR/บัตร/Grab/LINE MAN…) บันทึกเป็น ยอดเต็ม (gross) โดย แยกบรรทัดส่วนลด ออกจากค่าธรรมเนียม/VAT แล้วได้ สุทธิ ต่อช่องทาง + รวมวันนี้ ท้ายการ์ด
  • คอลัมน์ รหัสบัญชี มาจากที่ตั้งไว้ใน ตั้งค่าระบบ (หรือ /api/account-map) — เว้นว่างได้
  • แต่ละการ์ดมีปุ่มพับ "📒 ร่างบันทึกบัญชีวันนี้ (Dr/Cr)" — กางออกเพื่อดูคู่เดบิต/เครดิตของวันนั้น (เงินสด/ธนาคารสุทธิ · ส่วนลด · ค่าธรรมเนียม · VAT เป็นเดบิต / รายได้เต็มยอดเป็นเครดิต) เอาไปลงบัญชีรายวันได้เลย
  • 🖨️ พิมพ์/PDF — ออกเป็นแผ่นการ์ดรายวันให้ฝ่ายบัญชี (เลือกสาขาเดียว หรือเว้น = ทุกสาขา หน้าละสาขา) · มีร่างบันทึกบัญชี Dr/Cr ในทุกการ์ด

ตัวเลขทุกตัวมาจากชุดเดียวกับ §9.2 (จอ ↔ กระดาษตรงกันทุกบาท) · เปิดผ่าน /api/daily-accounts (จอ) และ /api/daily-accounts.print (พิมพ์)

คูปอง & ส่วนลด: ช่อง คูปอง นับเฉพาะ แต้ม KTC/BAY ที่ค่ายบัตรจ่ายคืนเป็น เงินรับจริง · ส่วนลดบนบิล (ส่วนลดเด็ก / ผู้สูงอายุ / วันเกิด / พนักงาน ฯลฯ) ที่กดลดราคาบิล — แม้ลูกค้าจ่ายส่วนที่เหลือด้วยเงินสด/QR/บัตร ไม่ได้จ่ายผ่านคูปอง — จะถูกดึงจากข้อมูล POS (pos_coupon_day) มาแสดงเป็นบรรทัด "ส่วนลด / โปรโมชัน" โดย บวกกลับเข้ารายได้เต็ม (gross) แล้วหักออกเป็นบรรทัดส่วนลด (สุทธิเท่าเดิม) — รายได้จึงเป็นยอดเต็มก่อนหักส่วนลด ตรงตามจริง · (ส่วนลดจากแต้ม KTC/BAY ไม่นับซ้ำในบรรทัดนี้ เพราะค่ายบัตรจ่ายคืนเป็นเงินจริงแล้ว)

9.4 พจนานุกรมรหัสในสเตทเมนต์ + แก้รหัสเอง

สเตทเมนต์ธนาคารมี "รหัสย่อ" ที่ระบบใช้แยกประเภทอัตโนมัติ (เช่น SDCH = นำเงินสดไปฝาก, IORSDT = รับโอนระหว่างธนาคาร) — เปิดดูได้ที่ ⋯ เพิ่มเติม → 📖 พจนานุกรมรหัสในสเตทเมนต์ (รหัสที่ยังไม่ยืนยันขึ้นสีเหลือง "⚠ รอตรวจ" — พิมพ์ใบให้ทีมตรวจ หรือ ⬇ ดาวน์โหลด Excel ไปมาร์กได้)

  • ถ้าพบว่ารหัสถูกตีความผิด ผู้จัดการแก้เองได้ที่ ตั้งค่าระบบ → ส่วน ⑤ "รหัสในสเตทเมนต์ → ช่องทาง"
  • เลือกช่องทางที่ถูก (มีตัวเลือก "ไม่นับ/ไม่ใช่รายได้" สำหรับรายการที่ไม่ใช่ยอดขาย) แล้วกดบันทึก — มีผลทันทีทั้งข้อมูลเดิมและไฟล์ที่อัปใหม่
  • ต้องใช้ รหัสผู้จัดการ · กด "คืนค่าเดิม" เพื่อย้อนได้

9.5 แบนเนอร์เตือน "รูปแบบน่าสงสัย"

ถ้าระบบเจอว่าการ์ดเงินผิดช่องมี รูปแบบซ้ำผิดปกติ (เช่น เกิดเหมือนกันหลายสิบครั้ง คนละธนาคาร วันเดียวกัน) จะขึ้นแบนเนอร์ 🔎 บนหน้าแรกเตือนว่า "น่าจะเป็นรหัสสเตทเมนต์ตั้งผิด ไม่ใช่คนกดผิด" พร้อมลิงก์ไปตรวจพจนานุกรมรหัส — ช่วยจับปัญหาเชิงระบบก่อนให้สาขาเซ็นรับทราบผิด ๆ

9.6 ใบทดสอบและรับรองการใช้งาน (UAT)

⋯ เพิ่มเติม → ✅ ใบทดสอบ + รับรองการใช้งาน (UAT) — ใบเช็กลิสต์พิมพ์ได้ ให้ผู้ใช้เดินทดสอบทีละข้อ ทำเครื่องหมายผ่าน/ไม่ผ่าน แล้วลงนามรับรองก่อนใช้งานจริง

9.7 รหัสเข้าใช้ (สองชั้น)

รหัสใช้กับกรอกที่ไหน
รหัสบันทึก (admin)อัปโหลด / บันทึกข้อมูลปุ่ม 🔑 รหัส (จำไว้ในเบราว์เซอร์)
รหัสผู้จัดการปิดเดือน + แก้รหัสสเตทเมนต์ระบบถามครั้งแรกที่กดงานผู้จัดการ (จำไว้ใน session)

บังคับใช้บนเซิร์ฟเวอร์จริงเท่านั้น — บนเครื่องท้องถิ่นเปิดให้สะดวก ไม่ต้องใส่รหัส

9.8 รายงานติดตามเอกสารที่ยังขาด (ตามงานรายเดือน)

ใช้ไล่ตามว่าแต่ละสาขา ยังต้องอัปเอกสารอะไร และ มีเงินรอเอกสารนั้นจับคู่อยู่เท่าไร — เปิดจาก ⋯ เพิ่มเติม → 📥 ติดตามเอกสารที่ยังขาด

  • เลือกเดือน + สาขาได้บนหน้า → ใช้ตามงานได้ทุกเดือน · พิมพ์ PDF แจกสาขาได้ (มีช่อง ☐ ติ๊ก + ช่องเซ็น)
  • บัตรเครดิต แตกย่อยรายผู้รับบัตร (กสิกร / KTC) พร้อมยอดที่ควรได้ + จำนวนรายการ → รู้ทันทีว่าต้องไปขอ settlement ของค่ายไหน ยอดเท่าไร
  • ด้านบนบอก รวมเงินที่รอเอกสารทั้งเครือ · เรียงสาขาที่ค้างมากขึ้นก่อน

ใช้คู่กับรายงานจับคู่ (9.2): จับคู่ชี้ว่า "ขาดเอกสาร" ช่องไหน → รายงานนี้บอก "เอกสารตัวไหน ของค่ายไหน ยอดเท่าไร" ที่ต้องไปตาม

9.9 บันทึกผิดช่อง (ย้ายช่อง) — กระทบสองยอดพร้อมกัน

ถ้ายอดถูก บันทึกผิดช่องทาง (เช่น ลูกค้าสแกน QR แต่พนักงานกดเป็น "เงินสด") เงินไม่ได้หาย แต่ POS ลงผิดช่อง — ใช้เครื่องมือนี้ ย้ายยอดจากช่องผิดไปช่องที่ถูก โปรแกรมจะ ลดช่องผิด + เพิ่มช่องถูกพร้อมกันทันที (กระทบสองยอดในคราวเดียว) โดยไม่ต้องรันจับคู่ใหม่

  • หน้าสาขา → การ์ด "⇄ บันทึกผิดช่อง (ย้ายช่อง)" → + บันทึกผิดช่อง
  • เลือก จากช่อง (ที่กดผิด) → ไปช่อง (ที่ถูก) + ใส่ จำนวนเงิน + เหตุผล แล้วบันทึก
  • ย้อนกลับได้ — กด ↩ ยกเลิก ที่รายการย้าย ยอดกลับไปช่องเดิม
  • ทุกการย้ายเข้าไปอยู่ใน รายงานเงินบันทึกผิดช่อง (§9.1) ติดป้าย "ย้ายด้วยมือ" เพื่อให้ผู้จัดการเห็นและใช้โค้ชสาขา

ต่างจากการ์ดแนะนำ "เงินอาจถูกบันทึกผิดช่อง" (ที่ระบบจับคู่ POS กับบรรทัดสเตทเมนต์ให้อัตโนมัติ) — เครื่องมือนี้ให้ ระบุเองด้วยมือ เมื่อรู้แน่ว่าย้ายช่องไหนไปไหน · ผ่าน /api/channel-move · ทำได้เฉพาะเดือนที่ยังไม่ปิด

9.10 Dashboard รายได้ตามช่องทาง รายวัน (ทุกสาขาในวันเดียว)

หน้า Dashboard สำหรับผู้บริหาร — เลือกวันจากปฏิทิน แล้วเห็น รายได้แยกช่องทางของทุกสาขาในวันนั้นพร้อมกัน

  • เปิดจาก ⋯ เพิ่มเติม → 📊 รายได้ตามช่องทาง รายวัน (Dashboard)
  • เลือกวันจากปฏิทินมุมขวา — การ์ดทุกสาขาปรับตามวันนั้น
  • มีปุ่มสลับ 3 โหมด:
    • เงินเข้าจริง (บัญชี) — ช่องทาง / ยอดเต็ม / ส่วนลด / สุทธิ (เรียงสาขาสุทธิมากสุด) · แยกคูปอง KTC/BAY (แต้ม) = เงินรับจริง ออกจากคูปองส่วนลดอื่นชุดเดียวกับ §9.3
    • ยอด POS — ยอดที่เครื่อง POS บันทึกแยกช่องทาง (ก่อนกระทบเงินเข้าจริง)
    • ประกบ POS ↔ เงินเข้า — แต่ละช่องทางแสดง POS | เงินเข้าจริง | ต่าง (เงินเข้า = ยอดที่เข้าบัญชี/ค่ายบัตรตาม statement·settlement; ต่าง = เงินเข้า − POS) · ช่องที่ยังไม่ได้อัปเอกสาร เงินเข้า = 0 → ต่างติดลบเท่ายอด POS
  • ด้านบนมี แถบยอดรวมทุกสาขา ที่เปลี่ยนตามโหมด

ผ่าน /api/daily-dashboard?day=YYYY-MM-DD (คืนทั้งฝั่งบัญชีและฝั่ง POS↔เงินเข้าในครั้งเดียว สลับโหมดไม่ต้องโหลดใหม่) · แสดงเฉพาะสาขาหลัก (master) · วันที่ไม่มีข้อมูลขึ้นข้อความว่าง

9.11 รายงานเพื่อการควบคุมภายใน / การถูกตรวจสอบ (Audit & Controls)

กลุ่มรายงาน “การควบคุมภายใน” ในหน้า 📊 รายงาน — ออกแบบตามสิ่งที่ผู้สอบบัญชีขอดู ทุกตัวเป็น อ่านอย่างเดียว (ไม่แก้ตัวเลข) เปิดในแอปและพิมพ์ PDF ได้ · ขอบเขตเฉพาะสาขาหลัก (master)

  • ใบรับรองการกระทบยอด (#certificate) — รายสาขา/เดือน: ยอด POS รวม ↔ เงินเข้าจริงรวม ↔ ผลต่างคงเหลือ (หลังรับทราบ) แยกตามช่องทาง พร้อม ผู้จัดทำ / ผู้สอบทาน / วันที่อนุมัติ และ เลขหลักฐานแช่แข็ง (SHA-256) ของไฟล์งบที่ปิดงวด · ปุ่ม “พิมพ์สาขานี้” / “พิมพ์ทุกสาขา” (แต่ละสาขาขึ้นหน้าใหม่สำหรับเซ็น) · /api/reports/recon-certificate[.print]
  • ทะเบียนการปรับปรุงด้วยมือ (#override) — ทุกการแก้ด้วยมือในเดือน (จับคู่เอง · ย้ายช่อง · รับทราบผลต่าง · ปรับ lane) พร้อม ใคร · เมื่อ · เหตุผล · จำนวนเงิน · รายการที่ ไม่มีเหตุผลกำกับถูกเน้นแดง (จุดที่ผู้สอบจะถาม) · /api/reports/override-register[.print]
  • อายุรายการค้าง (#aging) — รายการกระทบยอดที่ยังไม่ปิด นับอายุจากสิ้นงวด แยกช่วง 0–7 / 8–30 / เกิน 30 วัน · ตรวจงวดที่เลือกย้อนหลัง 2 เดือน (ไม่รวมงวดที่อนุมัติ/ปิดแล้ว) — ของค้างเกิน 30 วันต้องมีคำอธิบาย/แผนปิด · /api/reports/open-items-aging[.print]

รายงานทั้งสามดึงข้อมูลจากตารางที่มีอยู่แล้ว (audit log / การปรับปรุงที่ย้อนกลับได้ / reconcile รายเดือน) — ไม่มีการเปลี่ยนตรรกะบัญชีหรือการกระทบยอด

9.12 ทะเบียนการปิดเดือน + สรุปผลต่างที่รับทราบ

อีกสองรายงานในกลุ่ม การควบคุมภายใน สำหรับการ กำกับติดตาม (monitoring) และการตรวจ นโยบายผลต่าง:

  • ทะเบียนการปิดเดือน (#closereg) — มุมมองข้าม ทุกสาขา × 6 เดือนล่าสุด: แต่ละสาขา-เดือนปิดงวดแล้ว/อนุมัติ/ยังเปิด · ใครอนุมัติ + วันที่ · กระทบยอดแล้วกี่ % · มี หลักฐานแช่แข็ง (snapshot) หรือยัง — ใช้เป็น control dashboard ว่ามีงวดไหนค้างปิด · /api/reports/close-register[.print]
  • สรุปผลต่างที่รับทราบ / Write-off (#accepted) — รวมยอดผลต่างที่ถูก “รับทราบ” แล้วปล่อยผ่าน (ทั้งช่อง + รายวัน) แยกตามเหตุผล และแยกตามสาขา + รายการทั้งหมด · ตั้ง เกณฑ์ต่อรายการ ได้ (ค่าเริ่ม ฿1,000) ระบบ เน้นแดงรายการที่เกินเกณฑ์ ให้ผู้สอบขอหลักฐานเพิ่ม · /api/reports/accepted-variance[.print]

ทั้งคู่อ่านอย่างเดียว ขอบเขตสาขาหลัก · ทะเบียนปิดเดือนใช้ reconcile_overview เดิม · Write-off อ่านจาก recon_lane_adj (accept) + recon_day_ack — ไม่แตะตัวเลขบัญชี

10. เครื่องมือวินิจฉัย (Diagnostics)

เปิดได้จาก ⋯ เพิ่มเติม → ส่วน "วินิจฉัย / Diagnostics" — ใช้สำหรับตรวจสอบเชิงลึก ไม่ใช่งานประจำวัน

10.1 Daily Board — ตารางข้ามสาขาในวันเดียว (#board)

มุมมอง ทุกสาขา × ทุกช่องทาง ใน วันเดียวกัน — เห็นสถานะทั้งเครือในหน้าเดียว

  • เลือกวัน ด้วยปฏิทินมุมขวา หรือกดปุ่ม ◀ ▶ ไปวันก่อน/หลัง
  • แต่ละเซลล์ = ยอด POS ช่องทางนั้น สีเขียว = ตรงแล้ว · สีแดง = ต่าง · สีเหลือง = ขาดเอกสาร
  • แถบสรุปด้านบน: POS รวม · เงินเข้าจริงรวม · ผลต่าง · จำนวนสาขาที่รายงาน
  • ปุ่ม 🖨️ PDF ทุกสาขา ออกรายงานหลักฐานรายวันทุกสาขาเป็น PDF
  • ถ้ามีรหัส POS ที่ยังไม่ตั้งค่า จะขึ้นแบนเนอร์เตือนพร้อมลิงก์ไปตั้งค่า

10.2 Audit Log — ประวัติการแก้ไข (#audit)

บันทึก ทุกการเปลี่ยนแปลงในระบบ โดยอัตโนมัติ — ใครแก้อะไร เมื่อไร ค่าเดิม → ใหม่

  • แสดง 200 รายการล่าสุด · กรองด้วย entity (session, discrepancy, manual_match, day_ack, channel_move, payment_map) ได้จาก dropdown มุมขวา
  • ใช้สำหรับ: ตรวจว่าใครปิดเดือน · ติดตามการแก้รหัส payment map · หา root cause เมื่อตัวเลขเปลี่ยนโดยไม่คาดคิด

10.3 Trend Heatmap — ความคืบหน้ารายวัน (#trend)

ปฏิทินสีแสดง % lane match รายวัน ของสาขาที่เลือก — เห็นแนวโน้มการกระทบยอดทั้งเดือนในแผนที่สีเดียว

  • เลือกสาขา จาก dropdown — ระบบดึง session ที่มีอยู่ของเดือนนั้นให้อัตโนมัติ
  • ถ้ายังไม่มี session (ยังไม่เริ่มกระทบยอด) จะขึ้นข้อความแนะนำให้เปิดหน้าสาขาก่อน
  • สีเขียว = lane match ≥99% · สีเหลือง = 60–98% · สีแดง = <60% · เทา = ไม่มีข้อมูล
  • ตารางสรุปรายสัปดาห์ (W1–W4) แสดง POS รวม · เงินเข้า · % lane match · % coverage

10.4 Bank Coverage — สถานะครอบคลุมสเตทเมนต์ (#bankcov)

ตรวจทุกบรรทัดในสเตทเมนต์ธนาคาร ว่า กระทบยอดครบ / ยังรอ / ตัดออก

  • เลือกสาขา จาก dropdown — ใช้ session ของเดือนที่กำลังดูอยู่
  • แถบสรุปด้านบน: X/Y ตรงแล้ว · % match · ยอดตรง · ยอดยังรอ · ยอดตัดออก
  • ปุ่มกรอง ⌛ ยังรอ / ✓ ตรงแล้ว / ⊘ ตัดออก / ทั้งหมด คัดแสดงเฉพาะสถานะที่ต้องการ (ค่าเริ่มต้นขึ้น "ยังรอ" เมื่อมีงาน)
  • ส่วน 3 ขั้นบัตรเครดิต (แยกราย acquirer): POS gross ↔ สรุปยอดบัตร (ขั้น 1) ↔ เงินเข้าธนาคาร (ขั้น 2) พร้อมสถานะแต่ละขั้น
  • chip รายช่องทาง (เงินสด/QR/บัตร/Grab/LINE MAN) แสดงสัดส่วน matched/ทั้งหมด

ต้องมีสเตทเมนต์ธนาคารอัปโหลดแล้ว ถึงจะมีข้อมูลแสดง — ถ้าหน้าว่าง ให้อัปสเตทเมนต์ในหน้าสาขาก่อน

11. คำถามที่พบบ่อย (Q&A)

Q1. อัปโหลดเอกสารแล้วยอดยังไม่ตรง — ทำยังไง
กด 🔍 ดูรายการ ที่ todo หรือคลิกแถวช่องทางในตาราง → กางรายวัน คลิกเซลล์วันที่แดง → ดู POS bills (ซ้าย) เทียบกับบรรทัด statement (ขวา) ทีละใบ ถ้าระบบเดาวันผิด ใช้ 🔧 จับคู่ละเอียด ลากจับคู่
Q2. ผลต่างเล็ก ๆ (เช่น ฿5 ฿10) ตามไม่ทันต้องทำยังไง
กด ✓ รับทราบ + เหตุผล ใส่เหตุผลสั้น ๆ (เช่น "ทอนปัดเศษ") เหตุผลจะติดไปในไฟล์ Excel ให้ผู้จัดการเห็นตอนอนุมัติ ระบบไม่บังคับเคลียร์เป๊ะ แต่บังคับให้ทุกผลต่าง มีคำอธิบาย
Q3. ยอดเข้าตกเดือน — Grab/LM ขายสิ้นเดือน เงินเข้าต้นเดือนถัดไป
ปกติ — payout trace จะขึ้นสถานะ รอเงินเข้า และไม่บล็อกการปิดเดือน เพราะระบบรู้ว่ารอบ payout ยังไม่ถึง · บัตรเครดิตคล้ายกัน — รูดวันที่ 30 settle เดือนถัดไป รับทราบเป็น "ยอดข้ามเดือน" ได้
Q4. อัปโหลดเอกสารผิดสาขา
ระบบจะ บล็อก ด้วยแถบแดง "เอกสารนี้เป็นของสาขา X — ยืนยันไม่ได้" ไม่ต้องห่วงว่าจะปนกัน · ถ้าอยากเปลี่ยนไฟล์ที่อัปไปแล้ว เข้า เครื่องมือขั้นสูง ↗ มีหน้าจัดการเอกสาร
Q5. รหัสรับเงินใหม่ใน POS — ระบบไม่รู้จัก
จะขึ้น chip ตั้งค่า ในช่องทางที่เกี่ยวข้อง + todo "ระบุธนาคารของ XXX" · ผู้จัดการเข้า ตั้งค่าระบบ → ① ตารางจับคู่รหัสรับเงิน เพิ่มแมปและบอกว่าเข้าธนาคารไหน
Q6. ฝากเงินสดรวมหลายวันในใบเดียว
ระบบรองรับ — ตาราง 3-way จะโชว์ (ฝากรวมวัน) ในคอลัมน์ "ฝากเมื่อ" · พิมพ์ยอดสลิปของแต่ละวันให้ครบ ระบบจะ sum ให้ตรงกับเงินเข้าใบเดียว
Q7. เงินเข้าบัญชีที่ไม่ใช่ยอดขาย (สวีปบัญชี โอนข้ามสาขา)
ระบบเดาให้ใน โอนภายใน (ตัดออกแล้ว) — ตรวจรายการได้ ถ้าเดาผิดเข้า เครื่องมือขั้นสูง ปรับ flag ได้
Q8. ปิดเดือนแล้วพบว่าผิด
ผู้จัดการเข้าหน้าสาขานั้น → กด ส่งกลับแก้ → สถานะกลับเป็น "กำลังทำ" staff แก้แล้วส่งตรวจอีกรอบ · ปิดอีกครั้งใส่รหัสเดิม
Q9. ทำไมต้องใส่ค่าธรรมเนียมบัตรเครดิตเอง
