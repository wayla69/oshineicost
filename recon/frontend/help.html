1. ระบบนี้ทำอะไร ใครใช้

หน้านี้คือเครื่องมือ "กระทบยอดรายได้รายเดือน" — เช็คว่าเงินที่ลูกค้าชำระผ่าน POS ของแต่ละสาขา เข้าบัญชีจริงครบ ทุกบาทไหม ก่อนปิดงบเดือนนั้น

ผู้ใช้งาน

บทบาททำอะไร
Staff/บัญชีอัปโหลดเอกสารธนาคาร/ค่ายบัตร/เดลิเวอรี ทุกช่องทางในเดือนนั้น, ตรวจผลต่าง, รับทราบเหตุผล แล้ว กดส่งตรวจ
ผู้จัดการตรวจสรุปของ staff, ใส่รหัสปิดเดือน, ส่งกลับแก้ถ้ายังไม่พอใจ, เปิดงวดใหม่ถ้าปิดแล้วพบว่าผิด
เจ้าของระบบตั้งค่ารหัสรับเงิน / บัญชีธนาคารสาขา / MID เครื่องรูดบัตร ที่ ตั้งค่าระบบ

หลักการสำคัญ

  • POS = ความจริงด้านการขาย · Statement = ความจริงด้านเงินสด · ต่างกัน = ต้องอธิบายได้
  • ทุกผลต่างต้องมีเหตุผล ก่อนปิดเดือน — รับทราบไม่ใช่ลบ ผลต่างยังโชว์อยู่ในไฟล์ Excel ที่ผู้จัดการเซ็น
  • ปิดเดือนแล้ว = แก้ไม่ได้ นอกจากผู้จัดการกด "เปิดงวดใหม่ (ผู้จัดการ)" — ใส่รหัสผู้จัดการ + เหตุผล (อย่างน้อย 10 ตัวอักษร)

2. ภาพรวมการทำงานต่อเดือน

  1. ต้นเดือนถัดไป ระบบดึงยอดขาย POS เดือนที่ผ่านมาจากสำนักงานใหญ่อัตโนมัติ (ทุก 06:00)
  2. Staff เลือกเดือน + สาขา ที่ต้องการปิด — จะเห็นว่าเหลือเอกสารอะไร, ช่องทางไหนต่าง
  3. อัปโหลดเอกสาร ของทุกช่องทาง (รายละเอียดในส่วนที่ 4)
  4. ระบบจับคู่อัตโนมัติ POS ↔ Statement รายวัน — เห็นทันทีว่าวันไหนต่างเท่าไร
  5. ตรวจ + รับทราบผลต่างที่อธิบายได้ (เช่น ค่าธรรมเนียม/ปัดเศษ, เงินติดในระบบบัตร) ใส่เหตุผลที่ระบุสาเหตุจริง — หรือถ้าเป็นการกดผิดช่อง ใช้ ⇄ บันทึกผิดช่อง (ย้ายช่อง)
  6. กดส่งตรวจ — เปลี่ยนสถานะเป็น "รอผู้จัดการตรวจ"
  7. ผู้จัดการตรวจ ทั้งหน้าสรุป + เหตุผลที่ staff รับทราบ → ใส่รหัสปิดเดือน
  8. ดาวน์โหลดไฟล์ Excel สำหรับเก็บเข้าแฟ้มและส่งให้สำนักงานบัญชี
ส่งตรวจไม่จำเป็นต้องเคลียร์ครบ 100% — รับทราบเหตุผลครบทุกผลต่างก็ปิดได้ ระบบไม่บังคับให้ยอดต้องตรงเป๊ะ แต่บังคับให้ทุกผลต่างต้อง มีคำอธิบาย

3.2 หน้าแรก: Close Board (ปิดเดือน) และรายการสาขา

Close Board (#close) = ภาพเดียวว่าเดือนนี้เหลืออะไรก่อนปิดได้ทั้งเครือ

  • หัวหน้า — เดือน + กำหนดปิด: เดือน M ต้องปิดภายใน วันที่ 5 ของเดือนถัดไป (นับวันตามเวลาไทย) แสดง "อีก N วัน" · เลยกำหนดแล้วแต่ยังปิดไม่ครบ = ชิปแดง "เกิน N วัน" · ปิดครบทุกสาขา = "ปิดครบแล้ว"
  • ตัวเลข 4 ช่อง (นับเฉพาะสาขาที่ยังไม่ปิด):
    • ยังอธิบายไม่ได้ = ผลรวม |ผลต่างที่ยังค้าง| ของทุกช่องทางที่สถานะ "ยอดไม่ตรง" และยังไม่รับทราบ (ผลต่างของเดือน หลังหักวันที่รับทราบรายวันแล้ว และ ไม่นับวันที่เงินยังไม่ถึงรอบ · คูปองใช้ผลต่างแต้มกับใบสรุปคะแนน) + |ยอดต่าง| ของ ยอดโอนจากผู้ให้บริการที่ไม่ตรงรายงาน ที่ยังไม่รับทราบ
    • เอกสารที่ยังขาด = จำนวนเอกสารที่ยังไม่อัปโหลดหรือมีไม่ครบวัน แยกตามชื่อเอกสาร (เช่น สเตทเมนต์ KBANK 2 · รายงาน Grab 1) — ไม่นับเอกสารของช่องทางที่รับทราบไปแล้ว
    • รอเงินเข้าตามรอบ = ยอด POS ของวันที่เงินยังไม่ถึงรอบโอน (สถานะวัน "รอ") — ไม่ต้องทำอะไร ไม่นับเป็นผลต่าง
    • ปิดแล้ว x / n สาขา (+ จำนวนที่รอผู้จัดการตรวจ)
  • ตาราง — แถว = สาขา, คอลัมน์ = QR · เงินสด · เงินโอน · บัตร · Grab · Line Man · คูปอง (+ ยอดโอน เมื่อมีสาขาใดมียอดโอนไม่ตรงรายงาน) · คอลัมน์สุดท้าย = สถานะ (กำลังทำ + % / รอผู้จัดการ / ปิดแล้ว + ผู้อนุมัติ + วันที่)
    ช่องในตารางความหมาย
    ✓ตรงกันแล้ว (ต่างไม่เกินเกณฑ์) · ✓ รับทราบ = รับทราบผลต่างพร้อมเหตุผลแล้ว
    −฿1,200ยังอธิบายไม่ได้ (บวก = เงินเข้าเกิน, ลบ = เงินเข้าขาด)
    ขาด สเตทเมนต์ KBANK (ขอบประ)เอกสารของช่องทางนี้ยังไม่อัปโหลด / มีไม่ครบเดือน
    รอรอบรอเงินเข้าตามรอบ · ตั้งค่า = รหัสชำระใหม่ต้องระบุธนาคาร
    —สาขานี้ไม่มียอดช่องทางนี้ / ไม่ต้องตรวจ
  • ทุกช่องกดได้ → เปิดหน้าทำงานของสาขาที่ช่องทางนั้นทันที (#b/<สาขา>/<ช่องทาง>) · กดชื่อสาขา → หน้าทำงานของสาขา · กดสถานะ → ขั้นส่งตรวจ/ปิดเดือน
  • ลิงก์ ดูรายการสาขา › มุมขวาของหัวหน้า → รายการสาขาแบบเดิม

รายการสาขา (#branches — หน้าแรกของผู้ดูอย่างเดียว / ไม่ล็อกอิน) — แถบความคืบหน้าทั้งเครือ, แถบ "รอฉันตรวจ" (สาขาที่ส่งตรวจแล้ว), แบนเนอร์เงินอยู่ผิดช่อง, รายการสาขาที่ยังมีเรื่องค้าง (กดชิปช่องทาง → เข้าสาขาที่ช่องทางนั้น) และสาขาที่เรียบร้อยแล้ว (พับไว้) · มุมขวาบนมีลิงก์ Close Board ›

3.3 หน้าทำงานของสาขา (เดือนเดียว)

เปิดจาก Close Board หรือรายการสาขา — ลิงก์ #b/<สาขา> เปิดที่ รายการแรกที่ต้องจัดการ, #b/<สาขา>/<รายการ> เปิดที่รายการนั้น (รายการ = QR CASH TRANSFER CREDIT GRAB LINEMAN COUPON หรือ DOCS เอกสาร · PAYOUT ยอดโอน · SETUP รหัสชำระ · RECLASS ผิดช่อง · XFER โอนกันเอง · NONREV โอนภายใน · MOVES ย้ายช่อง · CLOSE ส่งตรวจ/ปิดเดือน)

  1. หัวหน้า (ตรึงไว้ด้านบนเมื่อเลื่อน — จอกว้าง) — สาขา · เดือน · สถานะ (กำลังทำ / รอผู้จัดการตรวจ / ปิดเดือนแล้ว) · กำหนดปิด · ผู้ทำ (ผู้สร้างงวด) · % ที่ตรงแล้ว · เมนู รายงาน ▾ (Excel ปิดเดือน · ใบรับรอง · ตรวจการจับคู่รายวัน · ฉบับตรวจสอบ (ละเอียด) · เงินเข้าธนาคาร · ข้อแตกต่าง · ทะเบียนการปรับปรุงด้วยมือ — กด Esc หรือกดที่อื่นเพื่อปิด) · และ ปุ่มของขั้นถัดไป ทางขวา: ส่งตรวจ (กำลังทำ) · ส่งกลับแก้ / ปิดเดือน (ผู้จัดการ) (รอผู้จัดการตรวจ) · เปิดงวดใหม่ (ผู้จัดการ) (ปิดแล้ว) · ถ้ายังปิดไม่ได้ ปุ่มปิดเดือนเป็นสีจางพร้อม เหตุผลหนึ่งบรรทัด ข้าง ๆ เช่น "ยังเหลือ 2 รายการ" หรือ "มีข้อแตกต่างค้าง 1" (ผู้จัดการเห็น · บัญชีไม่เห็นปุ่มนี้)
  2. ขั้นตอน 4 ขั้น — ① เอกสาร (อัปโหลดแล้ว n/N) → ② จับคู่อัตโนมัติ (ตรงแล้ว % · หรือ "ตั้งค่ารหัส n รหัส" ถ้ามีรหัสชำระใหม่) → ③ อธิบายผลต่าง (เหลือ n เรื่อง) → ④ ส่งตรวจ / ปิดเดือน · ขั้นที่ทำเสร็จมีเครื่องหมาย ✓ ขั้นปัจจุบันมีกรอบสีน้ำเงิน · กดขั้นไหนก็ได้เพื่อไปยังรายการของขั้นนั้น
  3. จอกว้าง (≥900px) แบ่งสองฝั่ง — ซ้าย = รายการงาน 4 กลุ่ม แต่ละแถวมีชื่อ ตัวเลข/สถานะหนึ่งบรรทัด และป้ายสถานะ:
    • ต้องจัดการ — เอกสารที่ยังขาด · รหัสชำระที่ยังไม่ตั้งค่า · ช่องทางที่ยอดไม่ตรง/ขาดเอกสาร/ต้องตั้งค่า · ยอดโอนจากผู้ให้บริการไม่ตรงรายงาน · เงินอาจอยู่ผิดช่อง · โอนกันเอง (แนะนำตัดออก)
    • รอเงินเข้าตามรอบ — ช่องทางที่รอเงินตามรอบโอน (ไม่ต้องทำอะไร)
    • ตรงแล้ว — ช่องทางที่ตรง/รับทราบแล้ว (ช่องทางที่ต่างเล็กน้อย ≤฿100 มีป้าย "ต่างเล็กน้อย" และปุ่ม รับทราบเศษ n ที่หัวกลุ่ม = รับทราบทุกช่องในครั้งเดียว)
    • อื่น ๆ — โอนภายใน (ตัดออกแล้ว) · บันทึกผิดช่อง (ย้ายช่อง) · ส่งตรวจ / ปิดเดือน
    ขวา = รายละเอียดของรายการที่เลือก:
    • ช่องทาง — สะพานตัวเลข ยอด POS → (สรุปยอดบัตร / รายงาน Grab, Line Man → ยอดสุทธิหลังหักค่าธรรมเนียม) → เงินเข้าธนาคาร = ผลต่าง พร้อมบอกว่ารับทราบรายวันไปแล้วเท่าไร รอเงินเข้าตามรอบเท่าไร และยังอธิบายไม่ได้เท่าไร · ปุ่ม เปิดตัวจับคู่ (3.4) · ✓ รับทราบ + เหตุผล / เลิกรับทราบ · ⇄ ย้ายยอดไปช่องอื่น · ใต้นั้นคือที่มา POS (รหัสชำระ กดดูรายวัน) · ตรวจผลต่างรายวัน — แต่ละวันที่ต่างกด รับทราบวันนี้ ใส่เหตุผลแยกรายวัน (เมื่อรับทราบครบทุกวัน ช่องทางนั้นจะเคลียร์เอง) · ตารางบัตร 2 ขั้น / ยอดโอน Grab, Line Man / เงินสด 3 ทาง (สลิปนำฝาก) / แต้มคูปอง / ค่าธรรมเนียม & VAT · ปฏิทินรายวัน — กดวัน → บิล POS รายใบเทียบบรรทัดเงินเข้าของวันนั้น (ตัดออกบรรทัดที่ไม่ใช่ยอดขายได้) + ปุ่ม จับคู่วันนี้ในตัวจับคู่
    • เอกสาร (ปรับ ต.ค. 2569) — บนสุดคือ ช่องวางไฟล์ของเดือน "วางไฟล์ทั้งหมดของ <สาขา> · <เดือน> ที่นี่" — ลากไฟล์ทั้งหมดของเดือน (หลายไฟล์, zip หรือทั้งโฟลเดอร์) มาวาง หรือกด เลือกไฟล์ / เลือกทั้งโฟลเดอร์ → ระบบแยกประเภทจากชื่อไฟล์เอง แล้วแสดง ผลทีละไฟล์ (บันทึกกี่รายการ · ข้ามบรรทัดซ้ำกี่บรรทัด · มีรายการของเดือนอื่นกี่รายการ · ไม่รับเพราะอะไร) + บรรทัดสรุป (§4) · ใต้นั้นคือ เอกสารที่ต้องใช้ แต่ละรายการมี แถบรายวัน (หนึ่งช่อง = หนึ่งวัน: เขียว = มีเอกสาร · กรอบแดง = ขาด · เทา = ยังไม่ถึงกำหนด) และป้าย ครบ / ขาด 27–30 / ยังไม่มี · ปุ่ม ↑ อัปโหลด ทีละเอกสาร (แสดงตัวอย่างก่อนยืนยัน) ยังใช้ได้ · จัดการไฟล์ (เปิดไว้ให้) — % จับคู่ต่อไฟล์ · รายบรรทัด · ย้ายสาขา · ลบ · สิทธิ์ดูอย่างเดียวไม่เห็นช่องวางไฟล์และปุ่มอัปโหลด
    • ยอดโอนจากผู้ให้บริการ (เพิ่ม ต.ค. 2569) — เทียบ ยอดสุทธิในรายงาน Grab / Line Man / บัตรเครดิต กับ เงินที่โอนเข้าธนาคารจริง ทั้งเดือน ทุกแถวที่ยังไม่ตรงนับเป็น "เรื่องค้าง" · ดูรายการโอนรายวัน → หน้าเงินเข้าธนาคาร (#payout) · ✓ รับทราบ + เหตุผล (อย่างน้อย 10 ตัวอักษร) / เลิกรับทราบ · ถ้ายอดเปลี่ยนเกิน ฿100 หลังรับทราบ แถวนั้นจะกลับมาค้างอีกครั้ง
    • รหัสชำระที่ยังไม่ตั้งค่า — ใช้คำตอบจากเอกสาร หรือตั้งค่าเอง (ช่องทาง + ธนาคาร)
    • เงินอาจอยู่ผิดช่อง — การ์ดเล่าเรื่อง + ใช่ เป็นเงินก้อนเดียวกัน / ขอดูรายการ / ไม่ใช่
    • โอนกันเอง — เงินเข้าที่ระบบเดาว่าไม่ใช่ยอดขาย 2 แบบ: ก้อนใหญ่เลขกลม (≥100,000 · ลงท้ายหมื่น · ไม่มีคำว่าขาย) และ รหัสโอนภายใน (IORSDT/NBSDT ของ KTB ไม่ว่ายอดเท่าไร) · ตัดออกทั้งหมด ส่งคำขอเดียว (POST /api/bank-lines/bulk-ignore) บรรทัดที่ตัดไม่ได้ (จับคู่ด้วยมือแล้ว / ตัดไปแล้ว / เดือนปิดแล้ว) ถูกข้ามพร้อมเหตุผล — ย้อนกลับได้ที่ โอนภายใน (UAT TC-26)
    • ส่งตรวจ / ปิดเดือน (ขั้นที่ 4) — รายการที่ยังขวางการปิด (แต่ละแถวมี ไปที่รายการ ›, อัปโหลด, รับทราบ + เหตุผล) · ถ้าไม่มีเรื่องค้างแต่ยังมี ข้อแตกต่างที่ยังไม่ได้ตัดสิน จะขึ้นการ์ดสีเหลืองพร้อมปุ่ม ไปที่ข้อแตกต่าง › · ตารางสรุปสำหรับผู้จัดการ (ทุกช่องทาง + ยอดโอน + โอนภายใน พร้อมเหตุผลที่ staff รับทราบ) · ทะเบียนการปรับปรุงด้วยมือ · ดูใบรับรอง · ปุ่มส่งตรวจ / ส่งกลับแก้ / ปิดเดือน (ปิดเดือน = เปิด แผ่นลงนาม — §7) · เดือนที่ปิดแล้ว: แถบ "เดือนนี้ปิดแล้ว" + เปิดงวดใหม่ (ผู้จัดการ) (แผ่นเดียวกัน: เหตุผล + ยืนยันตัวตน — §7) · สาขาที่ รอผู้จัดการตรวจ และไม่มีเรื่องค้าง เปิดมาที่ขั้นนี้เลย
  4. มือถือ / จอแคบ (<900px) — เห็นรายการงานก่อน แตะรายการ → รายละเอียดเต็มจอ · ปุ่ม ← รายการงาน (หรือปุ่มย้อนกลับของเบราว์เซอร์) กลับมาที่รายการ

เปลี่ยนรายการ = เปลี่ยนเฉพาะแผงขวา ไม่โหลดใหม่ทั้งหน้า · หลังรับทราบ/อัปโหลด/จับคู่ หน้าจะอัปเดตตัวเลขในที่เดิม (รายการที่เลือกและตำแหน่งที่เลื่อนไว้คงเดิม)

3.4 ตัวจับคู่ (จับคู่ด้วยมือ)

ใช้เมื่อระบบจับคู่อัตโนมัติไม่ได้ — เช่น เงินเข้าก้อนเดียวครอบหลายวัน, เข้าเป็นงวด, หรือวันที่ไม่ตรง · เปิดจากปุ่ม เปิดตัวจับคู่ ในช่องทาง หรือ จับคู่วันนี้ในตัวจับคู่ ในรายละเอียดวัน (ติ๊กวันนั้นไว้ให้) · แผงเลื่อนออกมาจากขวา (มือถือ: เต็มจอ) · ทำงานทีละ ช่องทาง · ธนาคาร (มีหลายธนาคารเลือกที่ปุ่มด้านบน)

  1. ① ยอด POS ที่ยังไม่จับคู่ (ซ้าย) — ติ๊กวัน · แก้ช่อง ใช้ ได้ถ้าจับแค่บางส่วน (ไม่เกินยอดคงเหลือของวัน)
  2. ② บรรทัดเงินเข้า (ขวา) — เรียง วันที่ใกล้วันที่ติ๊ก + ยอดที่พอดี ก่อน (ยอดตรงกับที่ยังขาดมีป้าย "ยอดพอดี") · บรรทัดที่ จับคู่ด้วยมือแล้ว / ตัดออกแล้ว — ไม่ใช่รายได้ / จับคู่อัตโนมัติแล้ว / ของสาขาอื่น เป็นสีจาง บอกเหตุผล และติ๊กไม่ได้ (เซิร์ฟเวอร์ปฏิเสธอยู่แล้ว)
  3. ตรงกลาง — ยอด POS ที่เลือก, เงินเข้าที่เลือก และ ต่าง = POS ที่เลือก − เงินเข้าที่เลือก (เป็น สีเขียว เมื่อห่างไม่เกิน ฿1) · ช่องหมายเหตุ (ติดไปในทะเบียนการปรับปรุงด้วยมือ) · ปุ่ม จับคู่ N วัน ↔ M บรรทัด กดได้เมื่อติ๊กครบทั้งสองฝั่ง (กดซ้ำไม่บันทึกสองครั้ง)
  4. จับคู่แล้วแผงยังเปิดอยู่ (จับต่อได้) · ตัวเลขในหน้าสาขาอัปเดตทันที · ด้านล่างคือ คู่ที่จับเองแล้วในช่องทางนี้ — ปุ่ม ยกเลิก คืนบรรทัดเป็น "ยังไม่จับคู่"
  5. ปิดแผง: ปุ่ม ปิด, แป้น Esc หรือกดพื้นที่มืดด้านซ้าย · เดือนที่ปิดแล้วดูได้อย่างเดียว

วิธีอัปโหลด — วางทุกไฟล์ของเดือนในช่องเดียว (แนะนำ)

  1. หน้าสาขา → รายการ เอกสาร → ช่องเส้นประ "วางไฟล์ทั้งหมดของ <สาขา> · <เดือน> ที่นี่"
  2. ลากไฟล์มาวาง — ได้ทั้ง หลายไฟล์, zip (แตกให้เอง) หรือ ทั้งโฟลเดอร์ · หรือกด เลือกไฟล์ / เลือกทั้งโฟลเดอร์
  3. ระบบแยกประเภทจาก ชื่อไฟล์ (สเตทเมนต์ · สรุปยอดบัตร · Grab · Line Man) แล้วตรวจทุกด่านเหมือนอัปทีละไฟล์ — ไฟล์ที่ผิดไม่ทำให้ไฟล์ที่ถูกเสีย
  4. อ่าน ผลอัปโหลด ทีละไฟล์: บันทึกแล้ว (กี่รายการ · ข้ามบรรทัดซ้ำ · รายการของเดือนอื่น เช่น เงินฝากวันที่ 1 ของเดือนถัดไป — นับในเดือนของมันเอง) · ข้าม (ไฟล์เดิมเคยอัปแล้ว / ทุกบรรทัดซ้ำ / ไม่รู้ประเภท) · ไม่รับ (เช่น เป็นเอกสารของเดือนอื่น, เดือนที่ปิดแล้ว, อ่านได้ 0 รายการ) พร้อมเหตุผลภาษาไทย · บรรทัดบนสุดสรุปรวมทั้งหมด · ผลนี้ค้างไว้ให้อ่านจนกด ปิด
  5. ระบบ คำนวณใหม่อัตโนมัติ — แถบรายวันและสถานะเอกสาร/ช่องทางอัปเดตทันที

แถบรายวันของเอกสาร (ดูว่าขาดวันไหน)

เอกสารแต่ละรายการมีแถบหนึ่งช่องต่อหนึ่งวันของเดือน — เขียว = มีเอกสารครอบคลุมวันนั้น · กรอบแดง = ถึงกำหนดแล้วแต่ยังไม่มี · เทา = ยังไม่ถึงกำหนด (วันในอนาคตตามเวลาไทย หรือหลังวันล่าสุดที่ POS มีข้อมูล) · ป้ายด้านขวาสรุปเป็นคำ: ครบ / ขาด 27–30 / ยังไม่มี · ไฟล์หนึ่งไฟล์ครอบคลุมตั้งแต่วันแรกถึงวันสุดท้ายที่มีรายการในไฟล์ (วันที่ไม่มีเงินเคลื่อนไหวระหว่างนั้นถือว่าครอบคลุม) · หลายไฟล์รวมกัน — สเตทเมนต์ 1–10 กับ 20–30 จะเห็นช่องแดง 11–19 ชัดเจน แม้สถานะจะขึ้นว่าอัปโหลดแล้ว · สรุปคะแนน KTC/BAY เป็นเอกสารรายเดือน ไม่มีแถบรายวัน

  2. เลือกไฟล์ — ระบบจะอ่านล่วงหน้าแล้วโชว์ตัวอย่าง (จำนวนรายการ, ผู้ให้บริการ, สาขาที่ตรวจพบ)
  3. ตรวจสาขา + เดือนถูกต้อง → กด ✓ ยืนยันบันทึก

ถ้าเอกสารว่าง (No Data) ยืนยันได้ ระบบจะบันทึกว่า "เดือนนี้ไม่มีรายการ" — เคลียร์ todo ของช่องทางนั้นอัตโนมัติ

ระบบมีด่านกันอัปโหลดผิด — เอกสารที่มีรายการของเดือนที่ปิดแล้ว, เลือกเดือนไม่ตรงกับเอกสาร, ไฟล์เดิมที่เคยอัปแล้ว จะถูกปฏิเสธพร้อมข้อความบอกเหตุผล · สเตทเมนต์ที่ดาวน์โหลดซ้ำ ระบบ ข้ามบรรทัดที่บันทึกไว้แล้ว ให้เอง — ดูรายละเอียด §9.15

5. วิธีกระทบยอดแต่ละช่องทาง POS

ทั้ง 7 ช่องทาง มีตรรกะการจับคู่ต่างกัน — ตารางสรุปก่อน แล้วลงรายละเอียดทีละช่องทาง

ช่องทางPOS รหัสที่นับเทียบกับวิธีจับคู่
QR พร้อมเพย์KNNQR, K-SHOP, ฯลฯstatement ธนาคารยอด+วัน (T+0)
เงินสดCASHสลิป → statement3-way: POS ↔ สลิป ↔ ฝากธนาคาร (T+1)
เงินโอนโอน*, BIZ TRANSFERstatement ธนาคารยอด+วัน (T+0)
บัตรเครดิตVISA, MC, JCB, ฯลฯสรุปบัตร + statement2 ขั้น: รูด↔สรุปบัตร, สุทธิ↔เงินเข้า
GrabGRABรายงาน Grab + statement2 ขั้น: ยอด↔รายงาน, สุทธิ↔payout
Line ManLINEMANรายงาน LM + statement2 ขั้น: ยอด↔รายงาน, สุทธิ↔payout
คูปองKTCPOINT, BAYPOINT, อื่นๆสรุปคะแนน issuerแต้ม↔ยอด settlement

5.1 QR พร้อมเพย์

เอกสาร
สเตทเมนต์ธนาคารที่ผูก QR (เช่น KBANK, KTB, SCB)
วิธีจับคู่
ระบบจับคู่รายวัน — POS รหัส KNNQR/K-SHOP ของวันนั้น = ยอด credit จาก QR ในวันเดียวกัน
ตรวจอะไร
เซลล์วันที่ขึ้นสีแดง (≠) → กดเข้าไปดูบิล POS vs บรรทัด statement
ที่ผิดบ่อย
QR ยอดเล็กสแกนไม่สำเร็จ ลูกค้าจ่ายซ้ำ • Statement ติดเป็นเงินคืน • QR ของอีกบัญชีถูกบันทึกในรหัสเดียวกัน (ต้องไปแยกที่ตั้งค่า)
รับทราบได้
ผลต่างเล็ก ≤ ฿100 หลังตรวจรายวันแล้ว

5.2 เงินสด — 3 ทาง

เอกสาร
สลิปนำฝากเงินสด (ถ่ายรูป + พิมพ์ยอด) + สเตทเมนต์ธนาคาร
วิธีจับคู่
ขั้น 1: POS เงินสดวันที่ X ↔ สลิปนำฝากที่พิมพ์ยอด (ต่างได้ไม่เกิน ±฿10)
ขั้น 2: สลิป ↔ เงินเข้าธนาคารวัน X+1 (ก่อน 13:00 = วันถัดไป, หลัง 13:00 = อีกวัน หรือฝากรวม)
ตรวจอะไร
กางแถว CASH → ตาราง 3 ทาง โชว์ POS / สลิป / ฝากธนาคาร / สถานะแต่ละขา
วิธีบันทึกสลิป
พิมพ์ยอดในช่อง "สลิปนำฝาก" — บันทึกอัตโนมัติ · กด แนบรูปสลิปได้
ที่ผิดบ่อย
ฝากรวมหลายวันในใบเดียว (ระบบรองรับ) • พิมพ์ยอดผิด • ลืมฝากวันศุกร์ เงินไปเข้าวันจันทร์
รับทราบได้
สลิป-POS ต่าง ≤ ฿10 (ทอนปัดเศษ) — ระบบไม่บล็อกการปิดเดือนถ้ายังไม่ใส่สลิป แต่เงินเข้าธนาคารต้องตรง

5.3 เงินโอน

เอกสาร
สเตทเมนต์ธนาคารทุกใบที่รับเงินโอน (รหัส ANY = อาจเข้าได้หลายแบงก์ ต้องอัปทุกใบ)
วิธีจับคู่
POS รหัสโอน + ANY ↔ บรรทัด credit ที่ไม่ใช่ QR/CC/payout — ยอด+วันตรง
ตรวจอะไร
กางแถว TRANSFER → ดู chip ธนาคารที่ใช้ตรวจ (อาจมีหลายใบ) + กริดรายวัน
ที่ผิดบ่อย
ลูกค้าโอนวันเสาร์-อาทิตย์ เข้าจริงวันจันทร์ (กดเซลล์วันจันทร์ดูได้) • โอนข้ามแบงก์ ค่าธรรมเนียมหักจากยอด
เครื่องมือ
เปิดตัวจับคู่ (3.4) — สำหรับโอนที่ระบบเดาวันไม่ออก ติ๊กวัน POS ↔ บรรทัดเงินเข้าแล้วจับคู่

5.4 บัตรเครดิต — 2 ขั้น

เอกสาร
สรุปยอดบัตรจากค่ายบัตร (KTC, BAY, KBANK, SCB) + สเตทเมนต์ธนาคาร
วิธีจับคู่
ขั้น 1 — ยอดรูด ↔ สรุปบัตร (gross):
  ยอดรูดในเครื่อง EDC (POS) = ยอดที่ค่ายบัตรสรุป (ก่อนหักค่าธรรมเนียม + VAT)
ขั้น 2 — ยอดสุทธิ ↔ เงินเข้า:
  ยอดสรุป − ค่าธรรมเนียม − VAT 7% = ยอดที่ค่ายบัตรโอนเข้าบัญชี
  เคส KTC พิเศษ: ค่ายบัตรหักยอด settlement บัตร KTC กับ KTB statement สุทธิ
ตรวจอะไร
กางแถว CREDIT → เห็น 3-way chain แยกตามค่ายบัตร แต่ละค่ายมี 2 ขั้นและสถานะของแต่ละขา
ข้ามเดือน
เงินเข้าวันที่ 1–7 ที่เดือนก่อนจับคู่ไปแล้ว (เงินสดฝาก T+1 ของวันสิ้นเดือน, payout สิ้นเดือนของ Grab/LINE MAN/บัตร) และบรรทัดที่เงินสดเดือนนี้จับไปแล้ว จะไม่ถูกนำมาจับเป็น settlement บัตรของเดือนนี้อีก แม้ยอดจะเท่ากันพอดี — ขั้น 2 จะขึ้น "รอเงินเข้า" จนกว่าเงินของบัตรจะเข้าจริง (TC-35, 2026-09-05)
ตั้งค่าครั้งแรก
ใส่อัตราค่าธรรมเนียม % ของแต่ละค่ายบัตร (ปุ่ม ค่าธรรมเนียม & VAT)
ที่ผิดบ่อย
VAT 7% ที่ค่ายบัตรหักไม่เท่ากันทุกค่าย • บัตรต่างประเทศมี cross-border fee • payout ข้ามเดือน (สิ้นเดือน ↔ ต้นเดือนถัดไป)

5.5 Grab — 2 ขั้น

เอกสาร
รายงาน Grab (Excel) + สเตทเมนต์ KBANK
วิธีจับคู่
ขั้น 1: POS รหัส GRAB ↔ ยอด gross ในรายงาน Grab (รายวัน)
ขั้น 2: ยอดสุทธิรายวัน (หลังหักค่าธรรมเนียม + VAT) ↔ เงินเข้าบัญชี KBANK
  Grab โอนวันถัดไป — บางครั้ง รวมหลายวันใน 1 โอน ระบบจับให้
ตรวจอะไร
กางแถว GRAB → ตาราง payout trace: วันขาย / ยอดสุทธิ / เงินเข้า / วันที่เงินเข้า / สถานะ
ที่ผิดบ่อย
payout สิ้นเดือนตกเดือนถัดไป (ยังไม่ตรง = "รอเงินเข้า") • Grab refund บิลเก่า ขึ้นเป็นยอดลบ

5.6 Line Man — 2 ขั้น (จ่ายตามยอดสะสม ฿500)

เอกสาร
รายงาน LINE MAN + สเตทเมนต์ KBANK
วิธีจับคู่
ขั้น ① ยอดขาย POS ↔ รายงาน LM (รายบิล เดือนเดียวกัน) · ขั้น ② ยอดสุทธิ ↔ เงินโอนเข้าบัญชี — LINE MAN โอนตามยอดสะสม ฿500 ไม่ใช่ T+1 รายวันแบบ Grab: ยอดสุทธิจะสะสมจนเกิน ฿500 แล้วจึงโอน (วันเล็ก ๆ ต่ำกว่า ฿50 ก็ถูกนับสะสมด้วย) · ถ้าทั้งเดือนยอดยังไม่ถึง ฿500 LINE MAN จะโอนยอดทั้งเดือนเข้าบัญชี ในวันที่ 1 ของเดือนถัดไป — ระบบจะจับคู่เงินก้อนนั้นกลับมาให้เดือนที่เป็นเจ้าของยอดโดยอัตโนมัติ (ไม่นับซ้ำในเดือนถัดไป)
ตรวจอะไร
payout trace ในการ์ด LINEMAN — สถานะ ✓ ตรง / รอเงินเข้า (= ยอดยังสะสมไม่ถึง ฿500 หรือยังไม่อัปสเตทเมนต์เดือนถัดไป ยังไม่ใช่ปัญหา)
ที่ผิดบ่อย
เดือนยอดน้อย (< ฿500) เงินตกไปโอนวันที่ 1 เดือนถัดไป — ต้องอัปสเตทเมนต์เดือนถัดไปด้วย ระบบจึงจะจับคู่ครบ • อย่าตีว่าเงินก้อนวันที่ 1 เป็นรายได้ของเดือนใหม่ (เป็นของเดือนก่อน)

5.7 คูปอง (KTC / BAY / อื่น ๆ)

เอกสาร
สรุปคะแนน KTC, สรุปคะแนน BAY (เฉพาะที่สาขามียอดแลก)
วิธีจับคู่
POS รหัส KTCPOINT/BAYPOINT (ยอดแต้มที่แลก) ↔ ยอด settlement จาก issuer
เคสพิเศษ KTC
เงิน settlement ไม่ได้เข้าตรง — ค่ายบัตรหักออกจากยอดเงินเข้า KTB ของบัตรเครดิต KTC แทน (โชว์ "in KTC deposit")
ตรวจอะไร
กางแถว COUPON → การ์ดแยกตาม issuer / ปุ่ม รายละเอียดคูปอง เปิดหน้าวิเคราะห์คูปองซีรีส์ในแอป (#coupon)
ที่ผิดบ่อย
แลกแต้มเดือนก่อน settlement มาเดือนนี้ • คูปอง 3rd-party ที่ยังไม่ตั้งค่า issuer

5.8 วิเคราะห์คูปองซีรีส์ (#coupon)

หน้า วิเคราะห์คูปองซีรีส์ (รายงาน → งานประจำ / เครื่องมือ → คูปองซีรีส์ หรือปุ่ม รายละเอียดคูปอง ในแถว COUPON) ดึงข้อมูลจาก pos_coupon_day เดียวกับที่ร่างบัญชีใช้คำนวณส่วนลด — ยอดจึงสอดคล้องกันเสมอ

ข้อมูล
ส่วนลดคูปองแยกตาม ซีรีส์ (coupon_series_id) · master สาขาเท่านั้น · เลือกสาขาหรือดูทุกสาขา
ระดับเวลา
สลับ เดือน / สัปดาห์ / วัน ได้จาก gran toggle · สัปดาห์/วัน ต้องเลือกวันที่จาก date picker
ตัวเลขในตาราง
จำนวนใช้ · มูลค่าส่วนลด · MoM (เทียบช่วงก่อน — ▲แดง=ส่วนลดมากขึ้น ▼เขียว=น้อยลง) · % ของรวม
Drill
คลิกแถวซีรีส์ใด → แสดง แยกรายสาขา + แยกรายวัน ของซีรีส์นั้น · กด ✕ เพื่อปิด drill
ความสอดคล้องบัญชี
ยอดรวมในหน้านี้อ้างอิง pos_coupon_day.discount_amount — ตัวเลขเดียวกับบรรทัด "ส่วนลด/โปรโมชัน" ในร่างบัญชีรายวัน
หมายเหตุ
เปิดได้จาก รายงาน → งานประจำ / เครื่องมือ → คูปองซีรีส์ หรือปุ่ม รายละเอียดคูปอง ในช่องทางคูปองของหน้าสาขา (route #coupon)

5.9 ตรวจเงินเข้าธนาคาร — Payout Matching (#payout)

หน้า เงินเข้าธนาคาร แสดงการจับคู่ ยอดสุทธิรายวัน ↔ เงินโอนเข้าบัญชี แยกตามช่องทาง ทุกประเภท (บัตรเครดิต, Grab, Line Man, BAY Point, KTC Point) — เปิดจาก รายงาน ▾ → เงินเข้าธนาคาร ที่หัวหน้าสาขา

ยอดสรุป
ด้านบนแสดง ยอดสุทธิรวม · เข้าบัญชีแล้ว · รอเงินเข้า (ถ้ามี) — ครอบคลุมทุกช่องทาง
แต่ละช่องทาง
การ์ดแสดงสถานะ ✓ ตรง หรือ รอเงินเข้า พร้อมรายการวันขาย / ยอดสุทธิ / เงินโอน / วันที่โอน / ช้ากี่วัน
KTC Point
แสดงแบบพิเศษ "รวมในยอดบัตร" (bank_in_credit) — KTC จ่ายผ่านยอดรวม CC ไม่มีการโอนแยก
รวมหลายวัน
Grab/Line Man อาจรวมหลายวันในโอนเดียว — ระบบแสดง "รวม N วัน" พร้อมรายวันที่รวม
ที่ผิดบ่อย
"รอเงินเข้า" ปลายเดือน = ปกติ (เงินโอนต้นเดือนถัดไป) · ดูร่วมกับ payout trace รายช่องทางในหน้าสาขา

5.10 จัดการข้อแตกต่าง — Discrepancies Admin (#discrepancies)

หน้า ข้อแตกต่าง คือ admin view สำหรับตรวจสอบและจัดการข้อแตกต่างที่ระบบตรวจพบ — เปิดจากปุ่ม รายงาน ▾ → ข้อแตกต่าง ที่หัวหน้าสาขา (ต้องมี session แล้ว) · ใช้คู่กับ (ไม่แทนที่) ตาราง "ตรวจผลต่างรายวัน" ในหน้าสาขา

กรอง
เลือก สถานะ (รอแก้ไข / ยอมรับ / ปรับแล้ว / ปฏิเสธ / ทั้งหมด) + พิมพ์ ช่องทาง / ธนาคาร แล้วกด "ค้นหา" หรือ Enter
จัดเรียง
คลิก header คอลัมน์ "ต่าง (฿)" → เรียงตามขนาดผลต่าง (มากสุดขึ้นก่อน / กดอีกครั้งกลับ)
Drill รายวัน
คลิกเซลล์ "ต่าง (฿)" → ขยายแถวแสดงผลต่างรายวัน (POS / เงินเข้า / ต่าง / สถานะ) · คลิกอีกครั้งซ่อน
resolve ทีละแถว
แถวสถานะ "รอแก้ไข" มี dropdown → เลือก ยอมรับ / ปรับแล้ว / ปฏิเสธ → บันทึกทันที
มอบหมาย
ช่อง "มอบหมาย…" ใส่ชื่อผู้รับผิดชอบ → บันทึกอัตโนมัติเมื่อออกจากช่อง (ขึ้นข้อความ "มอบหมายให้ … แล้ว")
Bulk resolve
ติ๊กช่อง checkbox หลายแถว → แถบสีล่างจอปรากฏ (บนมือถืออยู่เหนือเมนูล่าง) → กด "ยอมรับทั้งหมด / ปรับแล้ว / ปฏิเสธ" ทีเดียว · ผู้แก้ไขบันทึกจากผู้ใช้ที่ล็อกอินอยู่
สิทธิ์
เมื่อเปิดล็อกอินแล้ว: สิทธิ์ บัญชี หรือ ผู้จัดการ (ดูอย่างเดียวแก้ไม่ได้ — §9.7) · ก่อนเปิดล็อกอิน: ต้องมีรหัส write token (ปุ่ม รหัส) — write ที่ไม่มี token จะได้รับข้อความ "ต้องตั้งรหัสบันทึกก่อน"

7. ส่งตรวจและปิดเดือน

Staff: ส่งตรวจ

  1. เคลียร์กลุ่ม ต้องจัดการ ในรายการงานให้หมด (อัปโหลด, ตั้งค่า, รับทราบ) — ขั้นที่ 4 ส่งตรวจ / ปิดเดือน บอกว่ายังเหลือเรื่องไหน
  2. กด ส่งตรวจ ที่หัวหน้าทำงานของสาขา (มุมขวาบน) หรือในขั้นที่ 4 → สถานะเปลี่ยนเป็น "รอผู้จัดการตรวจ"
  3. หลังส่งตรวจแล้วยังแก้ได้ ถ้าผู้จัดการกด "ส่งกลับแก้" ก่อนปิด (ปิดเดือนไปแล้วต้องใช้ เปิดงวดใหม่)

ผู้จัดการ: ตรวจและลงนามปิดเดือน (แผ่นลงนาม — ปรับ ต.ค. 2569)

  1. Close Board → สาขาที่สถานะ รอผู้จัดการ — หน้าทำงานเปิดที่ขั้นที่ 4 ซึ่งมี สรุปสำหรับผู้จัดการ รวมทุกช่องทาง + เหตุผลที่ staff รับทราบ
  2. ถ้าปุ่ม ปิดเดือน (ผู้จัดการ) เป็นสีจาง ให้อ่านเหตุผลข้างปุ่ม ("ยังเหลือ n รายการ" / "มีข้อแตกต่างค้าง n") แล้วจัดการก่อน — ระบบไม่ให้กรอกรหัสผ่านแล้วค่อยปฏิเสธทีหลัง
  3. กด ปิดเดือน (ผู้จัดการ) → เปิด แผ่นลงนาม (จอคอมกลางจอ · มือถือเต็มจอ) แสดงสิ่งที่กำลังรับรอง: สาขา · เดือน · ผู้จัดทำ · ส่งตรวจเมื่อ (เวลาไทย) และโดยใคร และรายการตรวจทีละข้อ (✓ = ผ่าน · ! = ต้องดู):
    • เอกสารครบ — อัปโหลดแล้ว n/N · ครอบคลุมต่อเนื่องถึงวันที่ X · เอกสารที่ยังขาดวันไหน
    • ช่องทางตรงกันหรือรับทราบแล้ว — n/N ช่องทาง
    • ผลต่างที่รับทราบพร้อมเหตุผล — จำนวน + ยอดรวม ฿ + ทุกรายการพร้อมเหตุผลและผู้รับทราบ (ทั้งช่อง · รายวัน · ยอดโอนจากผู้ให้บริการ)
    • การปรับปรุงด้วยมือ — จับคู่ด้วยมือ · ย้ายช่อง · ปรับยอดช่อง (จากทะเบียนการปรับปรุง)
    • เรื่องค้างก่อนปิดเดือน และ ข้อแตกต่างที่ยังไม่ได้ตัดสิน — ต้องเป็น 0
    พร้อมปุ่ม ดูใบรับรอง ↗ และ ทะเบียนการปรับปรุง ↗
  4. ยืนยันตัวตน: เมื่อเปิดล็อกอินแล้ว แผ่นแสดง "อนุมัติโดย <ชื่อของคุณ> (จากการเข้าสู่ระบบ)" → พิมพ์ รหัสผ่านของคุณเองอีกครั้ง → กด ลงนามปิดเดือน (หรือ Enter) · รหัสผ่านผิดจะขึ้นข้อความในแผ่นและนับรวมกับการเข้าสู่ระบบผิด (ผิด 5 ครั้งติดกัน บัญชีล็อก 15 นาที) · ผู้จัดทำของเดือนนั้นลงนามเองไม่ได้ (แบ่งแยกหน้าที่ — แผ่นบอกให้ผู้จัดการคนอื่นลงนาม) · ก่อนเปิดล็อกอิน: แผ่นมีช่อง ชื่อผู้จัดการที่อนุมัติ + รหัสผู้จัดการ (ไม่มีหน้าต่างถามแยกแล้ว)
  5. ถ้ายัง → กด ส่งกลับแก้ → กลับเป็น "กำลังทำ" staff แก้แล้วส่งใหม่ (ไม่ต้องใส่รหัสผ่าน)
  6. หลังปิด: ดาวน์โหลด Excel จากเมนู รายงาน ▾ (Summary / Categories / Daily / Discrepancies / Cash 3-way / Coupon points)
⚠ ปิดเดือนแล้วทุกค่าจะถูกล็อก ทั้งเหตุผลและการจับคู่ — กลับมาแก้ได้เฉพาะผู้จัดการกด "เปิดงวดใหม่ (ผู้จัดการ)" เท่านั้น · เดือนที่ปิดแล้ว กด "ปิดเดือน" ซ้ำระบบจะปฏิเสธ (ผู้อนุมัติเดิมไม่ถูกเปลี่ยน)
✓ หน้าสาขาขึ้นว่าพร้อมปิดแล้ว = กดปิดเดือนได้เลย — ตอนปิดเดือนระบบจับคู่ใหม่อีกรอบ แต่ ไม่เปิดข้อแตกต่างที่จัดการ/รับทราบไปแล้วกลับมา (เดิมเคยเด้งกลับมาทำให้ปิดไม่ได้) · ช่องทางที่รับทราบครบทุกวันแล้ว และคูปองที่ไม่มีข้อมูลแต้มให้ตรวจ ถือว่าเรียบร้อย/เป็นข้อมูลประกอบ ไม่ขวางการปิดเดือน
ยอดระดับ รอบโอน ของ Grab / LINE MAN / บัตรเครดิตที่ไม่ตรงรายงาน แสดงบนหน้าสาขาเป็นรายการ "ยอดโอนจากผู้ให้บริการ" (การ์ด "ยอดโอนจากผู้ให้บริการไม่ตรงรายงาน") และนับเป็นเรื่องค้าง — ตรวจหรือกด ✓ รับทราบ + เหตุผล ที่การ์ดนั้นได้เลย ไม่ต้องไปหน้า ข้อแตกต่าง แล้ว (ผู้จัดการเห็นรายการเหล่านี้ในตารางสรุปก่อนปิดเดือนด้วย)

ผู้จัดการ: เปิดงวดที่ปิดแล้วใหม่ (เมื่อปิดแล้วพบว่าผิด)

  1. เข้าหน้าสาขา + เดือนที่ปิดแล้ว — ปุ่ม เปิดงวดใหม่ (ผู้จัดการ) อยู่ที่หัวหน้าทำงาน (มุมขวาบน) และในแถบเขียว "เดือนนี้ปิดแล้ว" ของขั้นที่ 4
  2. กดปุ่ม → แผ่นเดียวกับการลงนาม แสดง ปิดโดย · ปิดเมื่อ · ผู้จัดทำ → พิมพ์ เหตุผล ที่ต้องเปิดใหม่ (อย่างน้อย 10 ตัวอักษร เช่น "พบสเตทเมนต์ KBANK วันที่ 30 อัปไม่ครบ")
  3. ยืนยันตัวตน: เมื่อเปิดล็อกอินแล้ว "เปิดงวดโดย <ชื่อของคุณ>" + รหัสผ่านของคุณเอง (ผิดนับรวมการล็อกบัญชี) · ก่อนเปิดล็อกอิน: ช่อง รหัสผู้จัดการ (จำไว้ในรอบการใช้งานนี้) — รหัสผิดจะเปิดไม่ได้ → กด เปิดงวดใหม่
  4. สถานะกลับเป็น "กำลังทำ" → staff แก้ไข → ส่งตรวจ → ผู้จัดการปิดเดือนอีกครั้ง (ระบบสร้างหลักฐานแช่แข็งชุดใหม่ให้ตรงกับตัวเลขสุดท้าย)
  5. เหตุผล + ผู้เปิด + เวลา ถูกบันทึกใน ประวัติการแก้ไข (Audit Trail) ทุกครั้ง

7.1 การควบคุมภายในของการแก้ไข (เพิ่ม 2026-06-19)

ปรับให้รัดกุมตามหลักการควบคุมภายใน/ผู้สอบบัญชี:

  • เปิดงวดที่ปิดแล้ว (ปุ่ม "เปิดงวดใหม่ (ผู้จัดการ)") ต้องเป็นผู้จัดการที่ใส่รหัสผ่านของตัวเองซ้ำ (ก่อนเปิดล็อกอิน: รหัสผู้จัดการ) + ระบุเหตุผล (อย่างน้อย 10 ตัวอักษร) — บันทึกลง audit log ทุกครั้ง · เมื่ออนุมัติใหม่ ระบบจะ สร้างหลักฐานแช่แข็ง (snapshot) ใหม่ ให้ตรงกับตัวเลขสุดท้ายเสมอ
  • ทุกการแก้ด้วยมือต้องมีเหตุผล — ย้ายช่อง / ปรับ lane / รับทราบผลต่าง (รายวันและทั้งช่อง) บังคับใส่เหตุผล ≥10 ตัวอักษร (การจับคู่ด้วยมือถ้าไม่ใส่ ระบบเติมเหตุผลมาตรฐานให้)
  • ระบุตัวตนผู้ทำจริง — เมื่อเปิดล็อกอินของระบบกระทบยอดแล้ว (§9.7) ใช้ชื่อผู้ใช้ของระบบนี้ · ก่อนหน้านั้น ถ้าล็อกอินระบบหลัก (dashboard) ไว้ ระบบจะบันทึก "ใครทำ" จาก บัญชีผู้ใช้จริง (ไม่ใช่ค่าที่หน้าเว็บส่งมา) ลงทุกการแก้ไข + การอนุมัติ — แบ่งแยกหน้าที่ (ผู้จัดทำ ≠ ผู้อนุมัติ) ตรวจจากตัวตนจริง
  • หลักฐานแช่แข็งผูกกับเอกสารต้นทาง — ตอนปิดงวด snapshot จะเก็บ รายชื่อ + ลายนิ้วมือ (SHA-256) ของเอกสารทุกไฟล์ ที่ใช้คำนวณงวดนั้น (ใบรับรองการกระทบยอดแสดงจำนวนไฟล์ที่ผูกไว้)

8. ตั้งค่าระบบ (สำหรับผู้จัดการ)

เข้าจาก ตั้งค่าระบบ ↗ มุมบนขวา · ปกติทำครั้งเดียวตอนตั้งสาขา + อัปเดตเมื่อเพิ่ม MID/บัญชี/รหัสรับเงิน

① ตารางจับคู่รหัสรับเงิน

แมปรหัสรับเงินใน POS (เช่น KNNQR) ↔ ประเภท (QR/CASH/...) + ธนาคารปลายทาง + นับ/ไม่นับเข้ากระทบยอด

② วิธีกระทบยอดราย lane

กำหนดวิธีจับคู่ของแต่ละคู่ "ประเภท × ธนาคาร" — เช่น (CREDIT × KTC) = 3-way settlement, (CASH × KBANK) = 3-way slip

③ บัญชีธนาคารของสาขา

เลขบัญชีของแต่ละธนาคาร — ใช้เช็คว่า statement ที่อัปโหลดเป็นของสาขานี้จริงไหม

④ MID เครื่องรูดบัตร / คะแนน

หมายเลข MID ของเครื่อง EDC แต่ละค่ายบัตร — ใช้แมปยอดในสรุปบัตรกับสาขาที่ถูกต้อง

พารามิเตอร์ในหน้า setup ถูกล็อกด้วย Manager Token — staff เปิดดูได้แต่แก้ไม่ได้

9. รายงาน — จัดชุดตามผู้รับ + เปิดอ่านในแอป

ก่อน sync ยอดขายครั้งแรก กระดานรายวัน รายงานรายวัน และเครื่องมือวินิจฉัยคอลัมน์ Excel จะแจ้งว่า “ยังไม่มีข้อมูล POS รายวัน” — ไม่ใช่ข้อผิดพลาดของระบบ ข้อมูลจะปรากฏทันทีหลัง sync เสร็จ (UAT TC-25)

แท็บ รายงาน (#reports) จัดรายงานเป็น 4 ชุดตามคนที่รับรายงาน — เลือกเดือนและสาขาครั้งเดียวที่แถบด้านบน (ค่าเริ่ม = เดือนที่หัวหน้า · สาขา "ทุกสาขา" หรือสาขาเดียว — ระบบจำสาขาที่เลือกไว้ในเครื่องนี้) แล้วทุกรายงานในหน้าใช้ขอบเขตนั้น

9.0 เปิดอ่านรายงานในแอป (ตัวดูรายงาน)

กดชื่อรายงาน → เปิด ในแอป (#report/<ชื่อรายงาน> — ส่งลิงก์ให้กันได้) ไม่เปิดแท็บใหม่ · แถบด้านบนของตัวดูรายงาน:

  • ชื่อรายงาน + ชุด/ผู้รับ + เดือน + สาขาที่กำลังดู · ปุ่ม ← รายงาน กลับหน้ารวม
  • เลือกเดือน / สาขา — เปลี่ยนแล้วรายงานโหลดใหม่ทันที (รายงานที่ออกทีละสาขาจะขอให้เลือกสาขาก่อน)
  • พิมพ์ / PDF — พิมพ์เฉพาะตัวรายงาน (เลือก "บันทึกเป็น PDF" ในหน้าต่างพิมพ์ได้) · เปิดในแท็บใหม่ — ฉบับเต็มหน้าแบบเดิม
  • Excel / ZIP — ดาวน์โหลดไฟล์ของรายงานนั้น (มีเฉพาะรายงานที่มีไฟล์) · หน้าจอโต้ตอบ — หน้าจอเดิมในแอปของรายงานนั้น (กรอง/ดูรายละเอียด)
  • บนมือถือ รายงานแสดงในกรอบสูงเต็มจอ เลื่อนดูภายในกรอบ (ตารางกว้างเลื่อนซ้าย-ขวาได้)

ทุกรายงาน อ่านอย่างเดียว — ผู้ใช้ทุกสิทธิ์ (รวม "ดูอย่างเดียว") เปิดได้ทุกฉบับ · เมื่อเปิดล็อกอิน รายงานที่พิมพ์มีบรรทัด "จัดทำ/พิมพ์โดย (บัญชีที่ล็อกอิน)" เป็นชื่อผู้ที่เปิด · ถ้าหมดเวลาเข้าสู่ระบบระหว่างดู ระบบพากลับหน้าเข้าสู่ระบบ แล้วกลับมาที่รายงานเดิม

9.1 รายงานข้อผิดพลาดประจำเดือน (ทุกประเภท)

รวม ข้อผิดพลาดทุกชนิดที่พบในเดือนนั้น ไว้ในใบเดียว — ไม่ใช่แค่การบันทึกผิดช่อง · เลือกสาขาได้จากเมนูดรอปดาวน์มุมขวา (หรือดูทุกสาขา) — ดรอปดาวน์มี ครบทุกสาขา รวมสาขาที่ไม่มีรายการผิดช่อง

  • ตารางข้อผิดพลาดทั้งหมด — แต่ละแถวมี ประเภท + ช่องทาง/รหัส + รายละเอียด + ยอด + สถานะ (ค้าง = ยังต้องจัดการก่อนปิดเดือน · รับทราบแล้ว · แก้ไขแล้ว) + เหตุผล · ช่องทางที่ รับทราบผลต่างทั้งช่องแล้ว ขึ้นเป็น "รับทราบแล้ว" ไม่ใช่ "ค้าง"
  • ประเภทที่รวม: ยอดต่าง (POS≠เงินเข้า) · เงินเข้าเกิน (ไม่มียอด POS) · ขาดเอกสาร · เงินโอนเข้าไม่ครบ/ช้า (Grab/LM/บัตร) · รหัสยังไม่ตั้งธนาคาร · บันทึกผิดช่อง
  • รายละเอียดบันทึกผิดช่อง (ส่วนท้าย) — สรุปรายสาขา + แนวโน้ม + ช่องที่สับสนบ่อย + คำแนะนำโค้ชแคชเชียร์ + ใบเซ็นรับทราบ (พิมพ์/PDF) ยังอยู่ครบเหมือนเดิม
  • พิมพ์/PDF (หนึ่งหน้าต่อสาขา) · Excel — แผ่นแรก "ข้อผิดพลาดทั้งหมด" แล้วตามด้วยแผ่นบันทึกผิดช่อง

รายงานนี้ช่วยให้ผู้จัดการเห็น ทุกเรื่องที่ต้องจัดการในเดือนนั้นในที่เดียว — บันทึกผิดช่องเป็นเพียงประเภทหนึ่ง

9.2 รายงานการจับคู่รายวันทั้งเดือน

ใช้ตรวจให้มั่นใจว่า ทุกวัน × ทุกช่องทางจับคู่กับเอกสารถูกครบ ในใบเดียว

  • เปิดจาก หน้าสาขา → รายงาน ▾ → ตรวจการจับคู่รายวัน (เฉพาะสาขานั้น) หรือ รายงาน → บัญชี → รายงานการจับคู่รายวัน (ทุกสาขา หรือเลือกสาขา)
  • มี KPI ด้านบน (จับคู่ตรง X/Y · ต้องตรวจ · รอเอกสาร · POS รวม · เอกสารรวม · ผลต่างสะสม)
  • ตารางไล่ทุกวัน — แถว ✗ ต่าง / ขาดเอกสาร ขึ้นสีแดง, รอเอกสารตามรอบ สีเหลือง (ปกติ), ตรงแล้วเป็น ✓
  • แบบทุกสาขา = เฉพาะ 5 สาขาหลัก · ท้ายใบมีช่องเซ็น 3 คน
  • สรุปบัญชีรายวัน — ตารางไล่ทุกวัน × ช่องทาง บันทึกเป็น ยอดเต็ม (gross) โดย แยกบรรทัดส่วนลด ออกจากค่าธรรมเนียม/VAT/สุทธิ — staff ใช้ลงบัญชีรายวันได้ · มีคอลัมน์ รหัสบัญชี / ชื่อบัญชี (เว้นว่างไว้ก่อน เติมภายหลังที่ /api/account-map)
  • ท้ายใบมีสรุปการรับเงินทั้งเดือน — รายช่องทาง: รหัส/ชื่อบัญชี · ยอดรับเต็ม · ส่วนลด · ค่าธรรมเนียม · VAT · สุทธิเข้าบัญชี พร้อม ร่างการบันทึกบัญชี (Dr/Cr) (รายได้ลงเต็มยอด ส่วนลดแยกบัญชี) ให้ฝ่ายบัญชีตรวจตรงกับยอดที่เข้าจริง (มีประมาณการภาษีขาย output ให้ด้วย)
  • ตัวกรองรายวัน (filter by date) — มี ช่องเลือกวัน บนหัวรายงาน · เลือกวันเดียวแล้วรายงานจะ ย่อเหลือเฉพาะวันนั้น และแสดง ร่างการบันทึกบัญชี (Dr/Cr) ของวันนั้นโดยตรง — เอาไปลงบัญชีรายวันได้เลย · กด "↺ ทั้งเดือน" เพื่อกลับไปดูทั้งเดือน (URL: /api/monthly-report?...&day=YYYY-MM-DD)
  • "ฉบับตรวจสอบ (ละเอียด)" (หน้าสาขา → เมนู รายงาน ▾) — เพิ่มหลักฐานระดับบรรทัดสำหรับผู้ตรวจสอบ: รหัส POS ทุกตัว · ยอดบัตรเครดิตราย acquirer (ค่าธรรมเนียม/VAT/สุทธิ) · ทุกบรรทัดเงินเข้าบัญชี (วันที่/อ้างอิง) · Grab/LM · การจับคู่ด้วยมือพร้อมเหตุผล — ตรวจสอบได้ทุกบาท

อยากดู "บรรทัดจริง" ของวันเดียว (รายการธนาคารทีละบรรทัด) ใช้ รายงานหลักฐานรายวัน: เปิด /api/daily-report?day=YYYY-MM-DD (เว้น branch_id = ทุกสาขา)

9.3 สรุปบัญชีรายวัน (รายใบ) — แต่ละวัน = 1 ใบ

เหมือนส่วน "สรุปบัญชีรายวัน" ในรายงานการจับคู่ (§9.2) แต่ดึงออกมาเป็น หน้าแยกของตัวเอง และแสดงเป็น การ์ดรายวัน (1 วัน = 1 ใบบันทึกบัญชี) ดูง่ายทีละสาขา

  • เปิดจาก รายงาน → บัญชี → สรุปบัญชีรายวัน (Dr/Cr) (ฉบับพิมพ์ในตัวดูรายงาน) — หน้าจอแบบการ์ด (#daybook) เปิดได้จากปุ่ม หน้าจอโต้ตอบ
  • เลือกทีละสาขา ได้จาก dropdown มุมขวา (เริ่มที่สาขาแรก) · ด้านบนมีแถบสรุปทั้งเดือน (ยอดเต็มรวม · ส่วนลดรวม · ค่าธรรมเนียม · VAT · สุทธิเข้าบัญชี · จำนวนใบ)
  • แต่ละการ์ด = 1 วัน ไล่ทุกช่องทางของวันนั้น (เงินสด/QR/บัตร/Grab/LINE MAN…) บันทึกเป็น ยอดเต็ม (gross) โดย แยกบรรทัดส่วนลด ออกจากค่าธรรมเนียม/VAT แล้วได้ สุทธิ ต่อช่องทาง + รวมวันนี้ ท้ายการ์ด
  • คอลัมน์ รหัสบัญชี มาจากที่ตั้งไว้ใน ตั้งค่าระบบ (หรือ /api/account-map) — เว้นว่างได้
  • แต่ละการ์ดมีปุ่มพับ "ร่างบันทึกบัญชีวันนี้ (Dr/Cr)" — กางออกเพื่อดูคู่เดบิต/เครดิตของวันนั้น (เงินสด/ธนาคารสุทธิ · ส่วนลด · ค่าธรรมเนียม · VAT เป็นเดบิต / รายได้เต็มยอดเป็นเครดิต) เอาไปลงบัญชีรายวันได้เลย
  • พิมพ์/PDF — ออกเป็นแผ่นการ์ดรายวันให้ฝ่ายบัญชี (เลือกสาขาเดียว หรือเว้น = ทุกสาขา หน้าละสาขา) · มีร่างบันทึกบัญชี Dr/Cr ในทุกการ์ด

ตัวเลขทุกตัวมาจากชุดเดียวกับ §9.2 (จอ ↔ กระดาษตรงกันทุกบาท) · เปิดผ่าน /api/daily-accounts (จอ) และ /api/daily-accounts.print (พิมพ์)

คูปอง & ส่วนลด: ช่อง คูปอง นับเฉพาะ แต้ม KTC/BAY ที่ค่ายบัตรจ่ายคืนเป็น เงินรับจริง · ส่วนลดบนบิล (ส่วนลดเด็ก / ผู้สูงอายุ / วันเกิด / พนักงาน ฯลฯ) ที่กดลดราคาบิล — แม้ลูกค้าจ่ายส่วนที่เหลือด้วยเงินสด/QR/บัตร ไม่ได้จ่ายผ่านคูปอง — จะถูกดึงจากข้อมูล POS (pos_coupon_day) มาแสดงเป็นบรรทัด "ส่วนลด / โปรโมชัน" โดย บวกกลับเข้ารายได้เต็ม (gross) แล้วหักออกเป็นบรรทัดส่วนลด (สุทธิเท่าเดิม) — รายได้จึงเป็นยอดเต็มก่อนหักส่วนลด ตรงตามจริง · (ส่วนลดจากแต้ม KTC/BAY ไม่นับซ้ำในบรรทัดนี้ เพราะค่ายบัตรจ่ายคืนเป็นเงินจริงแล้ว)

9.4 พจนานุกรมรหัสในสเตทเมนต์ + แก้รหัสเอง

สเตทเมนต์ธนาคารมี "รหัสย่อ" ที่ระบบใช้แยกประเภทอัตโนมัติ (เช่น SDCH = นำเงินสดไปฝาก, IORSDT = รับโอนระหว่างธนาคาร) — เปิดดูได้ที่ รายงาน → งานประจำ / เครื่องมือ → พจนานุกรมรหัสสเตทเมนต์ (รหัสที่ยังไม่ยืนยันขึ้นสีเหลือง "⚠ รอตรวจ" — พิมพ์ใบให้ทีมตรวจ หรือ ดาวน์โหลด Excel ไปมาร์กได้)

  • ถ้าพบว่ารหัสถูกตีความผิด ผู้จัดการแก้เองได้ที่ ตั้งค่าระบบ → ส่วน ⑤ "รหัสในสเตทเมนต์ → ช่องทาง"
  • เลือกช่องทางที่ถูก (มีตัวเลือก "ไม่นับ/ไม่ใช่รายได้" สำหรับรายการที่ไม่ใช่ยอดขาย) แล้วกดบันทึก — มีผลทันทีทั้งข้อมูลเดิมและไฟล์ที่อัปใหม่
  • ต้องเป็น ผู้จัดการ (ก่อนเปิดล็อกอิน: รหัสผู้จัดการ) · กด "คืนค่าเดิม" เพื่อย้อนได้

9.5 แบนเนอร์เตือน "รูปแบบน่าสงสัย"

ถ้าระบบเจอว่าการ์ดเงินผิดช่องมี รูปแบบซ้ำผิดปกติ (เช่น เกิดเหมือนกันหลายสิบครั้ง คนละธนาคาร วันเดียวกัน) จะขึ้นแบนเนอร์ บนหน้าแรกเตือนว่า "น่าจะเป็นรหัสสเตทเมนต์ตั้งผิด ไม่ใช่คนกดผิด" พร้อมลิงก์ไปตรวจพจนานุกรมรหัส — ช่วยจับปัญหาเชิงระบบก่อนให้สาขาเซ็นรับทราบผิด ๆ

9.6 ใบทดสอบและรับรองการใช้งาน (UAT)

รายงาน → งานประจำ / เครื่องมือ → ใบทดสอบ + รับรองการใช้งาน (UAT) — ใบเช็กลิสต์พิมพ์ได้ ให้ผู้ใช้เดินทดสอบทีละข้อ ทำเครื่องหมายผ่าน/ไม่ผ่าน แล้วลงนามรับรองก่อนใช้งานจริง

9.7 รหัสเข้าใช้ — ล็อกอินของระบบกระทบยอด (แยกจากแดชบอร์ด)

ระบบกระทบยอดมี บัญชีผู้ใช้ของตัวเอง แยกจากแดชบอร์ดต้นทุน (คนละรายชื่อ คนละรหัสผ่าน คนละสิทธิ์) · เปิดหน้า /app/ แล้วจะเจอหน้า เข้าสู่ระบบ — ใส่ชื่อผู้ใช้ + รหัสผ่าน · เข้าครั้งแรก (หรือหลังผู้จัดการตั้งรหัสใหม่ให้) ระบบให้ ตั้งรหัสผ่านของตัวเอง ก่อนใช้งาน (อย่างน้อย 8 ตัวอักษร) · อยู่ในระบบได้ 12 ชั่วโมงต่อการเข้าหนึ่งครั้ง

สิทธิ์ทำอะไรได้ทำไม่ได้
ผู้จัดการทุกอย่าง — งานกระทบยอดทั้งหมด + ปิดเดือน (อนุมัติ) + เปิดงวดใหม่ (ทั้งสองอย่างต้องใส่รหัสผ่านของตัวเองซ้ำในแผ่นลงนาม) + ตั้งค่าขั้นสูง (วิธี/พารามิเตอร์ lane, แก้รหัสสเตทเมนต์) + จัดการผู้ใช้อนุมัติเดือนที่ตัวเองเป็นผู้จัดทำ (แบ่งแยกหน้าที่ SoD — ต้องให้ผู้จัดการอีกคนอนุมัติ)
บัญชีอัปโหลดเอกสาร, จับคู่, ย้ายช่อง, รับทราบ + เหตุผล, ใส่ค่าธรรมเนียม/สลิป, ตั้งรหัสรับเงิน↔ธนาคาร, ส่งตรวจ / ส่งกลับแก้ปิดเดือน, เปิดงวดใหม่, ตั้งค่าขั้นสูง, จัดการผู้ใช้ (ปุ่มเหล่านี้ไม่แสดง)
ดูอย่างเดียวเปิดดูทุกหน้า รายงาน Excel/PDFบันทึกหรือแก้ไขอะไรไม่ได้ (ปุ่มบันทึกทั้งหมดไม่แสดง · ถ้าลองส่งคำสั่ง ระบบตอบ "สิทธิ์ดูอย่างเดียว")
  • ชื่อผู้ใช้ + สิทธิ์ แสดงที่มุมขวาบน — กดเพื่อ เปลี่ยนรหัสผ่าน หรือ ออกจากระบบ
  • ผู้จัดการเพิ่มผู้ใช้: Admin → ตั้งค่าระบบ → ⑥ ผู้ใช้งานระบบ → เพิ่มผู้ใช้ (ชื่อที่แสดง, ชื่อผู้ใช้ภาษาอังกฤษ, สิทธิ์, รหัสผ่านชั่วคราว) → แจ้งรหัสชั่วคราวให้ผู้ใช้ทางช่องทางส่วนตัว — ผู้ใช้ต้องตั้งรหัสของตัวเองเมื่อเข้าครั้งแรก
  • ในตารางเดียวกัน: เปลี่ยนสิทธิ์ (มีผลทันที), ปิดบัญชี / เปิดใช้ (ปิดแล้วออกจากระบบทุกเครื่องทันที ประวัติงานยังอยู่ครบ), ตั้งรหัสใหม่ (ลืมรหัส / บัญชีถูกล็อก) · ระบบไม่ยอมให้ปิดหรือลดสิทธิ์ ผู้จัดการคนสุดท้าย
  • ใส่รหัสผ่านผิด 5 ครั้งติดกัน → บัญชีถูกล็อก 15 นาที (หรือให้ผู้จัดการตั้งรหัสใหม่) · ข้อความผิดพลาดจะไม่บอกว่าผิดที่ชื่อหรือรหัส · การใส่รหัสผ่านผิดตอน ลงนามปิดเดือน / เปิดงวดใหม่ นับรวมใน 5 ครั้งนี้ด้วย และบันทึกในประวัติการแก้ไข (stepup_fail)
  • ทุกการเข้า/ออก, เข้าไม่สำเร็จ, เพิ่ม/แก้ผู้ใช้ และงานทุกอย่าง บันทึก ชื่อผู้ใช้จริง ไว้ในประวัติการแก้ไข (Audit Trail) — ช่อง "ชื่อผู้อนุมัติ" ไม่ต้องพิมพ์อีก ระบบใช้ผู้ที่เข้าสู่ระบบอยู่
  • รหัสบันทึก (write token) ที่เคยกดปุ่ม รหัส ใส่ในเบราว์เซอร์ เลิกใช้กับคน แล้ว — เหลือไว้ให้สคริปต์อัปโหลดหลายไฟล์อัตโนมัติ (bulk upload) เท่านั้น และใช้อนุมัติ/ปิดเดือนไม่ได้ · รหัสผู้จัดการ แบบใช้ร่วมกันก็ไม่ต้องใช้แล้ว (ระบบดูจากสิทธิ์ผู้จัดการแทน)

ก่อนเจ้าของเปิดใช้ล็อกอิน (ตั้งค่า RECON_LOGIN=1 — ขั้นตอนใน recon/LOGIN_ROLLOUT.md) ระบบทำงานแบบเดิม: ปุ่ม รหัส (รหัสบันทึก) + รหัสผู้จัดการตอนปิดเดือน/เปิดงวดใหม่/ตั้งค่าขั้นสูง · ช่วงนั้นผู้จัดการเข้าสู่ระบบได้ที่ ตั้งค่าระบบ → ⑥ เพื่อสร้างบัญชีล่วงหน้า · บนเครื่องท้องถิ่นที่ไม่ได้ตั้งรหัสใด ๆ ระบบเปิดให้สะดวก

9.8 รายงานติดตามเอกสารที่ยังขาด (ตามงานรายเดือน)

ใช้ไล่ตามว่าแต่ละสาขา ยังต้องอัปเอกสารอะไร และ มีเงินรอเอกสารนั้นจับคู่อยู่เท่าไร — เปิดจาก รายงาน → งานประจำ / เครื่องมือ → ติดตามเอกสารที่ยังขาด

  • เลือกเดือน + สาขาได้บนหน้า → ใช้ตามงานได้ทุกเดือน · พิมพ์ PDF แจกสาขาได้ (มีช่อง ☐ ติ๊ก + ช่องเซ็น)
  • บัตรเครดิต แตกย่อยรายผู้รับบัตร (กสิกร / KTC) พร้อมยอดที่ควรได้ + จำนวนรายการ → รู้ทันทีว่าต้องไปขอ settlement ของค่ายไหน ยอดเท่าไร
  • ด้านบนบอก รวมเงินที่รอเอกสารทั้งเครือ · เรียงสาขาที่ค้างมากขึ้นก่อน

ใช้คู่กับรายงานจับคู่ (9.2): จับคู่ชี้ว่า "ขาดเอกสาร" ช่องไหน → รายงานนี้บอก "เอกสารตัวไหน ของค่ายไหน ยอดเท่าไร" ที่ต้องไปตาม

9.9 บันทึกผิดช่อง (ย้ายช่อง) — กระทบสองยอดพร้อมกัน

ถ้ายอดถูก บันทึกผิดช่องทาง (เช่น ลูกค้าสแกน QR แต่พนักงานกดเป็น "เงินสด") เงินไม่ได้หาย แต่ POS ลงผิดช่อง — ใช้เครื่องมือนี้ ย้ายยอดจากช่องผิดไปช่องที่ถูก โปรแกรมจะ ลดช่องผิด + เพิ่มช่องถูกพร้อมกันทันที (กระทบสองยอดในคราวเดียว) โดยไม่ต้องรันจับคู่ใหม่

  • หน้าสาขา → รายการ "บันทึกผิดช่อง (ย้ายช่อง)" (กลุ่ม อื่น ๆ) → + บันทึกผิดช่อง · หรือปุ่ม ⇄ ย้ายยอดไปช่องอื่น ในรายละเอียดช่องทาง (ตั้งช่องต้นทางไว้ให้)
  • เลือก จากช่อง (ที่กดผิด) → ไปช่อง (ที่ถูก) + ใส่ จำนวนเงิน + เหตุผล แล้วบันทึก
  • ย้อนกลับได้ — กด ↩ ยกเลิก ที่รายการย้าย ยอดกลับไปช่องเดิม
  • ทุกการย้ายเข้าไปอยู่ใน รายงานเงินบันทึกผิดช่อง (§9.1) ติดป้าย "ย้ายด้วยมือ" เพื่อให้ผู้จัดการเห็นและใช้โค้ชสาขา

ต่างจากการ์ดแนะนำ "เงินอาจถูกบันทึกผิดช่อง" (ที่ระบบจับคู่ POS กับบรรทัดสเตทเมนต์ให้อัตโนมัติ) — เครื่องมือนี้ให้ ระบุเองด้วยมือ เมื่อรู้แน่ว่าย้ายช่องไหนไปไหน · ผ่าน /api/channel-move · ทำได้เฉพาะเดือนที่ยังไม่ปิด

9.10 Dashboard รายได้ตามช่องทาง รายวัน (ทุกสาขาในวันเดียว)

หน้า Dashboard สำหรับผู้บริหาร — เลือกวันจากปฏิทิน แล้วเห็น รายได้แยกช่องทางของทุกสาขาในวันนั้นพร้อมกัน

  • เปิดจาก รายงาน → งานประจำ / เครื่องมือ → Dashboard รายได้รายวัน (#dashboard)
  • เลือกวันจากปฏิทินมุมขวา — การ์ดทุกสาขาปรับตามวันนั้น · เปิดครั้งแรกแสดง เมื่อวาน (วันที่ปิดยอดแล้ว — วันนี้ยังขายอยู่ ตัวเลขยังไม่ครบ)
  • มีปุ่มสลับ 3 โหมด:
    • เงินเข้าจริง (บัญชี) — ช่องทาง / ยอดเต็ม / ส่วนลด / สุทธิ (เรียงสาขาสุทธิมากสุด) · แยกคูปอง KTC/BAY (แต้ม) = เงินรับจริง ออกจากคูปองส่วนลดอื่นชุดเดียวกับ §9.3
    • ยอด POS — ยอดที่เครื่อง POS บันทึกแยกช่องทาง (ก่อนกระทบเงินเข้าจริง)
    • ประกบ POS ↔ เงินเข้า — แต่ละช่องทางแสดง POS | เงินเข้าจริง | ต่าง (เงินเข้า = ยอดที่เข้าบัญชี/ค่ายบัตรตาม statement·settlement; ต่าง = เงินเข้า − POS) · ช่องที่ยังไม่ได้อัปเอกสาร เงินเข้า = 0 → ต่างติดลบเท่ายอด POS
  • ด้านบนมี แถบยอดรวมทุกสาขา ที่เปลี่ยนตามโหมด

ผ่าน /api/daily-dashboard?day=YYYY-MM-DD (คืนทั้งฝั่งบัญชีและฝั่ง POS↔เงินเข้าในครั้งเดียว สลับโหมดไม่ต้องโหลดใหม่) · แสดงเฉพาะสาขาหลัก (master) · วันที่ไม่มีข้อมูลขึ้นข้อความว่าง

9.11 รายงานเพื่อการควบคุมภายใน / การถูกตรวจสอบ (Audit & Controls)

อยู่ในชุด ผู้จัดการ ของหน้า รายงาน (ประวัติการแก้ไขอยู่ในชุด ผู้สอบบัญชี) — ออกแบบตามสิ่งที่ผู้สอบบัญชีขอดู ทุกตัวเป็น อ่านอย่างเดียว (ไม่แก้ตัวเลข) เปิดในแอปและพิมพ์ PDF ได้ · ขอบเขตเฉพาะสาขาหลัก (master)

  • ใบรับรองการกระทบยอด (#certificate) — รายสาขา/เดือน: ยอด POS รวม ↔ เงินเข้าจริงรวม ↔ ผลต่างคงเหลือ (หลังรับทราบ) แยกตามช่องทาง — ผลต่างคงเหลือรวม = ผลรวมขนาดผลต่าง (ไม่คิดเครื่องหมาย) ของช่องทางที่ยังไม่รับทราบ (ช่องที่ขาดกับช่องที่เกินไม่หักล้างกันจนดูเหมือนเป็นศูนย์) พร้อม ผู้จัดทำ / ผู้สอบทาน / วันที่อนุมัติ และ เลขหลักฐานแช่แข็ง (SHA-256) ของไฟล์งบที่ปิดงวด · ปุ่ม “พิมพ์สาขานี้” / “พิมพ์ทุกสาขา” (แต่ละสาขาขึ้นหน้าใหม่สำหรับเซ็น) · /api/reports/recon-certificate[.print]
  • ทะเบียนการปรับปรุงด้วยมือ (#override) — ทุกการแก้ด้วยมือในเดือน (จับคู่เอง · ย้ายช่อง · รับทราบผลต่าง · ปรับ lane) พร้อม ใคร · เมื่อ · เหตุผล · จำนวนเงิน · รายการที่ ไม่มีเหตุผลกำกับถูกเน้นแดง (จุดที่ผู้สอบจะถาม) · /api/reports/override-register[.print]
  • อายุรายการค้าง (#aging) — รายการกระทบยอดที่ยังไม่ปิด นับอายุจากสิ้นงวด แยกช่วง 0–7 / 8–30 / เกิน 30 วัน · ตรวจงวดที่เลือกย้อนหลัง 2 เดือน (ไม่รวมงวดที่อนุมัติ/ปิดแล้ว) — ของค้างเกิน 30 วันต้องมีคำอธิบาย/แผนปิด · /api/reports/open-items-aging[.print]

รายงานทั้งสามดึงข้อมูลจากตารางที่มีอยู่แล้ว (audit log / การปรับปรุงที่ย้อนกลับได้ / reconcile รายเดือน) — ไม่มีการเปลี่ยนตรรกะบัญชีหรือการกระทบยอด

9.12 ทะเบียนการปิดเดือน + สรุปผลต่างที่รับทราบ

อีกสองรายงานในกลุ่ม การควบคุมภายใน สำหรับการ กำกับติดตาม (monitoring) และการตรวจ นโยบายผลต่าง:

  • ทะเบียนการปิดเดือน (#closereg) — มุมมองข้าม ทุกสาขา × 6 เดือนล่าสุด: แต่ละสาขา-เดือนปิดงวดแล้ว/อนุมัติ/ยังเปิด · ใครอนุมัติ + วันที่ · กระทบยอดแล้วกี่ % · มี หลักฐานแช่แข็ง (snapshot) หรือยัง — ใช้เป็น control dashboard ว่ามีงวดไหนค้างปิด · /api/reports/close-register[.print]
  • สรุปผลต่างที่รับทราบ / Write-off (#accepted) — รวมยอดผลต่างที่ถูก “รับทราบ” แล้วปล่อยผ่าน (ทั้งช่อง + รายวัน) แยกตามเหตุผล และแยกตามสาขา + รายการทั้งหมด · ตั้ง เกณฑ์ต่อรายการ ได้ (ค่าเริ่ม ฿1,000) ระบบ เน้นแดงรายการที่เกินเกณฑ์ ให้ผู้สอบขอหลักฐานเพิ่ม · /api/reports/accepted-variance[.print]
    การรับทราบรายวันคิดมูลค่าตาม ผลต่างจริงปัจจุบัน ของวันนั้น (ถ้าต่างจากยอดตอนรับทราบ แสดงยอดตอนรับทราบไว้ด้วย) และการรับทราบทั้งช่องคิดตามผลต่างคงเหลือจริงของช่องนั้น — ทะเบียนการปรับปรุงด้วยมือ (§9.11) ใช้หลักเดียวกัน

ทั้งคู่อ่านอย่างเดียว ขอบเขตสาขาหลัก · ทะเบียนปิดเดือนใช้ reconcile_overview เดิม · Write-off อ่านจาก recon_lane_adj (accept) + recon_day_ack — ไม่แตะตัวเลขบัญชี

① ปิดเดือน / เปิดงวดใหม่

  • เดือนที่ปิดแล้วแก้ได้ทางเดียวคือปุ่ม "เปิดงวดใหม่ (ผู้จัดการ)" — ต้องใส่ รหัสผู้จัดการ + เหตุผลอย่างน้อย 10 ตัวอักษร (ดู ส่วนที่ 7) · ปุ่ม "ส่งกลับแก้" ใช้เฉพาะตอน รอผู้จัดการตรวจ
  • สถานะ ปิดงวดแล้ว (closed) ตั้งได้หลัง ปิดเดือนแล้ว (approved) เท่านั้น · กดปิดเดือนซ้ำในเดือนที่ปิดแล้ว → ระบบปฏิเสธ (ผู้อนุมัติเดิมไม่ถูกแทนที่)
  • ถ้าผู้จัดการสองคนกดพร้อมกัน คนที่สองจะได้ข้อความ "สถานะงวดถูกเปลี่ยนระหว่างทำรายการ — โหลดหน้าใหม่แล้วลองอีกครั้ง"

② อัปโหลดเอกสาร

กรณีระบบทำอะไร
เอกสารมีรายการของ เดือนที่ปิด/อนุมัติแล้ว (แม้เลือกเดือนอื่นตอนอัป)ปฏิเสธ — "เอกสารนี้มีรายการของเดือน … ซึ่งปิด/อนุมัติแล้ว" · ต้องให้ผู้จัดการเปิดงวดใหม่ก่อน
สเตทเมนต์ธนาคาร / Grab / LINE MAN ที่ ไม่มีรายการในเดือนที่เลือกเลยปฏิเสธ — "รายการในเอกสารนี้เป็นของเดือน … ไม่ใช่เดือนที่เลือก" → เลือกเดือนให้ตรงกับเอกสาร แล้วอัปใหม่ (สรุปยอดบัตรเครดิตได้รับยกเว้น เพราะยอดขายสิ้นเดือนจ่ายวันที่ 1 เดือนถัดไป)
ไฟล์เดิม เคยอัปแล้วสำหรับสาขานี้ (เดือนไหนก็ตาม)ปฏิเสธ — "ไฟล์นี้อัปโหลดไปแล้วสำหรับสาขานี้ (เดือน …)"
สเตทเมนต์ที่ ดาวน์โหลดใหม่ (ไฟล์ต่างกันแต่มีบรรทัดซ้ำกับที่บันทึกไว้ — วันที่/ยอด/ยอดคงเหลือเดียวกัน)ข้ามบรรทัดที่ซ้ำ บันทึกเฉพาะบรรทัดใหม่ และแจ้งจำนวน — ตัวอย่างขึ้น "ซ้ำกับที่มีอยู่ N รายการ (จะข้าม)" · หลังบันทึกขึ้น "ข้ามรายการซ้ำ N" (อัปหลายไฟล์ขึ้น "ข้ามบรรทัดซ้ำ N")
สเตทเมนต์ที่ ซ้ำทั้งฉบับปฏิเสธ — "ทุกรายการในเอกสารนี้ (N รายการ) อัปโหลดไว้แล้วจากไฟล์อื่น — ไม่บันทึกซ้ำ"
ย้ายไฟล์ไปสาขาอื่น (จัดการไฟล์ ▾ → ย้ายสาขา)ใช้ด่านเดียวกับการอัปโหลด — ไฟล์ซ้ำ / บรรทัดซ้ำในสาขาปลายทาง / เอกสารที่ระบุว่าเป็นของสาขาอื่น / เดือนที่ปิดแล้ว (ทั้งสาขาต้นทางและปลายทาง) จะถูกปฏิเสธ
PDF ที่ตั้งรหัสเฉพาะ "สิทธิ์เจ้าของ" (เปิดอ่านได้โดยไม่ต้องใส่รหัส)อ่านได้ตามปกติ ไม่ต้องใส่รหัส
ไฟล์แนบ / หลักฐานที่ ชื่อไฟล์เป็นภาษาไทยดาวน์โหลดได้ตามปกติ (เดิมเคยดาวน์โหลดไม่ได้)

③ จับคู่ด้วยมือ / ย้ายช่อง

  • บรรทัดเอกสารที่ จับคู่ด้วยมือไปแล้ว, ที่ ถูกตัดออก (ไม่ใช่รายได้), หรือที่เป็นของ สาขาอื่น / เดือนอื่น — ติ๊กจับคู่ไม่ได้ ระบบบอกเหตุผลชัดเจน (เช่น "ถูกจับคู่ด้วยมือไปแล้ว — ยกเลิกคู่เดิมก่อน")
  • ยอดฝั่งเอกสารในคู่ที่จับเอง = ยอดจริงของบรรทัดในสเตทเมนต์เสมอ (ไม่ใช้ตัวเลขที่หน้าจอส่งมา)
  • กดซ้ำ / ดับเบิลคลิกไม่บันทึกสองครั้ง — ปุ่ม "จับคู่", "ใช่ เป็นเงินก้อนเดียวกัน", "บันทึกรับทราบ", "ส่งตรวจ" จะเป็นสีจางระหว่างรอ และบันทึกครั้งเดียว
  • ย้ายช่องยอดเดียวกันซ้ำภายใน 10 วินาที → ปฏิเสธ "บันทึกการย้ายช่องนี้ไปแล้วเมื่อสักครู่ (กดซ้ำ?)"

④ รับทราบรายวัน — ยอดเปลี่ยนหลังรับทราบ

  • ตอนกด รับทราบวันนี้ ระบบเก็บ ผลต่างจริงของวันนั้น ณ เวลารับทราบ (ตัวเลขเดียวกับที่หน้าสาขาแสดง)
  • ถ้าภายหลังยอดของวันนั้น เปลี่ยนเกิน ฿50 (เช่น อัปเอกสารเพิ่ม / จับคู่ใหม่) วันนั้นจะ กลับมาเป็นผลต่าง พร้อมป้าย ยอดเปลี่ยนหลังรับทราบ ในเซลล์รายวันและตาราง "ตรวจผลต่างรายวัน" (บอกยอดที่เคยรับทราบไว้) → ตรวจแล้ว รับทราบใหม่

⑤ ปิดเดือนไม่ติดข้อแตกต่างที่จัดการแล้ว

  • ตอนกดปิดเดือน ระบบจับคู่ใหม่ แต่ ไม่เปิดข้อแตกต่างที่ resolve/รับทราบแล้วกลับมา และนับช่องทางที่รับทราบครบทุกวันแล้วว่าเรียบร้อย — หน้าสาขาขึ้นว่าพร้อมปิด = ปิดได้
  • คูปองที่ ไม่มีข้อมูลแต้ม ให้ตรวจ = ข้อมูลประกอบ ไม่ขวางการปิดเดือน
  • ผลต่างระดับ รอบโอน ของ Grab / LINE MAN / บัตรเครดิต (ยอดสุทธิในรายงาน ≠ เงินโอนเข้าธนาคาร) แสดงบนหน้าสาขา เป็นเรื่องค้าง พร้อมปุ่มรับทราบ + เหตุผลในการ์ดเดียวกัน — หน้าสาขาที่ขึ้นว่า "พร้อมปิดเดือน" จึงกดปิดได้จริง (ดู ส่วนที่ 7)

⑥ รายงาน

  • สรุปผลต่างที่รับทราบ / ทะเบียนการปรับปรุงด้วยมือ — คิดมูลค่าการรับทราบรายวันตามผลต่างจริงปัจจุบัน (แสดงยอดตอนรับทราบถ้าต่างกัน) และรวมการรับทราบทั้งช่องตามผลต่างคงเหลือของช่องนั้น
  • ใบรับรองการกระทบยอด — ผลต่างคงเหลือ = ผลรวมขนาดผลต่างของช่องทางที่ยังไม่รับทราบ (ช่องขาด + ช่องเกินไม่หักล้างกัน)
  • รายงานข้อผิดพลาดประจำเดือน — ช่องทางที่รับทราบแล้วขึ้น "รับทราบแล้ว" · ดรอปดาวน์สาขามีครบทุกสาขา
  • ประวัติการแก้ไข — เก็บการลบด้วย (เลิกรับทราบ / ยกเลิกจับคู่ / ลบไฟล์) · Excel ทุกไฟล์: ข้อความที่ขึ้นต้นด้วย = + - @ เป็นตัวอักษรธรรมดา ไม่ใช่สูตร

⑦ ล็อกอิน (เฉพาะเมื่อเจ้าของระบบเปิด RECON_ENFORCE_AUTH)

นอกจากการบันทึกแล้ว การเปิดรายงาน · ประวัติการแก้ไข · ดาวน์โหลด Excel/หลักฐานแช่แข็ง/ไฟล์แนบ ต้องล็อกอินระบบหลักก่อน — ถ้าไม่ได้ล็อกอินจะเปิดไม่ได้ (หน้าจอทำงานปกติยังเปิดได้)

9.16 ตัวเลขที่อาจเปลี่ยนเมื่อเปิดดูเดือนเก่า

รอบ ต.ค. 2569 แก้ตัวจับคู่ให้ถูกต้องขึ้น — ถ้าเปิดดูเดือนเก่า แบบสด (หน้าสาขา / รายงาน) ตัวเลขบางช่องอาจ ต่างจากที่เคยเห็น ซึ่งเป็นตัวเลขที่ถูกต้องกว่า · หลักฐานแช่แข็ง (snapshot) และ Excel ที่ปิดเดือนไปแล้วไม่เปลี่ยน

  • เงินฝาก / เงินโอน Grab·LINE MAN / settlement บัตร ที่เข้า ช่วงรอยต่อเดือน ไม่ถูกนับซ้ำทั้งสองเดือนอีกแล้ว
  • settlement บัตรที่เข้าบัญชี วันที่ 1 ของเดือนถัดไป นับให้เดือนที่ขาย (เดือนก่อน)
  • KTC Point นับรวมในเงินเข้าก้อน KTC ที่ธนาคาร (ตรงกับที่ KTC โอนสุทธิมาก้อนเดียว)
  • สรุปบัญชีรายวัน: ช่อง บัตรเครดิต ไม่รวม settlement แต้ม KTC/BAY (แต้มอยู่ในช่องคูปอง)
  • เงินเข้าธนาคาร หนึ่งบรรทัด ถูกนับให้ ผู้ให้บริการเดียว เท่านั้น (เดิมสองค่ายอาจนับก้อนเดียวกัน)
  • ช่อง เงินโอน / QR ไม่นับบรรทัดที่ถูกใช้เป็น settlement บัตร หรือเงินโอนของ Grab/LINE MAN ไปแล้ว

ถ้าเดือนที่ปิดแล้วตัวเลขสดต่างจากหลักฐานแช่แข็งจนต้องแก้ ผู้จัดการใช้ เปิดงวดใหม่ แล้วปิดใหม่ — ระบบจะออกหลักฐานแช่แข็งชุดใหม่

  • ใช้สำหรับ: ตรวจว่าใครปิดเดือน · ติดตามการแก้รหัส payment map · หา root cause เมื่อตัวเลขเปลี่ยนโดยไม่คาดคิด

10.3 Trend Heatmap — ความคืบหน้ารายวัน (#trend)

ปฏิทินสีแสดง % lane match รายวัน ของสาขาที่เลือก — เห็นแนวโน้มการกระทบยอดทั้งเดือนในแผนที่สีเดียว

  • เลือกสาขา จาก dropdown — ระบบดึง session ที่มีอยู่ของเดือนนั้นให้อัตโนมัติ
  • ถ้ายังไม่มี session (ยังไม่เริ่มกระทบยอด) จะขึ้นข้อความแนะนำให้เปิดหน้าสาขาก่อน
  • สีเขียว = lane match ≥99% · สีเหลือง = 60–98% · สีแดง = <60% · เทา = ไม่มีข้อมูล
  • ตารางสรุปรายสัปดาห์ (W1–W4) แสดง POS รวม · เงินเข้า · % lane match · % coverage

10.4 Bank Coverage — สถานะครอบคลุมสเตทเมนต์ (#bankcov)

ตรวจทุกบรรทัดในสเตทเมนต์ธนาคาร ว่า กระทบยอดครบ / ยังรอ / ตัดออก

  • เลือกสาขา จาก dropdown — ใช้ session ของเดือนที่กำลังดูอยู่ · เปลี่ยนเดือนแล้วตารางโหลดใหม่ ไม่ค้างข้อมูลเดือนเก่า
  • แถบสรุปด้านบน: X/Y ตรงแล้ว · % match · ยอดตรง · ยอดยังรอ · ยอดตัดออก
  • ปุ่มกรอง ยังรอ / ✓ ตรงแล้ว / ⊘ ตัดออก / ทั้งหมด คัดแสดงเฉพาะสถานะที่ต้องการ (ค่าเริ่มต้นขึ้น "ยังรอ" เมื่อมีงาน)
  • ส่วน 3 ขั้นบัตรเครดิต (แยกราย acquirer): POS gross ↔ สรุปยอดบัตร (ขั้น 1) ↔ เงินเข้าธนาคาร (ขั้น 2) พร้อมสถานะแต่ละขั้น
  • chip รายช่องทาง (เงินสด/QR/บัตร/Grab/LINE MAN) แสดงสัดส่วน matched/ทั้งหมด

ต้องมีสเตทเมนต์ธนาคารอัปโหลดแล้ว ถึงจะมีข้อมูลแสดง — ถ้าหน้าว่าง ให้อัปสเตทเมนต์ในหน้าสาขาก่อน

11. คำถามที่พบบ่อย (Q&A)

Q1. อัปโหลดเอกสารแล้วยอดยังไม่ตรง — ทำยังไง
เลือกช่องทางในรายการงาน (หรือกดช่องใน Close Board) → ดูสะพานตัวเลขและตารางรายวัน กดเซลล์วันที่แดงในปฏิทิน → ดูบิล POS เทียบบรรทัดเงินเข้าของวันนั้นทีละใบ ถ้าระบบเดาวันผิด กด จับคู่วันนี้ในตัวจับคู่ / เปิดตัวจับคู่ (3.4)
Q2. ผลต่างเล็ก ๆ (เช่น ฿5 ฿10) ตามไม่ทันต้องทำยังไง
กด ✓ รับทราบ + เหตุผล ใส่เหตุผลสั้น ๆ (เช่น "ทอนปัดเศษ") เหตุผลจะติดไปในไฟล์ Excel ให้ผู้จัดการเห็นตอนอนุมัติ ระบบไม่บังคับเคลียร์เป๊ะ แต่บังคับให้ทุกผลต่าง มีคำอธิบาย
Q3. ยอดเข้าตกเดือน — Grab/LM ขายสิ้นเดือน เงินเข้าต้นเดือนถัดไป
ปกติ — payout trace จะขึ้นสถานะ รอเงินเข้า และไม่บล็อกการปิดเดือน เพราะระบบรู้ว่ารอบ payout ยังไม่ถึง · บัตรเครดิตคล้ายกัน — รูดวันที่ 30 settle เดือนถัดไป รับทราบเป็น "ยอดข้ามเดือน" ได้
Q4. อัปโหลดเอกสารผิดสาขา
ระบบจะ บล็อก ด้วยแถบแดง "เอกสารนี้เป็นของสาขา X — ยืนยันไม่ได้" ไม่ต้องห่วงว่าจะปนกัน · ถ้าอัปไปแล้วผิดสาขา/ผิดไฟล์ กด จัดการไฟล์ ▾ ในการ์ดเอกสารของหน้าสาขา → ย้ายสาขา หรือ ลบ แล้วอัปใหม่
Q5. รหัสรับเงินใหม่ใน POS — ระบบไม่รู้จัก
จะขึ้น chip ตั้งค่า ในช่องทางที่เกี่ยวข้อง + todo "ระบุธนาคารของ XXX" · ผู้จัดการเข้า ตั้งค่าระบบ → ① ตารางจับคู่รหัสรับเงิน เพิ่มแมปและบอกว่าเข้าธนาคารไหน
Q6. ฝากเงินสดรวมหลายวันในใบเดียว
ระบบรองรับ — ตาราง 3-way จะโชว์ (ฝากรวมวัน) ในคอลัมน์ "ฝากเมื่อ" · พิมพ์ยอดสลิปของแต่ละวันให้ครบ ระบบจะ sum ให้ตรงกับเงินเข้าใบเดียว
Q7. เงินเข้าบัญชีที่ไม่ใช่ยอดขาย (สวีปบัญชี โอนข้ามสาขา)
ระบบเดาให้ใน โอนภายใน (ตัดออกแล้ว) — เลือกรายการ โอนภายใน (ตัดออกแล้ว) ในหน้าสาขาเพื่อตรวจ · บรรทัดที่ตัดออกทั้งหมดดูได้ที่ Bank Coverage (ตัวกรอง ⊘ ตัดออก) · ถ้าเดาผิดทั้งรหัส (เช่น รหัสในสเตทเมนต์ถูกจัดเป็นโอนภายในทั้งที่เป็นยอดขาย) ผู้จัดการแก้ที่ ตั้งค่าระบบ → ⑤ รหัสในสเตทเมนต์ → ช่องทาง
Q8. ปิดเดือนแล้วพบว่าผิด
ผู้จัดการเข้าหน้าสาขา + เดือนนั้น → กด เปิดงวดใหม่ (ผู้จัดการ) ที่หัวหน้าสาขา (หรือแถบ "เดือนนี้ปิดแล้ว" ในขั้นที่ 4) → ใส่เหตุผล (อย่างน้อย 10 ตัวอักษร) + รหัสผู้จัดการ → สถานะกลับเป็น "กำลังทำ" staff แก้แล้วส่งตรวจอีกรอบ · ปิดอีกครั้งใส่รหัสผู้จัดการ (ดู ส่วนที่ 7)
Q9. ทำไมต้องใส่ค่าธรรมเนียมบัตรเครดิตเอง
อัตรา % ต่างกันตามแต่ละค่ายบัตรและประเภทบัตร (ในประเทศ/ต่างประเทศ) — ตั้งครั้งแรกแล้วใช้ต่อเดือนได้ ระบบจะคำนวณ "ยอดสุทธิที่ควรเข้า" ให้อัตโนมัติ ปุ่ม ค่าธรรมเนียม & VAT ในการ์ด CREDIT
Q10. KTC บัตร + KTC แต้ม ทำไมตรวจไม่เหมือนค่ายอื่น
ตามนโยบาย KTC: ยอด settlement บัตร KTC + แต้ม KTC จะ หัก-โอนสุทธิเข้า KTB statement ใบเดียว (ไม่ได้แยก) ระบบเลยแสดงสถานะ "in KTC deposit" ในการ์ดคูปองและตรวจกับ KTB ฝั่งเครดิตแทน
Q11. รายงาน Excel ที่ได้หลังปิดเดือน — มีอะไรบ้าง
7 sheet: Summary (POS รวม, statement รวม, ผลต่าง, จำนวนผลต่างที่ยังเปิด), Categories (ทุกช่องทาง × ธนาคาร), Payout chain (Grab/LM net ↔ bank), Daily (รายวันแยกช่องทาง), Discrepancies (ทุกผลต่าง + เหตุผล + ผู้รับทราบ), Cash 3-way, Coupon points
Q12. ใส่รหัสบันทึก (Write Token) แต่ยัง 403
รหัสนี้ตั้งจาก env ของเซิร์ฟเวอร์ (Fly) ถ้ารหัสเพิ่งเปลี่ยน ให้กด รหัส ใส่ค่าใหม่ · บนเครื่องท้องถิ่นปกติไม่ต้องใส่ token ทำงานได้เลย
Q13. หาเมนู/เครื่องมือไม่เจอ — อยู่ตรงไหน
ทุกฟีเจอร์อยู่ในแอปเดียว เข้าถึงจากแถบนำทาง 4 โซน: ภาพรวมการปิดเดือน (ปิดเดือน → Close Board), จัดการเอกสาร/อัปโหลด (หน้าสาขา → รายการ เอกสาร → จัดการไฟล์), คูปองซีรีส์ (#coupon), แก้การจับคู่ (ปุ่ม เปิดตัวจับคู่ ในช่องทางของหน้าสาขา), รายงานของสาขา (เมนู รายงาน ▾ ที่หัวหน้าสาขา), เปิดงวดที่ปิดแล้ว (ปุ่ม เปิดงวดใหม่ (ผู้จัดการ) ในหน้าสาขา), รายงานทุกฉบับ (รายงาน → ชุดตามผู้รับ → เปิดในแอป), Daily Board / Trend / Audit / Bank Coverage (รายงาน → ตรวจระบบ หรือ Admin → การ์ดตรวจระบบ), ตั้งค่า (#setup)
