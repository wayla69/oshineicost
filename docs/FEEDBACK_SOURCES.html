§1 Google Business Profile API (ดึงทุกคืน)

1.1 สิทธิ์จัดการลิสติ้ง

  1. เข้า business.google.com ด้วยบัญชี Google ของบริษัท — ต้องเห็นทุกสาขา (ถ้ากระจายอยู่หลายบัญชี ให้โอนหรือเชิญเข้ากลุ่มธุรกิจเดียวกันก่อน)
  2. บัญชีนี้ต้องเป็น Owner/Manager ของลิสติ้ง (ไม่ใช่แค่ Site manager)

1.2 Google Cloud project + ขอสิทธิ์ API

  1. เข้า console.cloud.google.com ด้วยบัญชีเดียวกัน → สร้าง project ใหม่ เช่น oshinei-reviews
  2. ยื่นแบบฟอร์มขอสิทธิ์ Business Profile API (Google ต้องอนุมัติ project ก่อนจึงเรียก API ได้ — ปกติ 1–2 สัปดาห์): เริ่มที่ developers.google.com/my-business/content/prereqs → "Request access" ระบุ Project number, ชื่อบริษัท, อีเมล, เว็บไซต์ และเหตุผล ("monitor and reply to reviews of our own 29 restaurant locations")
  3. เมื่อได้รับอีเมลอนุมัติ: APIs & Services → Library → เปิดใช้ 3 ตัว: My Business Account Management API, My Business Business Information API, Google My Business API
  4. APIs & Services → OAuth consent screen → External → กรอกชื่อแอป/อีเมล → Scopes เพิ่ม https://www.googleapis.com/auth/business.manage → Test users เพิ่มอีเมลบัญชีบริษัท (อยู่โหมด Testing ได้ ไม่ต้องส่งตรวจ)
  5. Credentials → Create credentials → OAuth client ID → Application type Desktop app → จด Client ID และ Client secret

1.3 ตั้งค่าบนเครื่องที่รัน sync (เครื่องเดียวกับ Sync Live Data)

  1. สร้างไฟล์ backend\.feedback_config.json (ไฟล์นี้ถูก gitignore และถูกสำรองพร้อม secrets อื่นโดย Backup DB.bat): 
    {
  "google": {
    "client_id": "xxxxxxxx.apps.googleusercontent.com",
    "client_secret": "GOCSPX-xxxxxxxx"
  }
}
  2. ขอสิทธิ์ครั้งเดียว (เปิดเบราว์เซอร์ให้ล็อกอินและกดอนุญาต แล้วบันทึก refresh token ลงไฟล์): 
    py backend\fetch_feedback.py auth google
    ถ้าเครื่องไม่มีเบราว์เซอร์ ใช้ --manual แล้ววาง code จาก address bar
  3. ดูรายชื่อลิสติ้งและสาขาที่จับคู่ได้: 
    py backend\fetch_feedback.py locations google
    ลิสติ้งที่ชื่อมีชื่อสาขาอยู่แล้ว (เช่น "Oshinei Buffet ขอนแก่น") จับคู่อัตโนมัติ; ที่เหลือเพิ่มในไฟล์: 
    "google": { ..., "location_map": { "Oshinei Buffet Korat": "โคราช1", "โอชิเน นครราชสีมา 2": "โคราช2" } }
  4. ทดลองดึงทั้งหมดโดยยังไม่บันทึก แล้วดึงจริง: 
    py backend\fetch_feedback.py run --source google --since all --dry-run
py backend\fetch_feedback.py run --source google --since all

§2 Google Takeout (ไม่ต้องตั้งค่าอะไร)

  1. เข้า takeout.google.com ด้วยบัญชีที่จัดการลิสติ้ง → Deselect all → เลือกเฉพาะ Google Business Profile → Next → Export once → ดาวน์โหลด zip
  2. ในแท็บ 💬 เสียงลูกค้า เลือกไฟล์ zip ที่ได้ → นำเข้าและวิเคราะห์ (ระบบอ่าน location-*/reviews.json ทุกสาขาในไฟล์ และใช้ชื่อลิสติ้งจับคู่สาขา; ถ้าเป็นบัญชีสาขาเดียว เลือกสาขาในช่องค่าเริ่มต้นได้)
  3. ทำซ้ำเดือนละครั้งได้ — รีวิวเดิมไม่ซ้ำ (ระบบจำ review id) และรีวิวที่แก้ไข/ตอบกลับแล้วจะถูกอัปเดต

§3 Facebook Page

  1. เข้า developers.facebook.com ด้วยบัญชีที่เป็นแอดมินของเพจ → My Apps → Create App → ประเภท Business → ชื่อ เช่น "Oshinei Reviews" (แอปอยู่โหมด Development ใช้กับเพจที่คุณเป็นแอดมินได้เลย ไม่ต้องส่ง App Review)
  2. Tools → Graph API Explorer → เลือกแอปนี้ → Permissions เพิ่ม pages_show_list, pages_read_user_content, pages_read_engagement (และ pages_manage_engagement ถ้าจะให้ระบบตอบคอมเมนต์ §8) → Generate Access Token → เลือกทุกเพจสาขา → คัดลอก token (User token)
  3. ให้ระบบดึงรายชื่อเพจพร้อม Page token และบันทึกลงไฟล์: 
    py backend\fetch_feedback.py pages facebook --user-token "EAAB..." --save
    แล้วเปิด backend\.feedback_config.json เติม "branch" ให้แต่ละเพจ (และ "comments": true ถ้าต้องการคอมเมนต์ใต้โพสต์ด้วย): 
    "facebook": { "pages": [
  { "id": "1234567890", "name": "Oshinei ขอนแก่น", "branch": "ขอนแก่น", "token": "EAAB...", "comments": false }
] }
  4. ทดลองแล้วดึงจริง: 
    py backend\fetch_feedback.py run --source facebook --since all --dry-run
py backend\fetch_feedback.py run --source facebook --since all
Page token ที่ได้จาก User token แบบสั้นจะหมดอายุใน ~1–2 ชั่วโมง ถ้าเห็น OAuthException ในผลการดึง ให้ทำข้อ 2–3 ซ้ำ หรือใช้ token จาก Business Settings → System Users (ไม่หมดอายุ) — ทางที่มั่นคงที่สุดสำหรับงานประจำ

3.1 การแชร์และการ mention บน Facebook — ได้แค่ไหน

สิ่งที่เกิดขึ้นAPI ให้เพจเห็นไหมระบบทำอะไร
คนมาโพสต์บนเพจ (visitor post)ได้ (/feed)ดึงเป็น "คอมเมนต์" · ถ้าเป็นลบเข้าคิวรอสาขาตอบ · ตอบใต้โพสต์ได้จากแท็บ
คนโพสต์ที่อื่นแล้วแท็ก/@mention เพจได้ (/tagged) เฉพาะโพสต์ที่ผู้โพสต์เปิดสาธารณะหรืออนุญาตดึงเป็น "การพูดถึง" (ตอบเองในแอป)
คนแชร์โพสต์ของเพจจำนวนแชร์ได้ครบ (shares.count) · ตัวโพสต์ที่แชร์เห็นเฉพาะที่ตั้งค่าสาธารณะจำนวนแชร์แสดงใน log ของการดึง · การแชร์สาธารณะดึงเป็น "การพูดถึง" พร้อมข้อความที่ผู้แชร์เขียน
คนพูดถึงร้านในโพสต์/คอมเมนต์/กลุ่ม โดยไม่แท็กเพจไม่ได้ — Facebook ไม่มี API ค้นหาเนื้อหาสาธารณะ (CrowdTangle ปิดปี 2024, Content Library เฉพาะนักวิจัย)ใช้ Google Alerts (§12) เท่าที่ Google index หรือบริการ social listening
แชร์โดยคนที่ตั้งค่าเห็นเฉพาะเพื่อนไม่ได้ (ความเป็นส่วนตัว) นับอยู่ในจำนวนแชร์เท่านั้น—

เปิด/ปิดได้ต่อเพจในไฟล์ config: "visitor_posts": true, "tagged": true, "shares": true (ค่าเริ่มต้นเปิดทั้งสาม) · "comments": true สำหรับคอมเมนต์ใต้โพสต์ของเพจ · เพจรวมของเครือที่ไม่ระบุ branch ระบบจับชื่อสาขาจากข้อความให้

3.2 Instagram (บัญชี Business ที่ผูกกับเพจ — ใช้แอปและ token เดิม)

สิ่งที่เกิดขึ้นAPI ให้เห็นไหมระบบทำอะไร
คอมเมนต์ใต้โพสต์ของบัญชีร้านได้ดึงเป็น "คอมเมนต์" · ตอบใต้คอมเมนต์ได้จากแท็บ (ไม่เกิน 2,200 ตัวอักษร)
คนโพสต์แล้วแท็กบัญชีร้านได้ (/tags)ดึงเป็น "การพูดถึง"
คน @mention บัญชีร้านในแคปชันหรือคอมเมนต์ของโพสต์คนอื่นได้ แต่ผ่าน webhook เท่านั้น (Meta ส่ง id มาให้ตอนเกิดเหตุ) — จึงเก็บได้ตั้งแต่วันที่เปิด webhook ไม่มีย้อนหลังแดชบอร์ดรับ webhook เก็บ id ไว้ ตัวดึงคืนนั้นไปอ่านเนื้อหาแล้วบันทึกเป็น "การพูดถึง"
Story ที่ mention บัญชี, DMwebhook/messaging เท่านั้นยังไม่ทำ
  1. ผูกบัญชี Instagram (Business/Creator) กับเพจ Facebook ของร้าน แล้วขอสิทธิ์ใน Graph API Explorer เพิ่ม instagram_basic, instagram_manage_comments → รัน pages facebook --user-token … --save อีกครั้ง ระบบจะเติมส่วน "instagram": {"accounts": [...]} ให้เอง (เติม branch ถ้าเป็นบัญชีของสาขาเดียว)
  2. Webhook สำหรับ @mention (ทำครั้งเดียว):
    1. ใน Meta app → App settings → Basic → จด App secret · ตั้งค่า verify token เป็นข้อความอะไรก็ได้ที่คุณเลือก
    2. ใส่สองค่านี้ใน backend\.env (ถูกสำรองพร้อม secrets อื่น) และตั้งเป็น Fly secret ชื่อเดียวกัน: META_APP_SECRET, META_WEBHOOK_VERIFY_TOKEN (แจ้งได้ ระบบตั้งให้ตามกติกาสำรอง secret)
    3. Meta app → Products → Webhooks → Instagram → Callback URL https://oshinei-dashboard.fly.dev/api/feedback/webhook/meta · Verify token = ค่าที่ตั้งไว้ → Verify and save → Subscribe field mentions (และ comments ถ้าต้องการให้เร็วกว่ารอบคืน)
    4. รัน py backend\fetch_feedback.py subscribe facebook ให้แอปสมัครรับเหตุการณ์ของทุกเพจที่ตั้งค่าไว้
    ถ้าแอปยังอยู่โหมด Development Meta ส่งเหตุการณ์ให้เฉพาะบัญชีที่มีบทบาทในแอป (เจ้าของ/ผู้ทดสอบ) ซึ่งครอบคลุมบัญชีร้านเองอยู่แล้ว

3.3 ข้อความจากกล่องข้อความ (Messenger และ Instagram DM)

ลูกค้าจำนวนมากบ่นทาง inbox ไม่ใช่รีวิวสาธารณะ ระบบรวมข้อความเหล่านี้เข้ามาเป็นประเภทที่ 4 "ข้อความ Inbox" ได้ โดยมีกติกาต่างจากรีวิว:

เรื่องกติกา
สิทธิ์ที่ token ต้องมีเพิ่มpages_messaging (Messenger) และ instagram_manage_messages (IG DM) — เพิ่มตอนสร้าง token ใน §3 ข้อ 2
เปิดใช้ในไฟล์ config ใส่ "inbox": true ที่เพจ (ส่วน facebook.pages) และ/หรือที่บัญชี (ส่วน instagram.accounts) — ค่าเริ่มต้นปิด
สิ่งที่เก็บข้อความของลูกค้าต่อบทสนทนาต่อวัน รวมเป็น 1 รายการ (ข้อความสั้นกว่า 8 ตัวอักษร เช่น สวัสดี/สติกเกอร์ ไม่นับ ปรับด้วย "inbox_min_chars") · ผู้ส่งเก็บเป็นแฮช ไม่เก็บชื่อ · มีลิงก์เปิดบทสนทนาใน Business Suite
ตอบแล้วหรือยังถ้าเพจตอบหลังข้อความล่าสุดของลูกค้าในวันนั้น ระบบบันทึกคำตอบและถือว่าตอบแล้ว · ถ้าลูกค้าเขียนมาอีกหลังคำตอบ วันนั้นกลับเป็น "รอสาขาตอบ" · ข้อความลบที่ยังไม่ตอบเข้าคิว "รอสาขาตอบ" และแจ้งเตือน Telegram เหมือนรีวิว
การตอบระบบไม่ส่งข้อความแทน (เป็นบทสนทนาส่วนตัวและ Messenger มีกติกาหน้าต่าง 24 ชั่วโมง) — กด ✍ ตอบ เพื่อร่างข้อความ แล้วไปวางในกล่องข้อความของ Meta Business Suite ตามลิงก์ ↗
ความเป็นส่วนตัวข้อความ inbox เป็นข้อมูลส่วนบุคคล ดูได้เฉพาะผู้ใช้ที่มีสิทธิ์โมดูลเสียงลูกค้า · ลบรายการที่ลูกค้าขอให้ลบด้วยปุ่ม ✕ · ทบทวนความจำเป็นในการเปิดใช้ทุกไตรมาส (§13)
ย้อนหลังรอบแรกอ่านบทสนทนาที่มีความเคลื่อนไหวล่าสุด ≤ 200 บทสนทนาต่อเพจ (ปรับด้วย max_threads ในโค้ด) รอบถัดไปเฉพาะบทสนทนาที่มีข้อความใหม่ตั้งแต่รอบล่าสุด −2 วัน

§5 ตารางเวลาและการทำงาน

  • Task Scheduler "Oshinei Feedback Sync" รัน Fetch Feedback.bat auto ทุกวัน 09:00 (ก่อน push DB 10:00) — log ที่ backend\logs\fetch_feedback.log
  • รันเองได้ทุกเมื่อ: ดับเบิลคลิก Fetch Feedback.bat หรือ py backend\fetch_feedback.py run
  • --since auto (ค่าเริ่มต้น) = ดึงตั้งแต่การดึงสำเร็จครั้งล่าสุดย้อนไป 2 วัน (จับรีวิวที่ถูกแก้ไขและการตอบกลับที่มาทีหลัง); --since all = ทั้งหมด; --since 2026-08-01 = ตั้งแต่วันที่
  • รีวิวถูกส่งเข้าเว็บที่ Fly โดยตรง (ไม่ผ่านฐานข้อมูลในเครื่อง) และไม่หายเมื่อ push ยอดขายประจำวัน — ตารางรีวิวอยู่ในรายการที่ระบบเก็บไว้ข้ามการสลับฐานข้อมูล
  • ยังไม่ตั้งค่าอะไรเลย = งานจบด้วยข้อความ "no review source configured" ไม่นับเป็นความล้มเหลว
  • ในแท็บ การ์ด "แหล่งข้อมูล & การดึงอัตโนมัติ" แสดงจำนวนรีวิว รีวิวล่าสุด จำนวนรอสาขาตอบ (รีวิวลบ/≤3 ดาวที่ยังไม่มีคำตอบ) และผลการดึงครั้งล่าสุดของแต่ละแหล่ง

§6 ข้อมูลส่วนบุคคลและการวิเคราะห์

  • ระบบเก็บเฉพาะข้อความ คะแนน วันที่ ลิงก์ และแฮชของชื่อผู้รีวิว — ไม่เก็บชื่อหรือรูป (PDPA)
  • การวิเคราะห์ใช้พจนานุกรมไทยในตัว; ตั้ง ANTHROPIC_API_KEY เป็น Fly secret เมื่อไรก็ได้ ระบบจะสลับไปใช้ Claude (แม่นกว่ามากกับประโยคประชด/ผสมภาษา; รีวิวหลักพันข้อความไม่ถึง ฿50) — อย่าลืมสำรอง secret ตามกติกาเดิม

§8 ตอบรีวิวจากระบบ

  1. ในแท็บ กด ✍ ตอบ ที่รายการใน "กล่องงาน" (หรือใน "รายการทั้งหมดในช่วงที่เลือก" ท้ายหน้า) — ระบบร่างคำตอบภาษาไทยให้ตามความรู้สึก หัวข้อ และเมนูที่ถูกพูดถึง (ใช้ Claude ถ้าตั้ง ANTHROPIC_API_KEY ไว้ ไม่งั้นใช้แม่แบบ) แก้ไขได้ก่อนส่ง
  2. กด ส่งในรอบถัดไป → รีวิวขึ้นสถานะ "รอส่ง" และถูกส่งจริงในรอบดึง 09:00 (หรือสั่งส่งทันทีด้วย py backend\fetch_feedback.py replies) — Google: โพสต์เป็นคำตอบของเจ้าของร้านใต้รีวิว · Facebook: โพสต์ใต้คอมเมนต์ (token ต้องมีสิทธิ์ pages_manage_engagement)
  3. ผลการส่งกลับมาแสดงที่รีวิว: ตอบแล้ว ✓ หรือ ส่งไม่สำเร็จ พร้อมเหตุผล (กด "ลองใหม่" ได้) — ถ้าเครื่องที่รันตัวดึงยังไม่ได้ตั้งค่า connector รีวิวจะขึ้น "ส่งไม่สำเร็จ: not configured" ไม่ค้างเงียบ ๆ
  4. Facebook Recommendation (แนะนำ/ไม่แนะนำ) ตอบผ่าน API ไม่ได้ — ระบบเก็บข้อความไว้ให้คัดลอกไปตอบในแอป Facebook (สถานะ "ตอบเองในแอป") — เช่นเดียวกับข้อความ Inbox และการพูดถึง: ตอบในแอปของแพลตฟอร์มแล้วกด ✓ ตอบแล้ว ในกล่องงานเพื่อปิดคิว
  5. รีวิวที่สาขาตอบเองในแอป Google/Facebook จะถูกดึงกลับมาปิดคิวอัตโนมัติในรอบถัดไป

§10 TikTok — คอมเมนต์ใต้วิดีโอของร้าน

  1. บัญชี TikTok ของร้านต้องเป็น Business account (ตั้งค่า → บัญชี → สลับเป็นบัญชีธุรกิจ)
  2. เข้า developers.tiktok.com ด้วยบัญชีนั้น → Manage apps → Create app → เพิ่ม product Login Kit และ Business Account (บางบัญชีชื่อ "Content Posting / Business Account API") → Scopes: user.info.basic, video.list, comment.list, comment.list.manage → Redirect URI ใส่ https://oshinei-dashboard.fly.dev/api/feedback/oauth-callback (ต้องเป็น https ที่ลงทะเบียน — localhost ใช้ไม่ได้) → Submit for review (TikTok ตรวจแอปก่อนเปิดสิทธิ์ ใช้เวลาหลายวันถึงหลายสัปดาห์)
  3. เมื่ออนุมัติ: จด Client key / Client secret ใส่ในไฟล์ config (หนึ่ง developer app ใช้ขอสิทธิ์ได้หลายบัญชี — จำเป็นก็ต่อเมื่อแต่ละสาขามีบัญชี TikTok ของตัวเอง): 
    "tiktok": { "client_key": "aw…", "client_secret": "…" }
  4. ขอสิทธิ์ครั้งเดียวต่อบัญชี: py backend\fetch_feedback.py auth tiktok (บัญชีรวมของเครือ ไม่ใส่ --branch — ระบบจะจับชื่อสาขาจากข้อความคอมเมนต์แทน) หรือ py backend\fetch_feedback.py auth tiktok --branch เชียงใหม่ (บัญชีของสาขาเดียว) → เปิดลิงก์ ล็อกอินบัญชีนั้น กดอนุญาต → เบราว์เซอร์มาที่หน้า callback ของแดชบอร์ด (ต้องล็อกอินแดชบอร์ดอยู่) แสดง code → คัดลอกมาวางในหน้าต่างคำสั่ง — token ถูกเพิ่ม (หรือแทนที่ถ้ามีของสาขานั้นอยู่แล้ว) ลงใน tiktok.accounts และต่ออายุอัตโนมัติทุกรอบ ทำซ้ำขั้นนี้ทีละสาขาถ้ามีหลายบัญชี — ใช้ client_key/secret เดิมซ้ำได้ ไม่ต้องยื่นแอปใหม่
  5. ทดสอบ: py backend\fetch_feedback.py run --source tiktok --since all --dry-run
ระบบดึงได้เฉพาะคอมเมนต์ใต้วิดีโอของบัญชีร้านเอง (ทุกบัญชีที่ตั้งไว้ใน tiktok.accounts) — วิดีโอของคนอื่นที่พูดถึงร้านไม่มี API ทางการให้ (Research API ให้เฉพาะนักวิชาการ) การตอบคอมเมนต์ TikTok จำกัด 150 ตัวอักษร ชื่อ endpoint อิงตาม Business Account API v1.3 — ถ้าแอปที่ได้รับอนุมัติเป็นเวอร์ชันอื่น ค่าคงที่ทั้งหมดอยู่ตอนต้นไฟล์ backend/feedback_sources/tiktok.py

§11 X (Twitter) — โพสต์ที่พูดถึงร้าน

  1. เข้า developer.x.com → สมัคร Basic tier (ประมาณ $200/เดือน — ทีม Free อ่านค้นหาไม่ได้ ระบบจะรายงาน "search needs the Basic tier") → สร้าง Project + App → Keys and tokens → Bearer Token
  2. ใส่ในไฟล์ config (คำค้นปรับได้): 
    "x": { "bearer_token": "AAAA…", "keywords": ["โอชิเน", "oshinei"], "lang": "th" }
  3. ทดสอบ: py backend\fetch_feedback.py run --source x --since all --dry-run — API ค้นย้อนหลังได้ 7 วัน การดึงทุกคืนจึงไม่พลาดโพสต์
คุ้มไหม: ทีมนี้อ่านได้ 10,000 โพสต์/เดือน สำหรับแบรนด์ร้านอาหารไทยปริมาณการพูดถึงบน X มักไม่กี่สิบโพสต์ต่อเดือน — ตัดสินใจจากงบ ถ้าไม่สมัคร ข้ามส่วนนี้ได้โดยไม่กระทบส่วนอื่น

§12 YouTube และการพูดถึงทั่วเว็บ (Google News / Google Alerts)

12.1 YouTube (API key ฟรี)

  1. ใน Google Cloud project เดียวกับ §1 → APIs & Services → Library → เปิด YouTube Data API v3 → Credentials → Create credentials → API key (จำกัดให้ใช้ได้เฉพาะ YouTube Data API)
  2. ใส่ในไฟล์ config: 
    "youtube": { "api_key": "AIza…", "keywords": ["โอชิเน", "oshinei buffet"], "comments": true }
    comments: true = ดึงคอมเมนต์ยอดนิยมใต้วิดีโอที่พูดถึงร้านด้วย (เสียโควตาน้อยมาก: ค้นหา 100 หน่วย/คำ คอมเมนต์ 1 หน่วย/วิดีโอ จากโควตาฟรี 10,000/วัน)

12.2 Google News (ในตัว) และ Google Alerts

  1. ไม่ต้องตั้งค่า: ระบบดึง Google News search ของคำค้น ("web": {"keywords": [...]}, ค่าเริ่มต้น โอชิเน / oshinei) ทุกคืนอยู่แล้วเมื่อมีส่วน "web" ในไฟล์ config (ใส่ "web": {} ก็พอ)
  2. Google Alerts ครอบคลุมบล็อก เว็บบอร์ด และหน้าเว็บที่ Google เก็บ (กว้างกว่าข่าว): เข้า google.com/alerts → สร้าง alert คำว่า "โอชิเน" → Show options → Deliver to: RSS feed → คัดลอก URL ฟีด (ไอคอน RSS) → เพิ่มในไฟล์: 
    "web": { "keywords": ["โอชิเน"], "feeds": [ { "url": "https://www.google.com/alerts/feeds/…", "name": "Google Alerts โอชิเน" } ] }
  3. ฟีด RSS/Atom อื่นใส่เพิ่มในรายการเดียวกันได้ (เช่น ฟีดช่อง YouTube ของร้าน https://www.youtube.com/feeds/videos.xml?channel_id=…)

§13 ช่องทางอื่น

  • Grab / LINE MAN / foodpanda: ไม่มี API สาธารณะ — คัดลอกรีวิวจาก merchant app/portal ลงไฟล์ CSV/XLSX (คอลัมน์ date, branch, source, rating, text) แล้วอัปโหลดในแท็บ สัปดาห์ละครั้งก็เพียงพอ
  • Pantip / Wongnai / TikTok ของคนอื่น / Instagram: ไม่มี API สำหรับค้นหาการพูดถึง — Google Alerts (§12.2) เก็บกระทู้ Pantip และรีวิว Wongnai ที่ Google index ได้ส่วนหนึ่ง; ถ้าต้องการครบถ้วนใช้บริการ social listening ไทย (Wisesight, Mandala) แล้วนำเข้าไฟล์ส่งออกในแท็บ

§14 หน้าจอ 💬 เสียงลูกค้า — อ่านยังไง ทำอะไรได้บ้าง

2. ตั้งค่าbackend\.feedback_config.json เพิ่ม "places": {"api_key": "AIza…", "radius_m": 3000, "keywords": ["บุฟเฟ่ต์ญี่ปุ่น","ชาบู","หมูกระทะ","ปิ้งย่าง"]} · ถ้าลิสติ้งของสาขาชื่อไม่ตรงกับ "โอชิเน <สาขา>" ใส่ "branches": {"ชื่อสาขา": {"query": "ชื่อที่ค้นแล้วเจอ"}} · "only": ["ขอนแก่น"] เพื่อจำกัดสาขาตอนทดสอบ
3. ถ่ายภาพครั้งแรกpy backend\fetch_feedback.py places → บันทึกลง feedback_competitor ของเดือนนี้ (รันซ้ำ = แทนที่ของเดือนเดิม) · หลังจากนั้นรอบดึง 09:00 จะถ่ายภาพเองเมื่อขึ้นเดือนใหม่ (หรือ run --places)
4. อ่านในแท็บแผง "🏁 เทียบคู่แข่งรอบสาขา": ★ เรา และจำนวนรีวิว (ลูกศรเทียบเดือนก่อน), ★ กลางของคู่แข่งที่มีรีวิว ≥ 20, ห่าง (เรา − กลาง), อันดับในละแวก, คู่แข่งที่ดีที่สุด · คลิกสาขาเพื่อดูรายชื่อ · ห่างติดลบ ≥ 0.2 = สาขาแพ้ละแวกตัวเอง ควรตั้งเป้ายกคะแนนคู่กับการเพิ่มรีวิว (QR §15 ชวนรีวิว Google)
