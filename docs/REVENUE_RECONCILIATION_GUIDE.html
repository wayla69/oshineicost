1. ภาพรวมและวัตถุประสงค์

ระบบ Revenue Reconciliation ทำหน้าที่ กระทบยอดรายได้ที่รับเข้าจากภายนอก (ธนาคาร, บัตรเครดิต, Grab, Line Man) กับ ยอดขายใน POS ของแต่ละสาขา Master ทีละเดือน เพื่อให้ทีมบัญชีสามารถ:

  • ยืนยันว่าเงินที่เข้าบัญชีธนาคารตรงกับยอดขายที่บันทึกใน POS
  • ตรวจจับความคลาดเคลื่อน (variance) ที่ต้องติดตาม ก่อนที่จะปิดบัญชีรายเดือน
  • ติดตามสถานะรายวัน (matched / variance / missing / pending) ในหน้า Daily Board
  • บริหารคิว discrepancy — assign / accept / adjust / reject พร้อม audit trail
ขอบเขตของระบบ ระบบนี้รองรับ 5 สาขา Master เท่านั้น ได้แก่ โคราช1, เชียงใหม่, สุรินทร์, อุดรธานี, อุบลราชธานี สาขาอื่นๆ ไม่ปรากฏในระบบ Reconciliation นี้

3. แนวคิดหลักก่อนเริ่ม

3.1 Payment Map คืออะไร?

POS ของแต่ละสาขามีรหัสชำระเงิน (Payment Code) ที่ตั้งชื่อต่างกัน เช่น KNNQR, QR Code on EDC, Credit ฯลฯ ระบบไม่รู้ว่ารหัสเหล่านั้นเป็นประเภทอะไร และเข้าธนาคารไหน

Payment Map คือตารางที่ผู้ใช้กำหนดเองว่า: รหัส X = ประเภท QR + ธนาคาร KTB เป็นต้น โดยระบบจะ Seed รายการเริ่มต้นจากข้อมูล POS แต่ต้อง เติม Bank ให้ครบทุกรหัสที่มียอด ก่อนกระทบยอดถึงจะตรงได้

3.2 Session คืออะไร?

การ Reconcile แต่ละครั้งจะสร้าง Session หนึ่งชุด ซึ่งผูกกับ (สาขา + เดือน) Session เก็บผลการ Match ทั้งหมดไว้ และสามารถรัน Match ซ้ำ (Idempotent) ได้โดยไม่สูญเสียข้อมูลเดิม

3.3 Tolerance (ค่าความคลาดเคลื่อนที่ยอมรับได้)

ระดับค่าสูงสุดแบบ Absoluteค่าสูงสุดแบบ % หมายเหตุ
รายวัน (Daily)฿501.0%ยอดต่อวันต่อ lane เล็กกว่า ให้ tolerance แคบกว่า
รายเดือน (Monthly)฿1000.5%ยอดรวมทั้งเดือน ใช้ % เป็นหลัก

ถ้า |ext − pos| ≤ ฿50 หรือ |ext − pos| / pos ≤ 1% → ถือว่า matched

4. การตั้งค่าระบบ (Setup)

ทำ ครั้งแรกครั้งเดียว ใช้เวลาประมาณ 15–30 นาที ต้องมี Write Token ก่อน

4.1 Payment Code Map (แมปรหัสชำระเงิน)

เปิดแท็บ Setup → Payment Code Map

ขั้นตอน

1
ดูรายการรหัสที่มีสัญลักษณ์ ⚠ amber หรือแสดง "needs a bank" — รหัสเหล่านี้มียอดเงินแต่ยังไม่รู้ว่าเข้าธนาคารไหน
2
เริ่มจากรหัสที่มียอดสูงสุดก่อน (แสดงยอดกำกับแต่ละรหัส):
  • KNNQR (ยอดสูงมาก ~฿80M) — QR PromptPay เข้าธนาคารไหน? ตั้งเป็น QR + KTB หรือ QR + KBANK
  • Bank Transfer — โอนเงินเข้าธนาคารไหน?
  • Credit / CC / QR Code on EDC — บัตรเครดิต acquirer ไหน?
  • QR PromptPay → ตั้งธนาคารที่รับเงินจริงๆ (ไม่ใช่ตั้งเป็น PROMPTPAY)
3
สำหรับแต่ละรหัส เลือก: Category (CASH / QR / TRANSFER / CREDIT / GRAB / LINEMAN / COUPON) และ Bank (KTB / KBANK / KTC)
4
การเปลี่ยนแปลง บันทึกอัตโนมัติ (เห็น ✓ หลังแก้ไข) — ไม่ต้องกด Save
5
รายการ amber ที่ด้านบนต้องลดเหลือ 0 ทั้งหมดก่อนที่ผลการ Reconcile จะสมบูรณ์

5.2 Credit Card Settlement

1
คลิก + Upload → เลือก Credit Card Settlement
2
เลือก Acquirer: KTB / KBANK / KTC (ต้องตรงกับ statement ที่อัพ)
3
เลือกไฟล์ → Preview → ตรวจสอบ → Confirm
4
ตั้ง Fee และ VAT หลัง Confirm: ไปที่ Daily Board → คลิกที่แต่ละ line → แก้ไข Fee % และ VAT %
  • Fee = ค่า MDR ที่ตกลงกับ Acquirer (เช่น 1.5%, 2.0%)
  • VAT = VAT ของค่า fee (ปกติ 7%)
  • ระบบจะคำนวณ Net = Gross − Fee − VAT ให้อัตโนมัติ
Gross vs Net สำหรับบัตรเครดิต POS บันทึกยอด Gross (ยอดขายทั้งหมด) แต่ที่โอนเข้าบัญชีจริงคือยอด Net (หักค่า MDR แล้ว) ระบบจะ Reconcile ยอด Gross กับ POS, และแสดงยอด Net ไว้เปรียบเทียบกับที่เข้าบัญชีธนาคาร

6.2 การรัน Match

การ Run Match คือการให้ระบบเปรียบเทียบ POS กับเอกสารภายนอกทั้งหมด

  • ไปที่แท็บ Monthly → คลิก ▶ Run Match
  • รันได้กี่ครั้งก็ได้ — Idempotent (รันซ้ำ ผลลัพธ์เดิม)
  • ควรรัน Match ใหม่ทุกครั้งที่: อัพโหลดเอกสารใหม่, แก้ไข Payment Map, แก้ไข Fee/VAT
เมื่อไหร่ที่ควร Run Match หลังอัพโหลดเอกสารครบ → Run Match ครั้งแรก → ดูผล → แก้ Payment Map หรือ Fee/VAT → Run Match อีกครั้ง ทำซ้ำจนกว่าจะพอใจกับผล

  4 พ.ค.    │  ✓    │   ✓    │    ✓     │      ?       │      ✓      │  ✓   │   ✓

7.2 ความหมายของแต่ละสถานะ

สัญลักษณ์สถานะความหมายสิ่งที่ต้องทำ
✓ matched Matched POS = Statement (ภายใน tolerance ฿50/1%) ไม่ต้องทำอะไร ✓
≠ variance Variance มีทั้งสองฝั่ง แต่ยอดต่างกันเกิน tolerance ตรวจสอบ — อาจเป็น fee ขาด, รายการซ้ำ, หรือข้อผิดพลาด
✗ missing Missing Statement มีวันนั้น แต่ POS ไม่มี (หรือกลับกัน) ช่องว่างจริง — ต้องติดตามทันที
… pending Pending ยังไม่มี Statement ที่ Cover วันนั้น (เอกสารมาช้า) รอเอกสาร → อัพโหลดเมื่อได้
? unmapped_bank Unmapped Bank รหัสชำระเงินมี Bank = UNKNOWN หรือ PROMPTPAY ไปแก้ใน Setup → Payment Map
+ ext_only Ext Only มีรายการใน Statement แต่ไม่มีใน POS ตรวจสอบ — อาจเป็นรายการ settle ของวันก่อน
· no_source No Source ประเภทนี้ไม่มีเอกสารภายนอก (เช่น COUPON) บันทึกเป็น remark — ไม่ต้องแก้

7.3 Coverage Strip

ด้านบน Daily Board จะมีแถบ Coverage แสดงวันสุดท้ายที่เอกสารแต่ละ source ครอบคลุมถึง:

  • ถ้า Coverage ของ KTB Bank Statement = 31 พ.ค. → statement ครอบคลุมถึง 31 พ.ค.
  • วันหลัง Coverage = pending (เอกสารยังไม่มา)
  • วันก่อน Coverage แต่ไม่มีรายการ = missing (ช่องว่างจริง)

7.4 Date Picker

ใช้ Date Picker บน Daily Board เพื่อ Focus เฉพาะวันที่ต้องการ ดูรายละเอียด lane นั้นวันนั้น

7.5 Fee & VAT Panel (สำหรับ Grab / Line Man / Credit Card)

คลิกที่แต่ละ Lane บน Daily Board → จะแสดงแผง Fee & VAT:

  • ใส่ Fee % = อัตราค่าบริการ (เช่น Grab 30%, KTB Credit 1.5%)
  • ใส่ VAT % = VAT ของค่า fee (ปกติ 7%)
  • ระบบคำนวณ Net = Gross − (Gross × Fee%) − (Fee × VAT%)
  • แก้แล้ว → Run Match ใหม่ เพื่ออัพเดทผล

8. Monthly Board — ผลลัพธ์รายเดือน

Monthly Board รวมผลทั้งเดือนเป็น Cards แต่ละ Lane

8.1 โครงสร้าง Monthly Board

แต่ละ Card แสดง:

  • ชื่อ Lane เช่น QR · KTB
  • POS Amount — ยอดรวมจาก POS ทั้งเดือน
  • External Amount — ยอดรวมจาก Statement ทั้งเดือน
  • Difference — ส่วนต่าง (Ext − POS)
  • Status badge — matched / mismatch / pos_only / ext_only / no_source

8.2 สถานะใน Monthly Board

สถานะความหมาย
matchedยอดรวมทั้งเดือนตรงกัน (ภายใน tolerance ฿100/0.5%)
mismatchมีทั้งสองฝั่ง แต่ยอดรวมเดือนต่างกันเกิน tolerance
pos_onlyมีแต่ POS — ไม่มี Statement (ลืมอัพโหลดหรือ Channel ไม่ตรง)
ext_onlyมีแต่ Statement — ไม่มี POS (รหัสไม่ได้ map ถูกต้อง)
no_sourceCOUPON หรือ lane ที่ไม่มีเอกสารภายนอก

8.3 หลังจาก Run Match ผ่านหมด

  • ทุก Lane เป็น matched → เดือนนี้ Reconcile สำเร็จ ✓
  • มี mismatch → ดู Discrepancies tab เพื่อติดตาม
  • มี pos_only → ตรวจสอบ Payment Map หรืออัพโหลด Statement
  • มี ext_only → ตรวจสอบว่า Statement มี MID / Account ที่ตรงกับสาขานี้หรือไม่

9. การจัดการ Discrepancies

รายการที่ยอดต่างกันเกิน tolerance จะถูกส่งมายังคิว Discrepancies โดยอัตโนมัติเมื่อ Run Match

9.1 การเปิดดู Discrepancies

  • เปิดแท็บ Discrepancies (ใน Session ที่เลือก)
  • หรือจาก Overview → คลิกที่ Issues badge ของสาขา/เดือน

9.2 ข้อมูลใน Discrepancy แต่ละรายการ

Fieldคำอธิบาย
Laneเช่น QR · KTB, CREDIT · KBANK
Periodเดือน/วันที่เกิด discrepancy
POS Amountยอดจาก POS
External Amountยอดจาก Statement
DifferenceExt − POS (ลบแปลว่า POS สูงกว่า)
Statuspending → accepted / adjusted / rejected
Assigned Toชื่อผู้รับผิดชอบ

9.3 การ Assign Discrepancy

1
เลือกรายการ discrepancy
2
คลิก Assign → ใส่ชื่อผู้รับผิดชอบ
3
ระบบบันทึกใน audit trail พร้อม timestamp

9.4 การ Resolve Discrepancy

ผู้รับผิดชอบตรวจสอบแล้วเลือก action:

Actionความหมายใช้เมื่อ
accepted ยอมรับว่าตรงกันแล้ว ตรวจสอบแล้วพบว่าเป็น timing difference หรือภายใน tolerance
adjusted ปรับ/แก้ไขแล้ว พบข้อผิดพลาดและได้แก้ไขแล้ว (เช่น แก้ fee/vat, แก้ mapping)
rejected ปฏิเสธ/ยังไม่ยอมรับ ยังไม่ได้รับการแก้ไข — ต้องส่งต่อหรือรอข้อมูลเพิ่ม

9.5 Bulk Resolve

เลือกหลาย Discrepancy พร้อมกัน → คลิก Bulk Resolve → เลือก action เดียวกันทั้งหมด (ประหยัดเวลาสำหรับ timing differences ที่รู้อยู่แล้ว)

9.6 Audit Trail

ทุก action (assign, resolve, comment) ถูกบันทึกใน recon_audit_log พร้อม:

  • เวลา (timestamp)
  • ผู้กระทำ (actor)
  • action ที่ทำ
  • ค่าก่อน/หลัง

10. Manual Matching

สำหรับกรณีที่ต้องการจับคู่ POS กับ Statement รายการด้วยตนเอง เช่น ยอดที่กระจายอยู่หลายวันแต่ควรนับรวมกัน

10.1 ขั้นตอน Manual Match

เลือก Statement line ที่ต้องการจับคู่ (tick checkbox)

ทำตาม checklist นี้ทีละสาขา ทีละเดือน

ก่อนเริ่มเดือนใหม่ (ทำครั้งแรกครั้งเดียว)

  • ตรวจสอบว่า Payment Map ครบ — รายการ amber = 0
  • เพิ่ม Bank Accounts ของทุกสาขา Master ครบ (KTB + KBANK)
  • เพิ่ม Acquirer MIDs ครบ (KTB / KBANK / KTC)

ต้นเดือน (หรือสิ้นเดือนที่ผ่านมา)

  • รอให้ POS ซิงค์ข้อมูลเดือนที่แล้วครบ (ตรวจสอบว่า Data Coverage ครอบคลุมถึงวันสุดท้ายของเดือน)
  • Download เอกสารทุกประเภทจากแต่ละแหล่ง:
    • Bank Statement KTB ทุกสาขา
    • Bank Statement KBANK ทุกสาขา
    • CC Settlement KTB / KBANK / KTC ทุกสาขา
    • Grab Settlement Report ทุกสาขา
    • Line Man Settlement Report ทุกสาขา

อัพโหลดและกระทบยอด (ทำแต่ละสาขา)

  • เปิดแท็บ Uploads → เลือกสาขา
  • Upload Bank Statement KTB → Preview → Confirm
  • Upload Bank Statement KBANK → Preview → Confirm
  • Upload CC Settlement (KTB / KBANK / KTC แยกไฟล์) → Preview → Confirm
  • ตั้ง Fee % + VAT % สำหรับ CC แต่ละ Acquirer
  • Upload Grab Report → Preview → Confirm → ตั้ง Fee/VAT
  • Upload Line Man Report → Preview → Confirm → ตั้ง Fee/VAT
  • ไปที่ Reconcile → Monthly tab → คลิก ▶ Run Match
  • ดูผล Monthly Board — มี pos_only / ext_only ให้แก้ไขก่อน
  • ดู Daily Board — ตรวจ variance และ missing ทุกวัน
  • Discrepancies ที่เกิน tolerance → Assign และ Resolve
  • Run Match อีกครั้งหลังแก้ไข
  • Sign-off: ทุก Lane เป็น matched หรือมี explained variance

Sign-off Criteria

เกณฑ์การ Sign-off
  • ทุก Lane ที่มีเอกสารแสดงสถานะ matched
  • หรือมี variance/missing พร้อม คำอธิบาย ที่ยอมรับได้ (ระบุใน Discrepancy note)
  • รายการ Coupon / no_source บันทึกไว้ใน remark
  • ไม่มี unmapped_bank เหลืออยู่

15. ข้อจำกัดที่รู้จัก

ข้อจำกัดเหล่านี้เป็น "by design" ไม่ใช่ bugs ทีมออกแบบรับทราบแล้วและอยู่ในแผนพัฒนา
ข้อจำกัดผลกระทบวิธีรับมือ
Timing Lag ของ CC, Grab, Line Man
Settlement ล่าช้า T+1 ถึง T+2 วัน (หรือมากกว่า)		 รายการขายวัน X อาจปรากฏใน Statement วัน X+1 หรือ X+2 ใช้สถานะ missing vs pending เป็นตัวบอก — ถ้า pending คือรอเอกสาร ถ้า missing คือต้องตามจริง
Cash เป็น Global Lane
POS ไม่บันทึกว่าเงินสดฝากธนาคารไหน		 Reconcile Cash ได้แค่ยอดรวม ไม่แยกว่าฝาก KTB กี่บาท, KBANK กี่บาท ตรวจสอบรวม Cash deposit ทั้งหมดว่าตรงกับ POS — ไม่แยก bank
Bank Refunds (Debit) ไม่รองรับ
Engine นับเฉพาะ Credit > 0		 รายการ refund/charge-back ในบัญชีธนาคารจะไม่ถูก Match ปรับ Net ด้วยตนเองในส่วน Fee & VAT หรือบันทึกใน Discrepancy note
Coupon ไม่มีเอกสารภายนอก Lane COUPON จะแสดงสถานะ no_source ตลอด บันทึกเป็น known limitation ใน note — ไม่ถือว่า error
1 Account ต่อ 1 ธนาคาร ต่อ 1 สาขา
ยังไม่รองรับหลาย account ต่อ bank ต่อสาขา		 ถ้าสาขามี 2 บัญชี KBANK จะ map ไม่ได้ ชั่วคราว: ใช้บัญชีหลัก — จะพัฒนาใน version ถัดไป
POS Data Lag 1–2 วัน
ข้อมูล POS ล่าสุดอาจช้า 1–2 วัน		 วันที่ใกล้ปัจจุบันจะแสดง pending ฝั่ง POS รัน Refresh ก่อน Reconcile; หรือรอข้อมูล sync ครบก่อน
ข้อมูล POS ปิดที่ 5 มิ.ย. (ช่วง Pilot) วัน 6 มิ.ย. เป็นต้นไปจะแสดง pending จนกว่า Sync จะทำงาน รัน Refresh Online Data.bat เพื่อดึงข้อมูลล่าสุด

16. คำถามที่พบบ่อย (FAQ)

Q: ต้องทำ Setup ใหม่ทุกเดือนไหม?

A: ไม่ต้อง — Setup ทำครั้งเดียว ข้อมูลอยู่ถาวร เว้นแต่มีบัญชีธนาคารใหม่, EDC ใหม่, หรือรหัสชำระเงินใหม่ใน POS

Q: ถ้าอัพโหลด Statement ผิดเดือน จะแก้ยังไง?

A: ไปที่ Uploads tab → ลบ upload นั้น → อัพโหลดไฟล์ที่ถูกต้อง → Run Match ใหม่

Q: Run Match ซ้ำๆ ได้ไหม ข้อมูลจะหายไหม?

A: ได้ — Run Match เป็น Idempotent ผลลัพธ์เดิมเสมอสำหรับข้อมูลเดิม ไม่ทำให้ข้อมูล Upload หรือ Manual Match หาย

Q: ถ้า Grab จ่ายเงินสัปดาห์ละครั้ง จะ Reconcile รายวันได้ไหม?

A: ยังไม่รองรับ automatic — วันที่ไม่มี payout จะแสดง pending วันที่มี payout จะ Match กับยอด POS ของช่วงนั้นแทน ใช้ Manual Match ช่วยได้

Q: Coupon ที่แสดง no_source ต้องทำอะไร?

A: ไม่ต้องทำอะไร — COUPON ไม่มีเอกสารภายนอก ระบบแสดง no_source เป็น known limitation ให้บันทึกยอดรวมไว้ใน note

Q: ยอด CC ใน POS กับ Statement ต่างกันเล็กน้อยทุกวัน เป็นปกติไหม?

A: อาจเกิดจาก Fee/VAT ที่ยังไม่ได้ตั้ง — ตรวจ Fee & VAT Panel ก่อน ถ้าตั้งแล้วยังต่างกัน อาจเป็น timing ของ settlement

Q: ถ้าสาขาใช้ KTB QR แต่บางวันลูกค้าโอนเข้า KBANK ผิด จะเกิดอะไร?

A: จะแสดงเป็น ext_only ฝั่ง KBANK และ mismatch ฝั่ง KTB — ควรบันทึกเป็น Discrepancy note และแจ้งทีมจัดการเงิน

Q: Token หมดอายุเมื่อไหร่?

A: Token ไม่มีวันหมดอายุ แต่จะหายไปเมื่อปิด browser หรือเคลียร์ session — ต้อง paste ใหม่ทุกครั้ง

Q: ทดสอบกับข้อมูลจริงได้เลยไหม?

A: ได้ — แนะนำให้ทดสอบกับข้อมูลเดือน พ.ค. และ มิ.ย. 2569 ก่อน เมื่อมั่นใจผลแล้วค่อย go-live กับเดือนถัดไป (ดูคู่มือ Pilot Guide ประกอบ)

สรุป: Flow การทำงานทั้งหมด

  ┌─────────────────────────────────────────────────────────────────────┐
  │                   Revenue Reconciliation Flow                       │
  └─────────────────────────────────────────────────────────────────────┘

  [ทำครั้งแรกครั้งเดียว]
       Setup Tab
         ├── Payment Map: แมปรหัส POS → Category + Bank
         ├── Bank Accounts: เพิ่มเลขบัญชี KTB/KBANK ทุกสาขา
         └── Acquirer MIDs: เพิ่ม MID บัตรเครดิต KTB/KBANK/KTC


  [ทุกเดือน — ทีละสาขา]
       Download เอกสาร
         ├── Bank Statement (KTB, KBANK)
         ├── CC Settlement (KTB/KBANK/KTC)
         ├── Grab Report
         └── Line Man Report

          ↓

       Uploads Tab → อัพโหลดทีละไฟล์
         ├── Preview ก่อนทุกครั้ง ✓
         ├── Confirm เมื่อ Preview ถูกต้อง
         └── ตั้ง Fee/VAT (CC, Grab, Line Man)

          ↓

       Reconcile Tab → Monthly → ▶ Run Match

          ↓

       Daily Board → ตรวจสถานะรายวัน
         ├── ✓ matched   → ผ่าน ✓
         ├── ≠ variance  → ตรวจ Fee/VAT หรือหาสาเหตุ
         ├── ✗ missing   → ตามหาเอกสาร หรือบันทึกเหตุผล
         ├── … pending   → รอเอกสาร (อัพโหลดเมื่อได้)
         └── ? unmapped  → แก้ใน Setup → Run Match ใหม่

          ↓

       Discrepancies Tab → Assign + Resolve
         ├── accepted (timing / known diff)
         ├── adjusted  (พบและแก้ไขแล้ว)
         └── rejected  (ยังต้องติดตาม)

          ↓

       Sign-off: ทุก Lane matched หรือ explained variance ✓

          ↓

       Export .xlsx → เก็บไว้เป็นหลักฐาน
