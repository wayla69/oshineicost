Findings are ordered by impact. Severity: CRITICAL (wrong money / exploitable / data loss) → HIGH → MEDIUM → LOW. Every item is verified against the actual code with file:line.

A · Financial-correctness bugs

The most dangerous: the dashboard reports money, and these make the money wrong.

A1 HIGH /api/summary headline revenue includes VAT

backend/main.py:992 — the Overview KPI card returns "revenue": round(total_rev_inc, 2) where total_rev_inc is SUM(total_inc_vat). The correct ex-VAT figure is already computed in revenue_ex_vat. avg_ticket is also inc-VAT. Violates the "VAT is NEVER revenue" rule; headline ~7% too high and inconsistent with the GP tab.

Fix: make revenue = total_rev_ex; base avg_ticket on ex-VAT.

A2 HIGH /api/cost/analysis bypasses the canonical COGS helpers

backend/main.py:5086-5094 — hand-rolls SUM(ssm.qty) * sc.unit_cost instead of _cogs_case(). It (1) ignores all sku_cost_monthly overrides, and (2) loses tier exclusion, so buffet tier SKUs double-count against item-level B0xxx consumption when include_buffet_drink=true — the exact bug the helpers prevent.

Fix: replace with SUM(_cogs_case()) + _costed_rev_case().

A3 MEDIUM-HIGH VAT-inclusive revenue leaking into buffet endpoints

  • main.py:5571 attach_pct = ex-VAT drink ÷ inc-VAT total → understated ~7%.
  • main.py:2200 branch-tier-matrix total_revenue uses rev_inc (ex-VAT computed alongside).
  • main.py:1582,1602,1625,1761,1777 cover-economics & RevPASH use SUM(total_inc_vat) without the /1.07 back-out → RevPASH inflated ~7%.

Fix: consistent ex-VAT basis (/1.07 for sales_transaction, or subtotal_ex_vat).

A4 MEDIUM Buffet food_cost_trend ignores monthly cost overrides

main.py:5499-5501 costs tier SKUs from sku_cost.unit_cost only (no monthly fallback); different model than _cogs_case, so the Buffet tab won't reconcile with the GP tab.

A5 LOW /api/analysis/sph trend ignores the selected period

main.py:7071-7085 — the trend block filters only by branch; _month_range_filter never applied, so the trend is always all-time.

A6 LOW Weekly bucketing year-boundary off-by-one

main.py:2860 uses strftime("%Y-W%W"), which mis-buckets days straddling Jan 1. Use ISO week (isocalendar()).

B · Data-integrity / ingestion bugs

Wrong numbers at the source.

B1 CRITICAL VAT stored as net revenue in sales_month_summary

ingest_easy.py:601,611 — load_es_typeb sets net_sales = sum(total_inc_vat). The per-transaction path stores no ex-VAT total even though total_exc_tax sits at col 29 (never read). A second VAT-inflated revenue number contradicts the ex-VAT sales_sku_monthly.

Fix: read col 29 for net_sales; keep total_inc_vat only on the transaction row.

⚠️ Verification caveat: the column convention was inferred from comments/schema. Confirm against a real 23 ES_*.xlsx before patching the VAT math.

B2 HIGH ingest_easy.main() deletes the DB with no backup

ingest_easy.py:1050-1051 — init_db unconditionally db_path.unlink(), destroying sku_cost, sku_cost_monthly, bom_ingredients, bom_sku_alias, branch_targets and archives with no backup.

Fix: refuse if curated tables non-empty, or back up first.

B3 HIGH Non-deterministic period derivation → re-ingest double-count

ingest_easy.py:217,235,289-294 — a filename hint can be silently overridden by an in-file Thai date; on disagreement a file loads into the wrong month, splitting sku_monthly vs transactions across buckets.

Fix: assert filename-hint == in-file period; delete by the same key you insert by.

B4 HIGH Silent numeric coercion to 0 + hardcoded column indices

ingest_easy.py:123-141,388-394,521-534 — parsers fall back to 0.0 on any failure with no header validation, so a future column shift silently reads the wrong column.

Fix: detect header row, map label→index, assert required columns, log/fail on high coercion rate.

B5 MEDIUM-HIGH BoM fuzzy/code matching auto-applies wrong cost attribution

match_bom_skus.py:131,53-74 — difflib ratio ≥ 0.85 plus A↔B prefix swaps, auto-written by --apply. Near-identical Thai names exceed 0.85 and attach a recipe's cost to the wrong SKU.

Fix: raise threshold (≥0.92), best-vs-second margin, stage for human confirmation.

B6 MEDIUM Backup/maintenance gaps

  • reingest_easy_safe.py:30-34 copies .db+-wal+-shm with no wal_checkpoint → torn snapshot.
  • Neither ingest path runs VACUUM/ANALYZE after bulk mutation.
  • Per-file commits with no overall transaction → silent partial dataset on mid-run failure.

C · Security / robustness (backend)

Internal LAN tool, no auth layer — but the wildcard CORS turns "internal" into "any website can write."

C1 HIGH No auth + permissive CORS on state-mutating endpoints

main.py:105-110 — allow_origins=["*", "null"], allow_methods=["*"], no auth, ~18 mutating endpoints. Any page the user visits can issue cross-origin writes that overwrite financial data.

Fix: explicit origin list, drop */null; add a token gate on mutating routes if off-localhost.

C2 MEDIUM Path traversal in /api/upload

main.py:2554-2568 — named_path = tmp_path.parent / filename uses raw file.filename; ..\..\x writes/deletes outside the temp dir.

Fix: basename only + verify resolved parent is the temp dir.

C3 MEDIUM Unhandled int() casts on month params → 500 DoS

main.py:2034,8696,8795,1567,2860 — cast YYYY-MM strings with no validation; malformed input returns 500.

Fix: validate format → 400.

C4 LOW Misc

  • Raw exception text returned to client (main.py:2592,9352,4697) — info disclosure.
  • invalidate_cache() at main.py:2599 is unreachable (after return) — stale analytics after upload.
  • Client-controlled body.extra concatenated into the Anthropic prompt (main.py:4688).
Verified OK: SQL is parameterized throughout (no injection — :named/? placeholders; f-strings interpolate only hardcoded/whitelisted fragments). No eval/exec/subprocess/pickle. No hardcoded secrets. Per-thread SQLite connections, so check_same_thread=False is safe.

D · Frontend (index.html)

D1 CRITICAL Stored XSS across nearly all tables/selectors

No HTML-escaping helper anywhere; 263 innerHTML sinks interpolate raw API strings. Branch names (:9171, editable + persisted), SKU descriptions (:8627,6315, from CSV), dropdown options (:4655,7920) all unescaped → stored XSS.

const esc = s => String(s ?? '').replace(/[&<>"']/g, c =>
  ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]));

D2 CRITICAL onclick handlers escape inconsistently / not at all

index.html:7254,9034,10325 — escape only ' (or nothing); a "/< in the value breaks out.

Fix: use data-* attributes + addEventListener, or escape for both contexts.

D3 HIGH 141 of 163 fetch calls have no response.ok check / .catch

A backend 500/empty body rejects and the loader aborts mid-render — half-populated tab, no error shown.

async function getJSON(url){ const r=await fetch(API+url);
  if(!r.ok) throw new Error(r.status+' '+url); return r.json(); }

D4 HIGH No stale-response guard on rapid tab/filter switches

index.html:4691,4811 — loaders fire with no sequence token; switching branch A→B lets A's slower response overwrite B's charts.

Fix: capture const myGen = ++loadGen; and bail if myGen !== loadGen before writing DOM.

D5 HIGH .toFixed() on values only null-checked, not number-checked

index.html:4492-4493,4545 — a numeric field returned as a string or NaN makes n.toFixed throw and (with D3) takes down the loader.

D6 MEDIUM Performance at real data volume

index.html:4811 — cache = {} wiped every loadActiveTab, so every visit re-fetches and rebuilds all charts. 1,988-row SKU tables built by string-concat with no pagination. (mkChart does destroy() first — no canvas leak.)

D7 LOW Misc

  • index.html:26-31 silently falls back to CDN on local vendor failure — defeats "offline".
  • badge/trendBadge duplicates; near-identical parallel SKU loaders.
