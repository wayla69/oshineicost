2. ขอบเขตและหน้าที่

ระบบต้องให้แคชเชียร์ค้นสมาชิก สะสมแต้ม ใช้คูปอง แลกแต้ม และยกเลิกรายการได้ที่จุดคิดเงินของทุกสาขาที่ใช้ Easy POS (ประมาณ 35 สาขา) การสมัครสมาชิกทำใน LINE OA ของ Buzzebees เท่านั้น POS ไม่รับสมัคร

ฝ่ายตำแหน่งหน้าที่หน้าที่
Buzzebeesผู้พัฒนาและผู้ดูแลระบบพัฒนา API B0–B9 ตามสเปก HO_CRM, ถอดรหัส QR ใบเสร็จ, จัดหา sandbox และบัญชีทดสอบ, ส่งรายงานกระทบยอดรายวัน, ตั้งค่า LINE OA กติกาแต้ม และคูปอง
Easy POSผู้ให้สเปกและผู้ตั้งค่า POSส่งสเปก HO_CRM และรูปแบบ QR ใบเสร็จให้ Buzzebees, ตั้งค่า URL และคีย์รายสาขาใน POS, เปิด QR ใบเสร็จรายสาขา, ผูกคูปองกับรหัสส่วนลดใน Easy, ร่วมทดสอบ
Oshineiเจ้าของโครงการ ผู้ตัดสินใจ และผู้ตรวจรับกำหนดกติกาแต้มและคูปอง, เลือกสาขานำร่อง, อบรมแคชเชียร์, กระทบยอดรายวัน, ตรวจรับงาน

นอกขอบเขต: การเปลี่ยน POS เป็น B-POS, การสั่งอาหารออนไลน์และเดลิเวอรี, การสมัครสมาชิกที่ POS, และการส่งแคมเปญการตลาด (เป็นงานในระบบ Buzzebees ไม่กระทบ API)

4. ภาพรวม API และแผนผังการเชื่อมต่อ

ผู้พัฒนาฝั่งรับ: Buzzebees · ผู้เรียก: Easy POS (B0–B8), Easy HQ (B7), ระบบรายงาน Oshinei (B9)

ทุกเส้นเป็นการเรียกเข้าหา Buzzebees ไม่มีการเรียกจาก Buzzebees มายัง POS เพราะเครื่อง POS อยู่หลังเครือข่ายร้าน รับการเรียกเข้าไม่ได้

แผนผัง API: ผู้เรียก 4 ฝ่าย กับส่วนของ Buzzebees ที่รับ
เส้นชื่อกลุ่มผู้เรียก → ผู้รับเรียกเมื่อตอบภายใน
B0ตรวจการเชื่อมต่อสนับสนุนEasy POS → Buzzebeesเปิดกะ และทุก 5 นาทีเมื่อครั้งก่อนล้มเหลว2 วินาที
B1ค้นสมาชิกหลักEasy POS → Buzzebeesแคชเชียร์สแกน QR สมาชิก หรือกรอกเบอร์โทร3 วินาที
B2ตรวจคูปองหลักEasy POS → Buzzebeesลูกค้าเลือกคูปอง ก่อนกดชำระ3 วินาที
B3ตัดคูปองหลักEasy POS → Buzzebeesกดชำระเงิน3 วินาที
B4แลกแต้มเป็นส่วนลดหลักEasy POS → Buzzebeesกดชำระเงิน3 วินาที
B5สะสมแต้มหลักEasy POS → Buzzebeesชำระเงินสำเร็จ ก่อนพิมพ์ใบเสร็จ3 วินาที (ส่งซ้ำได้)
B6ยกเลิกรายการหลักEasy POS → Buzzebeesยกเลิกบิลก่อนปิด หรือ void / คืนบิลภายหลัง5 วินาที (ส่งซ้ำได้)
B7ส่งข้อมูลหลักสนับสนุนEasy HQ → Buzzebeesวันละครั้ง 05:00 หรือเมื่อสาขา/เมนูเปลี่ยน30 วินาที
B8สอบถามสถานะรายการสนับสนุนEasy POS → BuzzebeesB3–B5 หมดเวลารอ และ POS ต้องรู้ผลก่อนปิดบิล3 วินาที
B9รายงานกระทบยอดสนับสนุนระบบรายงาน Oshinei → Buzzebeesทุกวัน 06:0030 วินาที

เส้นหลัก (B1–B6) กระทบการคิดเงินโดยตรง จึงกำหนดเวลาตอบสั้น เส้นสนับสนุน (B0, B7, B8, B9) ใช้ดูแลระบบ กู้คืนเมื่อเกิดปัญหา และตรวจสอบยอด

5. ลำดับการเรียกต่อ 1 บิล

ผู้พัฒนาฝั่ง POS (ลำดับการเรียกและการจัดการเมื่อไม่สำเร็จ): Easy · ผู้พัฒนาฝั่งรับ: Buzzebees

บิลหนึ่งใบเรียก API สูงสุด 5 ครั้ง (B1–B5) ทุกครั้งเริ่มจาก Easy POS การตัดคูปองและแต้ม (B3, B4) ต้องสำเร็จก่อนปิดบิล ส่วนสะสมแต้ม (B5) เรียกหลังชำระเงินสำเร็จและก่อนพิมพ์ใบเสร็จ เพื่อให้ใบเสร็จแสดงแต้มที่ได้และแต้มคงเหลือ

ลำดับการเรียก API ต่อ 1 บิล: 5 ขั้นตอน และ 2 กรณียกเว้น
  1. แคชเชียร์สแกน QR สมาชิกจาก LINE หรือกรอกเบอร์โทร → B1 ค้นสมาชิก POS แสดงชื่อ แต้มคงเหลือ และคูปองที่ใช้ได้
  2. ลูกค้าเลือกคูปอง → B2 ตรวจคูปอง (ยังไม่ตัด) POS ใส่ส่วนลดตามคำตอบ
  3. ลูกค้าขอแลกแต้ม → POS คำนวณส่วนลดจาก point_balance × point_value_thb ที่ได้จาก B1 ยังไม่เรียก API
  4. กดชำระเงิน → B3 ตัดคูปอง และ B4 ตัดแต้ม ทีละรายการ ถ้ารายการใดไม่สำเร็จ POS ยกเลิกรายการที่สำเร็จไปแล้วด้วย B6 แล้วแจ้งแคชเชียร์
  5. ชำระเงินสำเร็จ → B5 สะสมแต้ม → พิมพ์ใบเสร็จพร้อมแต้มที่ได้ แต้มคงเหลือ และ QR ใบเสร็จ ถ้า B5 ไม่ตอบในเวลา ใบเสร็จพิมพ์ "แต้มจะเข้าภายใน 24 ชั่วโมง" และ POS เข้าคิวส่งซ้ำ
  6. ยกเลิกบิลก่อนปิด หลัง B3/B4 สำเร็จแล้ว → B6 ด้วย transaction_refs ทันทีเพื่อคืนคูปองและแต้ม
  7. void หรือคืนบิลภายหลัง → B6 คืนคูปอง คืนแต้มที่แลก และหักแต้มที่ได้ การคืนบางรายการ = B6 ยกเลิกทั้งบิล แล้ว B5 ใหม่ด้วยยอดหลังคืน

กรณีหมดเวลารอ B3, B4 หรือ B5: POS เรียก B8 สอบถามสถานะ ด้วย request_id เดิม ได้ completed → ใช้ผลนั้น; ได้ not_found → ถือว่าไม่ได้ตัด ไม่ให้ส่วนลด; B8 ไม่ตอบเช่นกัน → ไม่ให้ส่วนลด ปิดบิลราคาเต็ม รายการที่อาจตัดไปแล้วจะปรากฏในรายงานกระทบยอด และ Buzzebees คืนให้ลูกค้า

401คีย์ไม่ถูกต้อง หรือไม่ตรงสาขาแสดง "เชื่อมต่อระบบสมาชิกไม่ได้"
409request_id เดิมแต่เนื้อหาต่างจากครั้งก่อนสร้าง request_id ใหม่แล้วส่งอีกครั้ง
429เรียกถี่เกินรอตาม Retry-After แล้วส่งซ้ำ
5xx หรือหมดเวลาระบบ Buzzebees ขัดข้องถือว่าไม่สำเร็จ ทำตามกติกาเมื่อ Buzzebees ไม่ตอบ (หัวข้อ 9)

7. รายละเอียดแต่ละเส้น B0–B9

ผู้พัฒนาฝั่งรับ: Buzzebees · ผู้พัฒนาฝั่งเรียกและผู้บันทึกลงตาราง Easy: Easy (ทีมเทคนิค)

8. QR บนใบเสร็จ

รูปแบบ QR: Easy (ทีมเทคนิค) · การถอดรหัสและให้แต้ม: Buzzebees · เปิดใช้รายสาขา: Easy

ใบเสร็จทุกใบพิมพ์ QR ลูกค้าที่ไม่ได้แสดงสมาชิกตอนคิดเงินสแกนใน LINE OA เพื่อรับแต้มภายหลัง ลูกค้าใหม่สแกนแล้วสมัครสมาชิกก่อนรับแต้มได้ ไม่ต้องเรียก API จาก POS (Easy มีค่าตั้ง QrDataReceipt อยู่แล้ว ยังปิดใช้งานทุกสาขา)

ข้อมูลใน QRหมายเหตุ
branch_code, receipt_no, sale_date, sale_timeคีย์บิล ต้องตรงกับที่ส่งใน B5
net_amount_inc_vat, earn_base_amountยอดสุทธิ และยอดฐานคิดแต้มตามที่ตกลง
signatureHMAC-SHA256 ของฟิลด์ข้างต้น ด้วยคีย์ที่ Buzzebees ออกให้ (QRDataSecretKey ใน Easy) กันการแก้ยอด (เสนอ)

รูปแบบการเรียงข้อมูลใน QR (ตัวคั่น ลำดับฟิลด์ การเข้ารหัส) ให้เป็นไปตามที่ QRDataReceiptSetting ของ Easy รองรับ ให้ Easy ส่งสเปกให้ Buzzebees

กติกา

  • 1 ใบเสร็จรับแต้มได้ครั้งเดียว และต้องสแกนภายใน 7 วันนับจาก sale_date (เสนอ)
  • บิลที่สะสมแต้มผ่าน B5 แล้ว สแกน QR ต้องได้ข้อความ "บิลนี้สะสมแต้มแล้ว" ไม่ได้แต้มซ้ำ (ตรวจจากคีย์บิล)
  • รายการจาก QR ใบเสร็จบันทึกด้วย channel = receipt_qr และมี transaction_ref เหมือนรายการอื่น
  • บิลที่ถูก void หลังลูกค้าสแกนแล้ว หักแต้มคืนผ่าน B6 (Buzzebees ค้นรายการจากคีย์บิล แม้ POS ไม่มี transaction_ref)
  • QR ที่ signature ไม่ตรง ถูกปฏิเสธ และ Buzzebees บันทึกไว้ในรายงานกระทบยอด

9. ข้อกำหนดทั่วไป

ผู้รับผิดชอบให้เป็นไปตามข้อกำหนด: Buzzebees (ฝั่งรับและการดูแลระบบ) · Easy (ฝั่ง POS: เวลารอ คิวส่งซ้ำ การบันทึก log)

ความปลอดภัย

  • HTTPS (TLS 1.2 ขึ้นไป) ทุกเส้น
  • คีย์แยกต่อสาขา ส่งใน header เท่านั้น ห้ามใส่ใน URL คีย์ของสาขาหนึ่งใช้กับ branch_code อื่นไม่ได้
  • เพิกถอนคีย์ทีละสาขาได้ และเปลี่ยนคีย์ได้โดยไม่หยุดบริการ (คีย์เก่าและใหม่ใช้ได้พร้อมกัน 7 วัน)
  • คีย์ระดับสำนักงานใหญ่สำหรับ B7 และ B9 จำกัด IP ต้นทางถ้าทำได้
  • ข้อมูลส่วนบุคคลที่ผ่าน API มีเพียง member_id ชื่อปิดบางส่วน และเบอร์โทรขาเข้าใน B1 เท่านั้น

การส่งซ้ำและการกันรายการซ้ำ

  • request_id เดิม + เนื้อหาเดิม → ตอบผลเดิม (HTTP 200) ไม่ทำรายการซ้ำ
  • request_id เดิม + เนื้อหาต่าง → HTTP 409
  • คีย์บิลเดิมสะสมแต้ม (B5) ได้ครั้งเดียว ไม่ว่าจะมาจาก POS หรือ QR ใบเสร็จ
  • คิวส่งซ้ำของ B5 และ B6: ส่งซ้ำที่ 1, 5, 15 นาที จากนั้นทุก 1 ชั่วโมง จนครบ 24 ชั่วโมง แล้วจึงแจ้งเป็นรายการค้างในรายงานกระทบยอด

เวลาตอบและกรณี Buzzebees ไม่ตอบ

  • POS ตั้งเวลารอตามตารางภาพรวม API เกินเวลาถือว่าไม่สำเร็จ
  • ปิดบิลได้เสมอ ระบบสมาชิกล่มต้องไม่ขวางการขาย
  • คูปองและแลกแต้ม (B2–B4) ใช้ไม่ได้ระหว่างออฟไลน์ แคชเชียร์เห็น "ระบบสมาชิกออฟไลน์" จาก B0
  • แต้มเข้าภายหลังผ่านคิวส่งซ้ำ หรือลูกค้าสแกน QR ใบเสร็จเอง ทั้งสองทางใช้คีย์บิลเดียวกันจึงไม่ซ้ำ

การบันทึก เวลา และเงิน

  • Easy บันทึกทุกคำขอและคำตอบใน CallAPILog เก็บ 90 วัน เบอร์โทรใน log ปิดเป็น 08x-xxx-1234
  • เวลาทุกค่าเป็น ISO 8601 เขตเวลาไทย (+07:00)
  • sale_date = วันทำการของ POS (SaleDate ใน Easy) บิลหลังเที่ยงคืนก่อนปิดรอบยังนับเป็นวันเดิม
  • เงินเป็นบาท ทศนิยม 2 ตำแหน่ง แยกยอดรวม VAT และก่อน VAT เสมอ แต้มเป็นจำนวนเต็ม

  • ช่องแจ้งเหตุขัดข้องและการปิดปรับปรุงล่วงหน้า (อยู่ในหัวข้อ 12)

การคิดเงินปกติ

  • B0: ตัดการเชื่อมต่อ → POS แสดง "ระบบสมาชิกออฟไลน์" และกลับมาปกติเองเมื่อเชื่อมต่อได้
  • B1: ค้นด้วย QR และด้วยเบอร์โทร ได้ชื่อปิดบางส่วน แต้มคงเหลือ และคูปองของสาขานั้นถูกต้อง; QR หมดอายุ → QR_EXPIRED
  • B5: บิลปกติได้แต้มตามกติกา ใบเสร็จพิมพ์แต้มที่ได้และคงเหลือ และ Sale.EarnPoint ตรงกับ Buzzebees
  • B5: บิลที่มีส่วนลด ค่าบริการ และหลายวิธีชำระ คิดแต้มตามฐานที่ตกลง
  • B5: บิลเดลิเวอรี ได้หรือไม่ได้แต้มตามที่ตกลง

คูปองและแต้ม

  • B2/B3: คูปองทั้งบิล คูปองรายเมนู และคูปองแถมเมนู ใช้ได้และลง PromotionByCRM ด้วย easy_promotion_code ที่ถูกต้อง
  • B2: คูปองใช้แล้ว หมดอายุ ผิดสาขา ยอดไม่ถึง และของสมาชิกอื่น → รหัสข้อผิดพลาดตรงตามตาราง
  • B3: คูปองเดิมใช้ซ้ำที่สาขาอื่นในเวลาเดียวกันไม่ได้
  • B4: แลกแต้มปกติ แลกเกินที่มี และแลกนอกช่วง min/max → สองกรณีหลังถูกปฏิเสธ
  • B4: expected_discount ไม่ตรง → AMOUNT_MISMATCH และไม่ตัดแต้ม

การยกเลิก

  • B6: ยกเลิกบิลก่อนปิดหลัง B3/B4 สำเร็จ → คูปองกลับมาใช้ได้ แต้มคืนทันที
  • B6: void บิลที่ใช้คูปอง แลกแต้ม และได้แต้ม → ทั้งสามรายการถูกย้อนกลับ
  • B6: void บิลที่ลูกค้าใช้แต้มที่ได้ไปแล้ว → ยอดติดลบตามที่ตกลง
  • B6 + B5: คืนบางรายการ → แต้มสุทธิตรงกับยอดหลังคืน
  • B6: ยกเลิกซ้ำ → already_reversed ไม่คืนสองรอบ

เครือข่ายและการส่งซ้ำ

  • ตัดอินเทอร์เน็ตตอนปิดบิล → ปิดบิลได้ ใบเสร็จพิมพ์ "แต้มจะเข้าภายใน 24 ชั่วโมง" และแต้มเข้าหลังเน็ตกลับมา ไม่ซ้ำ

  • request_id เดิม เนื้อหาต่าง → HTTP 409
  • B8: B3 หมดเวลาหลัง Buzzebees ตัดแล้ว → B8 ตอบ completed และ POS ใช้ผลนั้นปิดบิล; หมดเวลาก่อนถึง Buzzebees → not_found
  • คีย์ของสาขา A ใช้กับ branch_code B → 401

  • B7: ส่งสาขาและเมนูทั้งชุด → received ครบ และคูปองรายเมนูอ้างอิง item_code ได้

12. เรื่องที่ต้องตกลงร่วมกัน

รายการที่ต้องได้คำตอบก่อนเริ่มพัฒนา แยกตามผู้รับผิดชอบ

ก่อนเริ่มพัฒนา ผู้รับผิดชอบ: Easy และ Buzzebees

  • Easy: ส่งสเปก HO_CRM และรูปแบบ QR ใบเสร็จ ให้ Buzzebees ปรับชื่อฟิลด์และเส้นทางในเอกสารนี้ให้ตรง และยืนยันช่องที่ Easy บันทึก (Sale.CustomerId / CustRefNum, PromotionByCRM)
  • Easy: ยืนยันว่า HO_CRM รองรับการเรียกครบ B0–B8 เส้นใดที่ไม่รองรับ ต้องมีค่าพัฒนาเพิ่มหรือไม่
  • Buzzebees: ยืนยันว่ารองรับการสแกน QR ใบเสร็จจาก POS ภายนอก และมี sandbox

กติกาทางธุรกิจ ผู้ตัดสินใจ: Oshinei (เจ้าของโครงการ)

  • ฐานคิดแต้ม: ยอดหลังส่วนลด รวมหรือไม่รวม VAT และค่าบริการ และอัตราแต้มต่อบาท
  • มูลค่า 1 แต้มเมื่อแลก ขั้นต่ำและสูงสุดต่อบิล และอายุแต้ม
  • บิลเดลิเวอรี (Grab, LINE MAN) ได้แต้มหรือไม่
  • คูปองใช้ร่วมกับส่วนลดอื่นในบิลเดียวกันได้หรือไม่ ใช้ได้กี่ใบต่อบิล และใช้คูปองพร้อมแลกแต้มในบิลเดียวได้หรือไม่
  • void บิลที่ลูกค้าใช้แต้มที่ได้ไปแล้ว ยอดติดลบได้หรือหักจากแต้มที่ได้ครั้งถัดไป
  • ข้อความท้ายใบเสร็จ (receipt_message) ใครเป็นผู้กำหนดและเปลี่ยนได้บ่อยแค่ไหน

การตั้งค่าและการดูแล ผู้รับผิดชอบ: Buzzebees และ Easy, Oshinei อนุมัติ

  • Easy: ผูกคูปองแต่ละชนิดกับรหัสส่วนลดใน Easy (easy_promotion_code) ใครดูแลตารางผูกนี้
  • Buzzebees: คีย์รายสาขา Buzzebees ออก Easy ตั้งค่า และขั้นตอนเปลี่ยนคีย์เมื่อเปิดสาขาใหม่หรือคีย์รั่ว
  • Oshinei กับ Buzzebees: สัญญาประมวลผลข้อมูลส่วนบุคคล (DPA) ที่เก็บข้อมูล และระยะเก็บ
  • Buzzebees: ค่าพัฒนา ค่าใช้จ่ายรายเดือน ระดับบริการ (ความพร้อมใช้ เวลาแก้ปัญหา) และช่องแจ้งเหตุขัดข้อง
  • Oshinei: สาขานำร่อง วันเริ่มทดสอบ sandbox และวันเริ่มใช้จริง
