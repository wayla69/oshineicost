ข้อกำหนดส่วนต่อประสานโปรแกรมประยุกต์ (API) สำหรับการเชื่อมต่อระบบ Easy POS กับ Buzzebees

ระบบสมาชิก การสะสมคะแนน และคูปองส่วนลด ณ จุดชำระเงินของทุกสาขาของ Oshinei

หน่วยงานบทบาทในโครงการขอบเขตงานหลัก
Buzzebeesผู้พัฒนาและผู้ดูแลระบบพัฒนา API ลำดับที่ B0–B9 ถอดรหัส QR บนใบเสร็จรับเงิน จัดเตรียมสภาพแวดล้อมทดสอบ (sandbox) LINE Official Account และรายงานการกระทบยอด

Oshineiเจ้าของโครงการ ผู้กำหนดเงื่อนไขทางธุรกิจ และผู้ตรวจรับงานเงื่อนไขการสะสมคะแนนและคูปอง สาขานำร่อง การฝึกอบรมพนักงานแคชเชียร์ การกระทบยอดรายวัน และการตรวจรับงาน

1. นิยามศัพท์

คำศัพท์ต่อไปนี้มีความหมายเดียวกันตลอดทั้งเอกสาร

คำศัพท์ความหมาย
API (Application Programming Interface)ส่วนต่อประสานโปรแกรมประยุกต์ ซึ่งระบบหนึ่งใช้เรียกบริการของอีกระบบหนึ่งผ่านเครือข่าย
ปลายทาง API (endpoint)ที่อยู่ URL และเมธอด HTTP ของบริการแต่ละรายการ เช่น POST /pos/v1/points/earn
การสะสมคะแนน (earn)การที่ลูกค้าได้รับคะแนนจากยอดซื้อในรายการขาย
การแลกคะแนน (burn / redemption)การที่ลูกค้าใช้คะแนนเป็นส่วนลดในรายการขาย
คูปอง (coupon)สิทธิ์ส่วนลดที่มีรหัสเฉพาะ ออกโดย Buzzebees และใช้ได้เพียงครั้งเดียว
รหัสอ้างอิงรายการขาย (bill key)branch_code + sale_date + receipt_no ใช้ระบุรายการขายหนึ่งรายการ เนื่องจากเลขที่ใบเสร็จอาจซ้ำกันระหว่างสาขาและระหว่างวัน
request_idรหัสอ้างอิงคำขอที่ระบบ POS สร้างขึ้นและไม่ซ้ำกัน ใช้สำหรับการส่งคำขอซ้ำโดยไม่เกิดรายการซ้ำ
transaction_refรหัสอ้างอิงรายการที่ Buzzebees สร้างขึ้น ใช้ในการยกเลิกรายการ (B6) การสอบถามสถานะ (B8) และการกระทบยอด (B9)
การส่งซ้ำอย่างปลอดภัย (idempotency)คุณสมบัติที่การส่งคำขอเดิมซ้ำกี่ครั้งก็ให้ผลลัพธ์เดียวกัน และไม่เกิดการตัดคะแนนหรือคูปองซ้ำ
ระยะเวลารอคำตอบ (timeout)ระยะเวลาสูงสุดที่ระบบ POS รอคำตอบ หากเกินกำหนดจะถือว่าคำขอนั้นไม่สำเร็จ
HO_CRMตัวเชื่อมระบบ CRM ภายนอกที่มีอยู่ในระบบ Easy POS ใช้เป็นช่องทางที่ระบบ POS เรียกใช้ API ของ Buzzebees
QR บนใบเสร็จรับเงิน (receipt QR)รหัส QR ที่พิมพ์บนใบเสร็จรับเงินทุกฉบับ เพื่อให้ลูกค้าสแกนรับคะแนนด้วยตนเองผ่าน LINE Official Account
การยกเลิกรายการขาย (void)การยกเลิกรายการขายทั้งรายการภายหลังการปิดรายการขายแล้ว
การกระทบยอด (reconciliation)การเปรียบเทียบรายการระหว่างระบบ Buzzebees และระบบ Easy เพื่อยืนยันว่าข้อมูลทั้งสองฝั่งตรงกัน
สภาพแวดล้อมทดสอบ (sandbox)ระบบที่แยกออกจากระบบใช้งานจริง (production) สำหรับการพัฒนาและทดสอบ

2. ขอบเขตและบทบาทหน้าที่

ระบบจะต้องรองรับให้พนักงานแคชเชียร์สามารถค้นหาข้อมูลสมาชิก บันทึกการสะสมคะแนน ใช้คูปอง แลกคะแนน และยกเลิกรายการ ณ จุดชำระเงินของทุกสาขาที่ใช้ระบบ Easy POS (ประมาณ 35 สาขา) การสมัครสมาชิกจะดำเนินการผ่าน LINE Official Account ของ Buzzebees เท่านั้น ระบบ POS ไม่รองรับการสมัครสมาชิก

หน่วยงานบทบาทหน้าที่ความรับผิดชอบ
Buzzebeesผู้พัฒนาและผู้ดูแลระบบพัฒนา API ลำดับที่ B0–B9 ตามข้อกำหนด HO_CRM ถอดรหัส QR บนใบเสร็จรับเงิน จัดเตรียมสภาพแวดล้อมทดสอบและบัญชีทดสอบ จัดส่งรายงานการกระทบยอดรายวัน และตั้งค่า LINE Official Account เงื่อนไขการสะสมคะแนน และคูปอง
Easy POSผู้จัดทำข้อกำหนดและผู้ตั้งค่าระบบ POSจัดส่งข้อกำหนด HO_CRM และรูปแบบ QR บนใบเสร็จรับเงินให้แก่ Buzzebees ตั้งค่า URL และคีย์ API รายสาขาในระบบ POS เปิดใช้งาน QR บนใบเสร็จรับเงินรายสาขา จับคู่คูปองกับรหัสส่วนลดในระบบ Easy และร่วมทดสอบระบบ
Oshineiเจ้าของโครงการ ผู้พิจารณาตัดสินใจ และผู้ตรวจรับงานกำหนดเงื่อนไขการสะสมคะแนนและคูปอง คัดเลือกสาขานำร่อง ฝึกอบรมพนักงานแคชเชียร์ ดำเนินการกระทบยอดรายวัน และตรวจรับงาน

รายการที่อยู่นอกขอบเขต: การเปลี่ยนระบบ POS เป็น B-POS การสั่งอาหารออนไลน์และบริการจัดส่ง การสมัครสมาชิก ณ จุดชำระเงิน และการส่งแคมเปญทางการตลาด (ดำเนินการภายในระบบ Buzzebees และไม่มีผลต่อ API)

4. ภาพรวม API และแผนผังการเชื่อมต่อ

ผู้พัฒนาฝั่งผู้ให้บริการ: Buzzebees · ผู้เรียกใช้: Easy POS (B0–B8), Easy HQ (B7) และระบบรายงานของ Oshinei (B9)

API ทุกลำดับเป็นการเรียกใช้จากฝั่งผู้ใช้บริการไปยัง Buzzebees ทั้งสิ้น โดยไม่มีการเรียกจาก Buzzebees กลับมายังระบบ POS เนื่องจากเครื่อง POS อยู่ภายในเครือข่ายของสาขา และไม่สามารถรับการเชื่อมต่อขาเข้า (inbound connection) จากภายนอกได้

แผนผัง API: ผู้เรียกใช้ 4 ฝ่าย และส่วนงานของ Buzzebees ที่รับคำขอ

API ประเภทหลัก (B1–B6) มีผลต่อการชำระเงินโดยตรง จึงกำหนดระยะเวลารอคำตอบให้สั้น ส่วน API ประเภทสนับสนุน (B0, B7, B8 และ B9) ใช้สำหรับการดูแลระบบ การกู้คืนเมื่อเกิดเหตุขัดข้อง และการตรวจสอบยอด

5. ลำดับการเรียกใช้ API ต่อหนึ่งรายการขาย

ผู้พัฒนาฝั่ง POS (ลำดับการเรียกใช้และการจัดการกรณีไม่สำเร็จ): Easy · ผู้พัฒนาฝั่งผู้ให้บริการ: Buzzebees

รายการขายหนึ่งรายการจะเรียกใช้ API ไม่เกิน 5 ครั้ง (B1–B5) โดยทุกครั้งเริ่มจากระบบ Easy POS การใช้สิทธิ์คูปองและการแลกคะแนน (B3 และ B4) จะต้องสำเร็จก่อนปิดรายการขาย ส่วนการบันทึกการสะสมคะแนน (B5) จะเรียกใช้หลังการชำระเงินสำเร็จและก่อนพิมพ์ใบเสร็จรับเงิน เพื่อให้ใบเสร็จรับเงินแสดงคะแนนที่ได้รับและคะแนนคงเหลือ

ลำดับการเรียกใช้ API ต่อหนึ่งรายการขาย: 5 ขั้นตอน และกรณียกเว้น 2 กรณี
  1. พนักงานแคชเชียร์สแกน QR สมาชิกจาก LINE หรือระบุหมายเลขโทรศัพท์ → B1 ค้นหาข้อมูลสมาชิก ระบบ POS แสดงชื่อ คะแนนคงเหลือ และคูปองที่ใช้ได้
  2. ลูกค้าเลือกใช้คูปอง → B2 ตรวจสอบสิทธิ์คูปอง (ยังไม่ตัดสิทธิ์) ระบบ POS บันทึกส่วนลดตามผลที่ได้รับ
  3. ลูกค้าขอแลกคะแนน → ระบบ POS คำนวณส่วนลดจาก point_balance × point_value_thb ที่ได้รับจาก B1 โดยยังไม่เรียกใช้ API
  4. ยืนยันการชำระเงิน → B3 ใช้สิทธิ์คูปอง และ B4 แลกคะแนน ทีละรายการ หากรายการใดไม่สำเร็จ ระบบ POS จะยกเลิกรายการที่สำเร็จแล้วด้วย B6 และแจ้งพนักงานแคชเชียร์
  5. ชำระเงินสำเร็จ → B5 บันทึกการสะสมคะแนน → พิมพ์ใบเสร็จรับเงินพร้อมคะแนนที่ได้รับ คะแนนคงเหลือ และ QR บนใบเสร็จรับเงิน หาก B5 ไม่ตอบกลับภายในระยะเวลาที่กำหนด ใบเสร็จรับเงินจะพิมพ์ข้อความ "คะแนนจะเข้าสู่บัญชีภายใน 24 ชั่วโมง" และระบบ POS จะบรรจุคำขอเข้าคิวส่งซ้ำ (retry queue)
  6. ยกเลิกรายการขายก่อนปิด ภายหลังจาก B3 หรือ B4 สำเร็จแล้ว → B6 พร้อม transaction_refs ทันที เพื่อคืนสิทธิ์คูปองและคะแนน
  7. ยกเลิก (void) หรือรับคืนสินค้าภายหลัง → B6 คืนสิทธิ์คูปอง คืนคะแนนที่แลก และหักคะแนนที่ได้รับ สำหรับการรับคืนสินค้าบางรายการ ให้เรียก B6 เพื่อยกเลิกทั้งรายการขาย แล้วเรียก B5 ใหม่ด้วยยอดหลังรับคืน

กรณี B3, B4 หรือ B5 เกินระยะเวลารอคำตอบ: ระบบ POS จะเรียก B8 สอบถามสถานะรายการ ด้วย request_id เดิม หากได้สถานะ completed ให้ใช้ผลลัพธ์นั้น หากได้สถานะ not_found ให้ถือว่ายังไม่มีการตัดสิทธิ์และไม่ให้ส่วนลด หาก B8 ไม่ตอบกลับเช่นกัน ให้ไม่ให้ส่วนลดและปิดรายการขายในราคาเต็ม รายการที่อาจถูกตัดสิทธิ์ไปแล้วจะปรากฏในรายงานการกระทบยอด และ Buzzebees จะดำเนินการคืนสิทธิ์ให้แก่ลูกค้า

6. รูปแบบคำขอและคำตอบ

ผู้กำหนดรูปแบบฉบับสมบูรณ์: Buzzebees (ปรับให้สอดคล้องกับข้อกำหนด HO_CRM ของ Easy)

API ทุกลำดับสื่อสารผ่านโปรโตคอล HTTPS ด้วยรูปแบบข้อมูล JSON ปลายทาง API ทั้งหมดขึ้นต้นด้วย /pos/v1/ (เสนอ) Buzzebees จะกำหนด URL ของสภาพแวดล้อมทดสอบ (sandbox) และระบบใช้งานจริง (production) แยกจากกัน

7. รายละเอียด API ลำดับที่ B0–B9

ผู้พัฒนาฝั่งผู้ให้บริการ: Buzzebees · ผู้พัฒนาฝั่งผู้เรียกใช้และผู้บันทึกข้อมูลลงตารางของระบบ Easy: Easy (ทีมเทคนิค)

API แต่ละลำดับระบุฟิลด์ที่ระบบ POS ส่ง (นอกเหนือจากฟิลด์ร่วม) ฟิลด์ใน data ที่ Buzzebees ตอบกลับ และตารางในระบบ Easy ที่จัดเก็บค่าดังกล่าว (ชื่อตารางของระบบ Easy อ้างอิงจากโครงสร้างฐานข้อมูลปัจจุบัน และจะต้องได้รับการยืนยันจาก Easy)

B0 ตรวจสอบการเชื่อมต่อ GET /pos/v1/health

ไม่มีเนื้อหาคำขอ ใช้เฉพาะส่วนหัวคำขอ และตอบกลับด้วย status และ server_time หากไม่สำเร็จ ระบบ POS จะแสดงสัญลักษณ์ "ระบบสมาชิกไม่พร้อมใช้งาน" และปิดการใช้งานปุ่มคูปองและการแลกคะแนนจนกว่าจะเชื่อมต่อได้อีกครั้ง

B1 ค้นหาข้อมูลสมาชิก POST /pos/v1/members/lookup

ฟิลด์ทิศทางคำอธิบาย
member_qrคำขอรหัสจาก QR สมาชิกใน LINE Official Account มีอายุ 5 นาที (ส่ง member_qr หรือ phone อย่างใดอย่างหนึ่ง)
phoneคำขอหมายเลขโทรศัพท์ 10 หลัก ใช้เมื่อลูกค้าไม่สามารถแสดง QR สมาชิกได้
member_idคำตอบรหัสสมาชิก ใช้ใน B2–B5
display_nameคำตอบชื่อที่ปกปิดบางส่วน (data masking) เช่น สม*** เพื่อให้พนักงานแคชเชียร์ยืนยันกับลูกค้า
tierคำตอบระดับสมาชิก (ถ้ามี)
point_balanceคำตอบคะแนนคงเหลือ
point_value_thbคำตอบมูลค่าของ 1 คะแนนเป็นบาท ระบบ POS ใช้คำนวณส่วนลดก่อนเรียกใช้ B4
min_burn, max_burn_per_billคำตอบจำนวนคะแนนขั้นต่ำและสูงสุดที่แลกได้ต่อรายการขาย
points_expiring_30dคำตอบคะแนนที่จะหมดอายุภายใน 30 วัน เพื่อให้พนักงานแคชเชียร์แจ้งลูกค้า
coupons[]คำตอบคูปองที่ใช้ได้ที่สาขานี้ ประกอบด้วย coupon_code, name, discount_text และ expiry

การบันทึกในระบบ Easy: Sale.CustomerId หรือ Sale.CustRefNum = member_id (Easy เป็นผู้ระบุช่องที่ใช้) การค้นหาด้วยหมายเลขโทรศัพท์จะตอบกลับเฉพาะชื่อที่ปกปิดบางส่วนและคะแนน โดยไม่เปิดเผยข้อมูลส่วนบุคคลอื่น

B2 ตรวจสอบสิทธิ์คูปอง POST /pos/v1/coupons/validate

ตรวจสอบว่าคูปองสามารถใช้กับรายการขายนี้ได้หรือไม่ โดยยังไม่ตัดสิทธิ์ และสามารถเรียกซ้ำได้ทุกครั้งที่รายการขายมีการเปลี่ยนแปลง

ฟิลด์ทิศทางคำอธิบาย
coupon_codeคำขอได้จาก QR คูปอง หรือเลือกจาก coupons[] ใน B1
member_idคำขอไม่บังคับ สำหรับคูปองทั่วไปที่ไม่ผูกกับสมาชิก
sale_typeคำขอdine_in, take_away หรือ delivery
bill_amountคำขอยอดก่อนหักส่วนลด รวมภาษีมูลค่าเพิ่ม
items[]คำขอitem_code, qty, unit_price, amount สำหรับคูปองที่ใช้กับเมนูเฉพาะ
validคำตอบtrue หรือ false
reasonคำตอบรหัสข้อผิดพลาด เมื่อ valid = false
discount_typeคำตอบamount (จำนวนเงิน), percent (ร้อยละ) หรือ free_item (สินค้าแถม)
discount_value, max_discountคำตอบมูลค่าส่วนลด และส่วนลดสูงสุดเป็นบาท
apply_to, item_codes[]คำตอบbill (ทั้งรายการขาย) หรือ items (เฉพาะเมนู) พร้อมรหัสเมนูที่ได้รับส่วนลด
easy_promotion_codeคำตอบรหัสส่วนลดในระบบ Easy ที่จับคู่กับคูปองประเภทนี้ ระบบ POS ใช้รหัสนี้บันทึกส่วนลด

B3 ใช้สิทธิ์คูปอง POST /pos/v1/coupons/redeem

ฟิลด์ทิศทางคำอธิบาย
coupon_code, member_idคำขอค่าเดียวกับ B2
receipt_no, sale_dateคำขอเมื่อรวมกับ branch_code จะเป็นรหัสอ้างอิงรายการขาย
discount_amountคำขอส่วนลดที่ใช้จริงเป็นบาท Buzzebees จะตรวจสอบว่าไม่เกินมูลค่าที่ตอบกลับใน B2
transaction_refคำตอบรหัสอ้างอิงรายการ
redeemed_atคำตอบเวลาที่ตัดสิทธิ์คูปอง

การบันทึกในระบบ Easy: PromotionByCRM (CouponNumber, DiscountAmount, TransactionRef, IsSuccess) คูปองที่ถูกตัดสิทธิ์แล้วจะกลับมาใช้ได้อีกเฉพาะผ่าน B6 เท่านั้น

B4 แลกคะแนนเป็นส่วนลด POST /pos/v1/points/burn

ฟิลด์ทิศทางคำอธิบาย
member_id, receipt_no, sale_dateคำขอ
pointsคำขอจำนวนคะแนนที่ลูกค้าขอใช้ ซึ่งจะต้องอยู่ระหว่าง min_burn และ max_burn_per_bill
expected_discountคำขอส่วนลดที่ระบบ POS คำนวณไว้ (points × point_value_thb) Buzzebees จะตรวจสอบว่าตรงกัน
discount_amountคำตอบส่วนลดที่อนุมัติจริง
point_balanceคำตอบคะแนนคงเหลือหลังการแลก
transaction_refคำตอบรหัสอ้างอิงรายการ

การบันทึกในระบบ Easy: Sale.RedeemedPoint, Sale.BalancePoint และ PromotionByCRM เพิ่มอีกหนึ่งแถวสำหรับส่วนลดจากการแลกคะแนน

B5 บันทึกการสะสมคะแนน POST /pos/v1/points/earn

เรียกใช้หลังการชำระเงินสำเร็จและก่อนพิมพ์ใบเสร็จรับเงิน เพื่อให้ใบเสร็จรับเงินแสดงคะแนนที่ได้รับและคะแนนคงเหลือ รหัสอ้างอิงรายการขายหนึ่งรายการสะสมคะแนนได้เพียงครั้งเดียว (คำขอครั้งที่สองจะได้รับรหัส DUPLICATE_RECEIPT)

ฟิลด์ทิศทางคำอธิบาย
member_id, receipt_no, sale_date, sale_timeคำขอ
sale_type, coversคำขอช่องทางการขาย และจำนวนลูกค้าที่ใช้บริการ
gross_amount, discount_amount, service_charge, vat_amountคำขอยอดก่อนหักส่วนลด ส่วนลดรวม ค่าบริการ และภาษีมูลค่าเพิ่ม แยกรายการครบถ้วน เพื่อให้ Buzzebees คำนวณคะแนนตามฐานที่ตกลงกัน
net_amount_inc_vat, net_amount_ex_vatคำขอยอดสุทธิหลังหักส่วนลด รวมและไม่รวมภาษีมูลค่าเพิ่ม

การบันทึกในระบบ Easy: Sale.EarnPoint, Sale.EarnPointNetAmount, Sale.BalancePoint และพิมพ์ earned_points, point_balance, receipt_message บนใบเสร็จรับเงิน หาก B5 ไม่ตอบกลับภายในระยะเวลาที่กำหนด ใบเสร็จรับเงินจะพิมพ์ข้อความ "คะแนนจะเข้าสู่บัญชีภายใน 24 ชั่วโมง" และระบบ POS จะบรรจุคำขอเข้าคิวส่งซ้ำด้วย request_id เดิม

B6 ยกเลิกรายการ POST /pos/v1/transactions/void

ใช้ใน 3 กรณี ได้แก่ การยกเลิกรายการขายก่อนปิดภายหลังจาก B3 หรือ B4 สำเร็จแล้ว การยกเลิกรายการขาย (void) ภายหลังการปิด และการรับคืนสินค้า สำหรับการรับคืนสินค้าบางรายการ ให้เรียก B6 เพื่อยกเลิกทั้งรายการขาย แล้วเรียก B5 ใหม่ด้วยยอดหลังรับคืน

ฟิลด์ทิศทางคำอธิบาย
void_typeคำขอcancel_before_close, void หรือ return
receipt_no, sale_dateคำขอรายการขายที่ยกเลิก (ไม่บังคับเมื่อเป็น cancel_before_close)

void_reasonคำขอเหตุผลที่พนักงานแคชเชียร์เลือกในระบบ POS

point_balanceคำตอบคะแนนคงเหลือหลังการยกเลิก ซึ่งอาจติดลบได้ หากลูกค้าได้ใช้คะแนนที่ได้รับจากรายการขายนี้ไปแล้ว

การบันทึกในระบบ Easy: PromotionByCRM.DiscountStatus ของรายการที่ยกเลิก (Easy เป็นผู้ยืนยันช่องที่ใช้)

B7 ส่งข้อมูลหลัก PUT /pos/v1/master/branches และ PUT /pos/v1/master/items

ผู้เรียกใช้คือระบบ Easy HQ มิใช่เครื่อง POS ของสาขา โดยส่งข้อมูลทั้งชุดทุกครั้ง (full snapshot) Buzzebees ใช้ข้อมูลนี้ในการกำหนดคูปองรายสาขาและคะแนนพิเศษรายเมนู

ฟิลด์ทิศทางคำอธิบาย
branches[]คำขอbranch_code, name, active
items[]คำขอitem_code, name, category, price, active
receivedคำตอบจำนวนรายการที่รับเข้าระบบ
rejected[]คำตอบcode และ reason ของรายการที่ไม่สามารถรับเข้าระบบได้

B8 สอบถามสถานะรายการ GET /pos/v1/transactions/{request_id}

ใช้เมื่อ B3, B4 หรือ B5 เกินระยะเวลารอคำตอบ และระบบ POS จำเป็นต้องทราบว่า Buzzebees ได้ดำเนินการรายการดังกล่าวแล้วหรือไม่

ฟิลด์ทิศทางคำอธิบาย

B9 รายงานการกระทบยอด GET /pos/v1/reports/daily?branch_code=&date=

ผู้เรียกใช้คือระบบรายงานของ Oshinei ตอบกลับเป็น rows[] ตามคอลัมน์ในหัวข้อที่ 10 พร้อม total_count และ generated_at โดยใช้คีย์ API ระดับสำนักงานใหญ่ มิใช่คีย์ API ของสาขา ทั้งนี้ การจัดส่งไฟล์ CSV ทางอีเมลหรือ SFTP เป็นช่องทางสำรอง

8. QR บนใบเสร็จรับเงิน

ผู้กำหนดรูปแบบ QR: Easy (ทีมเทคนิค) · ผู้ถอดรหัสและให้คะแนน: Buzzebees · ผู้เปิดใช้งานรายสาขา: Easy

ใบเสร็จรับเงินทุกฉบับจะพิมพ์ QR เพื่อให้ลูกค้าที่ไม่ได้แสดงสถานะสมาชิกขณะชำระเงิน สามารถสแกนผ่าน LINE Official Account เพื่อรับคะแนนภายหลังได้ ลูกค้าใหม่สามารถสแกนแล้วสมัครสมาชิกก่อนรับคะแนนได้ โดยไม่ต้องเรียกใช้ API จากระบบ POS (ระบบ Easy มีการตั้งค่า QrDataReceipt อยู่แล้ว แต่ยังปิดการใช้งานในทุกสาขา)

ข้อมูลใน QRคำอธิบาย
branch_code, receipt_no, sale_date, sale_timeรหัสอ้างอิงรายการขาย ซึ่งจะต้องตรงกับค่าที่ส่งใน B5
net_amount_inc_vat, earn_base_amountยอดสุทธิ และยอดฐานสำหรับคำนวณคะแนนตามที่ตกลงกัน
signatureลายมือชื่อดิจิทัลแบบ HMAC-SHA256 ของฟิลด์ข้างต้น โดยใช้คีย์ลับที่ Buzzebees ออกให้ (QRDataSecretKey ในระบบ Easy) เพื่อป้องกันการแก้ไขยอด (เสนอ)

รูปแบบการจัดเรียงข้อมูลใน QR (ตัวคั่น ลำดับฟิลด์ และการเข้ารหัส) จะเป็นไปตามที่การตั้งค่า QRDataReceiptSetting ของระบบ Easy รองรับ โดย Easy จะจัดส่งข้อกำหนดให้แก่ Buzzebees

เงื่อนไข

  • ใบเสร็จรับเงินหนึ่งฉบับรับคะแนนได้เพียงครั้งเดียว และจะต้องสแกนภายใน 7 วันนับจาก sale_date (เสนอ)
  • รายการขายที่สะสมคะแนนผ่าน B5 แล้ว เมื่อสแกน QR จะต้องได้รับข้อความ "รายการขายนี้ได้รับคะแนนแล้ว" และไม่ได้รับคะแนนซ้ำ (ตรวจสอบจากรหัสอ้างอิงรายการขาย)
  • รายการจาก QR บนใบเสร็จรับเงินบันทึกด้วย channel = receipt_qr และมี transaction_ref เช่นเดียวกับรายการอื่น
  • รายการขายที่ถูกยกเลิก (void) ภายหลังลูกค้าสแกนแล้ว จะหักคะแนนคืนผ่าน B6 (Buzzebees ค้นหารายการจากรหัสอ้างอิงรายการขาย แม้ระบบ POS ไม่มี transaction_ref)
  • QR ที่ลายมือชื่อดิจิทัลไม่ถูกต้องจะถูกปฏิเสธ และ Buzzebees จะบันทึกไว้ในรายงานการกระทบยอด

9. ข้อกำหนดทั่วไป

ผู้รับผิดชอบการปฏิบัติตามข้อกำหนด: Buzzebees (ฝั่งผู้ให้บริการและการดูแลระบบ) · Easy (ฝั่ง POS ได้แก่ ระยะเวลารอคำตอบ คิวส่งซ้ำ และการบันทึกประวัติการทำงาน)

ความมั่นคงปลอดภัย (security)

  • API ทุกลำดับสื่อสารผ่าน HTTPS ด้วยการเข้ารหัส TLS 1.2 ขึ้นไป
  • คีย์ API แยกตามสาขา และส่งในส่วนหัวคำขอเท่านั้น ห้ามระบุใน URL คีย์ API ของสาขาหนึ่งไม่สามารถใช้กับ branch_code อื่นได้
  • สามารถเพิกถอน (revoke) คีย์ API ได้เป็นรายสาขา และสามารถเปลี่ยนคีย์ (key rotation) ได้โดยไม่หยุดให้บริการ (คีย์เดิมและคีย์ใหม่ใช้งานได้พร้อมกัน 7 วัน)
  • คีย์ API ระดับสำนักงานใหญ่สำหรับ B7 และ B9 ควรจำกัดหมายเลข IP ต้นทาง (IP allowlist) หากสามารถดำเนินการได้
  • ข้อมูลส่วนบุคคลที่ส่งผ่าน API ประกอบด้วย member_id ชื่อที่ปกปิดบางส่วน และหมายเลขโทรศัพท์ในคำขอของ B1 เท่านั้น

การส่งซ้ำอย่างปลอดภัย (idempotency) และการป้องกันรายการซ้ำ

  • request_id เดิม พร้อมเนื้อหาคำขอเดิม → ตอบกลับด้วยผลลัพธ์เดิม (HTTP 200) โดยไม่ดำเนินการซ้ำ
  • request_id เดิม แต่เนื้อหาคำขอแตกต่าง → HTTP 409
  • รหัสอ้างอิงรายการขายหนึ่งรายการสะสมคะแนน (B5) ได้เพียงครั้งเดียว ไม่ว่าคำขอจะมาจากระบบ POS หรือ QR บนใบเสร็จรับเงิน
  • คิวส่งซ้ำของ B5 และ B6: ส่งซ้ำเมื่อครบ 1, 5 และ 15 นาที จากนั้นทุก 1 ชั่วโมงจนครบ 24 ชั่วโมง แล้วจึงรายงานเป็นรายการค้างในรายงานการกระทบยอด

ระยะเวลาตอบสนองและกรณี Buzzebees ไม่ตอบกลับ

  • ระบบ POS กำหนดระยะเวลารอคำตอบตามตารางภาพรวม API หากเกินกำหนดให้ถือว่าไม่สำเร็จ
  • ระบบ POS จะต้องปิดรายการขายได้เสมอ การขัดข้องของระบบสมาชิกจะต้องไม่เป็นอุปสรรคต่อการขาย
  • ไม่สามารถใช้คูปองและแลกคะแนน (B2–B4) ได้ระหว่างที่ระบบสมาชิกไม่พร้อมใช้งาน พนักงานแคชเชียร์จะเห็นสถานะ "ระบบสมาชิกไม่พร้อมใช้งาน" จาก B0
  • คะแนนจะเข้าสู่บัญชีภายหลังผ่านคิวส่งซ้ำ หรือเมื่อลูกค้าสแกน QR บนใบเสร็จรับเงินด้วยตนเอง ทั้งสองช่องทางใช้รหัสอ้างอิงรายการขายเดียวกัน จึงไม่เกิดรายการซ้ำ

การบันทึกประวัติการทำงาน เวลา และหน่วยเงิน

  • ระบบ Easy บันทึกคำขอและคำตอบทุกรายการในตาราง CallAPILog และจัดเก็บเป็นเวลา 90 วัน หมายเลขโทรศัพท์ในประวัติการทำงานจะถูกปกปิดในรูปแบบ 08x-xxx-1234
  • ค่าเวลาทั้งหมดใช้รูปแบบ ISO 8601 ตามเขตเวลาประเทศไทย (+07:00)
  • sale_date หมายถึงวันทำการของระบบ POS (SaleDate ในระบบ Easy) รายการขายหลังเวลาเที่ยงคืนแต่ก่อนปิดรอบการขายจะนับเป็นวันทำการเดิม
  • หน่วยเงินเป็นบาท ทศนิยม 2 ตำแหน่ง และแยกยอดรวมและไม่รวมภาษีมูลค่าเพิ่มเสมอ คะแนนเป็นจำนวนเต็ม

  • B5: รายการขายที่มีส่วนลด ค่าบริการ และการชำระเงินหลายช่องทาง คำนวณคะแนนตามฐานที่ตกลงกัน
  • B5: รายการขายผ่านช่องทางจัดส่ง ได้รับหรือไม่ได้รับคะแนนตามที่ตกลงกัน

  • B2/B3: คูปองส่วนลดทั้งรายการขาย คูปองส่วนลดรายเมนู และคูปองสินค้าแถม ใช้ได้และบันทึกในตาราง PromotionByCRM ด้วย easy_promotion_code ที่ถูกต้อง

  • ใช้คีย์ API ของสาขา A กับ branch_code ของสาขา B → HTTP 401

  • B7: ส่งข้อมูลสาขาและเมนูทั้งชุด → received ครบถ้วน และคูปองรายเมนูอ้างอิง item_code ได้
  • B9: รายงานการกระทบยอดของวันทดสอบตรงกับระบบ Easy ทุกรายการ รวมถึงรายการที่ถูกยกเลิกและรายการจาก QR บนใบเสร็จรับเงิน

12. ประเด็นที่ต้องได้รับการตกลงร่วมกัน

ประเด็นต่อไปนี้จะต้องได้รับข้อยุติก่อนเริ่มการพัฒนา โดยจำแนกตามผู้รับผิดชอบ

ก่อนเริ่มการพัฒนา ผู้รับผิดชอบ: Easy และ Buzzebees

  • Easy: จัดส่งข้อกำหนด HO_CRM และรูปแบบ QR บนใบเสร็จรับเงิน เพื่อให้ Buzzebees ปรับชื่อฟิลด์และปลายทาง API ในเอกสารนี้ให้สอดคล้อง และยืนยันช่องที่ระบบ Easy ใช้บันทึกข้อมูล (Sale.CustomerId / CustRefNum และ PromotionByCRM)
  • Easy: ยืนยันว่า HO_CRM รองรับการเรียกใช้ API ครบทุกลำดับตั้งแต่ B0 ถึง B8 และหากมีลำดับใดที่ไม่รองรับ จะมีค่าใช้จ่ายในการพัฒนาเพิ่มเติมหรือไม่
  • Buzzebees: ยืนยันการรองรับการสแกน QR บนใบเสร็จรับเงินจากระบบ POS ภายนอก และการจัดเตรียมสภาพแวดล้อมทดสอบ

เงื่อนไขทางธุรกิจ ผู้พิจารณาตัดสินใจ: Oshinei (เจ้าของโครงการ)

  • ฐานการคำนวณคะแนน: ยอดหลังหักส่วนลด รวมหรือไม่รวมภาษีมูลค่าเพิ่มและค่าบริการ และอัตราคะแนนต่อบาท
  • มูลค่าของ 1 คะแนนเมื่อแลก จำนวนคะแนนขั้นต่ำและสูงสุดต่อรายการขาย และอายุของคะแนน
  • รายการขายผ่านช่องทางจัดส่ง (Grab, LINE MAN) ได้รับคะแนนหรือไม่
  • คูปองสามารถใช้ร่วมกับส่วนลดอื่นในรายการขายเดียวกันได้หรือไม่ ใช้ได้กี่ฉบับต่อรายการขาย และสามารถใช้คูปองร่วมกับการแลกคะแนนในรายการขายเดียวกันได้หรือไม่
  • กรณียกเลิกรายการขายที่ลูกค้าได้ใช้คะแนนที่ได้รับไปแล้ว ให้คะแนนคงเหลือติดลบได้ หรือหักจากคะแนนที่จะได้รับในครั้งถัดไป
  • ผู้กำหนดข้อความท้ายใบเสร็จรับเงิน (receipt_message) และความถี่ในการเปลี่ยนแปลง

การตั้งค่าและการดูแลระบบ ผู้รับผิดชอบ: Buzzebees และ Easy โดย Oshinei เป็นผู้อนุมัติ

  • Easy: การจับคู่คูปองแต่ละประเภทกับรหัสส่วนลดในระบบ Easy (easy_promotion_code) และผู้รับผิดชอบดูแลตารางการจับคู่ดังกล่าว
  • Buzzebees: การออกคีย์ API รายสาขา (Buzzebees ออกคีย์ และ Easy ตั้งค่า) และขั้นตอนการเปลี่ยนคีย์เมื่อเปิดสาขาใหม่หรือกรณีคีย์รั่วไหล
  • Oshinei และ Buzzebees: สัญญาการประมวลผลข้อมูลส่วนบุคคล (DPA) สถานที่จัดเก็บข้อมูล และระยะเวลาการจัดเก็บ
  • Buzzebees: ค่าพัฒนา ค่าบริการรายเดือน ข้อตกลงระดับการให้บริการ (Service Level Agreement: SLA) ได้แก่ ความพร้อมใช้งานและระยะเวลาการแก้ไขปัญหา และช่องทางการแจ้งเหตุขัดข้อง
  • Oshinei: สาขานำร่อง วันเริ่มทดสอบในสภาพแวดล้อมทดสอบ และวันเริ่มใช้งานจริง
