# เปลี่ยน write token (`OSHINEI_SEED_TOKEN`) — ขั้นตอนสำหรับเจ้าของ

> ทำหลังเปิดล็อกอินของระบบกระทบยอดแล้ว (`RECON_LOGIN=1`, 2026-10-07) — ดู `recon/LOGIN_ROLLOUT.md` ข้อ 10
> เครื่องมือ: `scripts/rotate_seed_token.py` · ทดสอบ: `backend/test_rotate_seed_token.py`

## ทำไมต้องเปลี่ยน

write token คือรหัสที่ให้ "บันทึกข้อมูล" ได้โดยไม่ต้องเข้าสู่ระบบ ใช้ร่วมกันทั้ง **แดชบอร์ดต้นทุน** และ **ระบบกระทบยอด**
token ชุดปัจจุบันเคยถูกพิมพ์ใส่ปุ่ม **รหัส** ในเบราว์เซอร์ของพนักงานหลายเครื่อง — ใครถือ token เดิมยังเขียนข้อมูลได้โดยไม่ผ่านล็อกอินใหม่
การเปลี่ยนจึงปิดช่องนี้ และให้แต่ละคนถือ token ของตัวเอง (ยกเลิกรายคนได้)

## ใครใช้ token อยู่ (ตรวจ 2026-10-07)

| ผู้ถือ (label) | ใช้ทำอะไร | หลังเปลี่ยนต้องทำอะไร |
|---|---|---|
| `admin` | เครื่อง PC นี้: sync ยอดขายขึ้น Fly (06/12/16 น.), ดึงค่าจาก Fly, สรุปเมนู, เสียงลูกค้า, task watchdog, BoM Center, อัปโหลดเอกสาร recon หลายไฟล์ | **ไม่ต้องทำอะไร** — สคริปต์ทุกตัวอ่านบรรทัดแรกของ `backend/.seed_tokens.txt` ซึ่งสคริปต์เปลี่ยนให้เอง |
| `Patcharee` · `Arnan` · `AR` | ปุ่ม **รหัส** ในเบราว์เซอร์ (แก้ข้อมูลในแดชบอร์ด เช่น ต้นทุน เป้า ฯลฯ และเดิมใช้บันทึกในระบบกระทบยอด) | ถ้ายังต้อง **แก้ข้อมูลในแดชบอร์ด** → ให้ token ใหม่ แล้วแดชบอร์ดจะถามเองเมื่อบันทึกครั้งถัดไป · ถ้าใช้แค่ระบบกระทบยอด → **ไม่ต้องมีแล้ว** (ใช้ล็อกอินแทน) |
| `upload.bat` (ไฟล์ในเครื่อง) | อัปโหลดเอกสาร recon หลายไฟล์ | token ในไฟล์นี้ **หมดอายุไปแล้ว** (ทดสอบแล้วถูกปฏิเสธ) — ลบบรรทัด token ออก ให้ไปอ่านจาก `backend/.seed_tokens.txt` แทน (ผมแก้ให้แล้ว) |

ไม่มี token อยู่ใน GitHub Actions, ตัวแปรระบบของ Windows หรือใน git — มีแค่ Fly secret กับไฟล์สำรองในเครื่อง

## ต้องตัดสินใจก่อน 1 ข้อ

**Patcharee / Arnan / AR ยังต้องแก้ข้อมูลในแดชบอร์ดต้นทุนไหม?**
- ใช่ → ใส่ชื่อในคำสั่ง (`--keep admin Patcharee Arnan AR`) แต่ละคนได้ token ใหม่ของตัวเอง
- ไม่ (ทำงานแค่ระบบกระทบยอด) → ไม่ต้องใส่ชื่อ token ของคนนั้นถูกยกเลิก

## ขั้นตอน (ประมาณ 5 นาที · แอปรีสตาร์ต ~20 วินาที)

> **ห้ามทำช่วง 05:50–07:00, 11:50–13:00, 15:50–17:00** — เป็นช่วง sync ที่ใช้ token (สคริปต์จะไม่ยอมทำให้เองถ้าอยู่ในช่วงนี้)

1. **ดูแผนก่อน (ไม่เปลี่ยนอะไร)** — ในโฟลเดอร์ `C:\Users\ASUS\Oshinei`
   ```bash
   py -3.12 scripts/rotate_seed_token.py --keep admin Patcharee Arnan AR
   ```
   จะแสดงว่าใครได้ token ใหม่ ใครถูกยกเลิก

2. **เปลี่ยนจริง**
   ```bash
   py -3.12 scripts/rotate_seed_token.py --keep admin Patcharee Arnan AR --apply
   ```
   สคริปต์ทำตามลำดับนี้ให้เอง:
   1. เขียนไฟล์สำรองใหม่ `backend/.seed_tokens.txt` **ก่อน** (ไฟล์เดิมเก็บเป็น `backend/.seed_tokens.revoked-<วันที่>.txt`)
   2. ตั้ง `OSHINEI_SEED_TOKEN` บน Fly (ถ้าไม่สำเร็จ จะคืนไฟล์สำรองเดิมให้ ไม่มีอะไรเปลี่ยน)
   3. ทดสอบบนระบบจริง: token ใหม่ทุกตัวต้อง "accepted" และ token เดิมทุกตัวต้อง "refused"
   4. แสดง token ใหม่ของแต่ละคน

3. **ส่ง token ใหม่ให้แต่ละคนทางช่องทางส่วนตัว** (LINE ส่วนตัว) — คนละตัว ไม่ส่งในกลุ่ม แล้วปิดหน้าต่างที่แสดง token
   - `admin` ไม่ต้องส่งใคร (อยู่ในไฟล์สำรองของเครื่องนี้แล้ว)

4. **แต่ละคน (ถ้ายังใช้แดชบอร์ด):** เปิดแดชบอร์ด → บันทึกอะไรสักอย่าง → ระบบจะขึ้นกล่องให้ใส่ token → ใส่ token ใหม่ของตัวเอง

5. **ตรวจรอบ sync ถัดไป** (12:00 หรือ 16:00): log `backend/logs/sync_live_fly.log` ต้องจบด้วย `Done. Live data is on …`
   ถ้าขึ้น `HTTP 403/404` = เครื่องนี้ใช้ token เดิม → ตรวจว่า `backend/.seed_tokens.txt` บรรทัดแรกเป็น `admin:…`

## ย้อนกลับ

ไฟล์ `backend/.seed_tokens.revoked-<วันที่>.txt` เก็บ token ชุดเดิมไว้ — ถ้าจำเป็นต้องคืน:
```bash
py -3.12 -c "from pathlib import Path; import re; t=[l for l in Path('backend/.seed_tokens.revoked-YYYYMMDD.txt').read_text(encoding='utf-8').splitlines() if ':' in l and not l.startswith('#')]; print(','.join(t))"
flyctl secrets set -a oshinei-dashboard OSHINEI_SEED_TOKEN='<ค่าที่พิมพ์ออกมา>'
```
แล้วคัดลอกไฟล์ revoked กลับเป็น `backend/.seed_tokens.txt` (ลบบรรทัดแรกที่เป็นหมายเหตุ REVOKED)

## เพิ่ม / ยกเลิกคนเดียวภายหลัง

รันคำสั่งเดิมโดยใส่รายชื่อคนที่ **ยังให้ใช้** ทั้งหมด — ทุกคนในรายชื่อได้ token ใหม่ (ต้องส่งให้ใหม่ทุกคน)
คนที่ไม่อยู่ในรายชื่อถูกยกเลิกทันที
