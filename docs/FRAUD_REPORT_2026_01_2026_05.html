1บทสรุปผู้บริหารและธงแดง

8ข้อเสนอแนะการควบคุม

มาตรการลดความเสี่ยงที่ทำได้ทันที เรียงตามผลกระทบ

1 · บังคับเลือก "เหตุผล" ทุกครั้งที่ลดราคา/วอยด์

ปิดช่องว่างที่ใหญ่ที่สุด — ส่วนลดไม่ระบุเหตุผล 93.2% (฿7.93M) ตั้งค่า POS ให้ reason เป็น required field

2 · จำกัดสิทธิ์วอยด์/แก้ราคา เฉพาะผู้จัดการ + รหัสอนุมัติ

วอยด์ ฿5,601,731 และแก้ราคา 1,413 ครั้งกระจุกในผู้ใช้ไม่กี่คน — ต้องมี manager override code และเก็บ log

3 · นับเงินสดสองชั้น (dual count) ในสาขาที่ขาดสะสม

เงินขาดสุทธิ ฿-937,972 — สาขาที่ขาดต่อเนื่องควรให้ผู้จัดการร่วมนับและเซ็นกำกับทุกกะ

4 · สุ่มตรวจใบเสร็จ/CCTV ตามธงแดงในรายงานนี้

โฟกัสที่บิลวอยด์มูลค่าสูง การวอยด์ยอดซ้ำ ๆ และวันที่เงินขาดหนัก — เทียบกับภาพกล้องและสต๊อกจริง

5 · ทำรายงานนี้เป็นประจำทุกเดือน + ตั้ง alert

รัน gen_fraud_report.py ทุกสิ้นเดือน หรือผูกกับแท็บ #fraud ในแดชบอร์ดเพื่อเฝ้าระวังต่อเนื่อง

9ระเบียบวิธีและข้อจำกัดของข้อมูล

  • แหล่งข้อมูล: oshinei.db (คลังข้อมูล Easy POS) ตาราง pos_cancel_bill_detail, pos_cashcount_day, pos_price_change, sales_transaction
  • ช่วงเวลา: 2026-01-01 ถึง 2026-05-31 — วอยด์/แก้ราคากรองตามวันที่ทำรายการ, เงินสดกรองตามวันนับเงิน
  • "ความเสี่ยงรวม" = ยอดวอยด์ + ยอดเงินขาดสุทธิ (ค่าสัมบูรณ์) — เป็น มูลค่าที่ควรตรวจสอบ ไม่ใช่มูลค่าการสูญเสียที่ยืนยันแล้ว
  • ตัวเลขทั้งหมดเป็นสัญญาณเชิงสถิติ ต้องตรวจสอบเอกสาร/CCTV/สอบถามผู้รับผิดชอบก่อนสรุปว่าเป็นการทุจริต
  • ส่วนลดไม่ระบุเหตุผล = discount_reason_id ว่าง/0; แคชเชียร์เกินเกณฑ์ = ลด ≥ 2× มัธยฐานเครือ (พื้น 5%)
  • คะแนนรายสาขาเป็นการเทียบกันเองในเครือ (relative) ไม่ใช่เกณฑ์มาตรฐานอุตสาหกรรม
