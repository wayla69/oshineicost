# เริ่มใช้งานระบบ “วัตถุดิบและใบสั่งซื้อ” กับ 30 สาขา

เอกสารสำหรับเจ้าของ: ลำดับงานที่ต้องทำตั้งแต่สร้างบัญชีสาขาจนถึงสัปดาห์แรกของการใช้งานจริง (PR-I)
สคริปต์ทั้งหมดอยู่ในโฟลเดอร์ `scripts\` ของโปรเจกต์ รันด้วย `py -3.12` จาก `C:\Users\ASUS\Oshinei`

## หลักการ

- สคริปต์ **ไม่ส่งข้อความเอง** และ **ไม่แสดงรหัสผ่านบนหน้าจอ** รหัสผ่านเริ่มต้นอยู่เฉพาะในไฟล์ข้อความและบัตรที่สร้างขึ้น
- ไฟล์ที่สร้างอยู่นอกโปรเจกต์ (ตัวอย่างในเอกสารนี้ใช้ `D:\onboarding`) ห้ามนำขึ้น GitHub และให้ลบโฟลเดอร์ที่มีรหัสผ่านเมื่อแจกเสร็จ
- ทุกสาขาใช้ไฟล์รายชื่อไฟล์เดียวกันในทุกขั้นตอน: คอลัมน์ `สาขา` · `ตัวย่อ` · `ชื่อผู้ใช้` (เว้นว่างไว้ กรอกเฉพาะกรณีพิเศษ) · `LINE/ผู้รับ` (ไม่บังคับ)
- ชื่อผู้ใช้ของสาขาคือ `wh_<ตัวย่อ>` (ตัวพิมพ์เล็ก เช่น ตัวย่อ `udon` = `wh_udon`) ตัวย่อใช้ได้เฉพาะ a-z 0-9 ยาว 2–12 ตัวอักษรและห้ามซ้ำกัน สาขาที่ไม่มีตัวย่อและไม่ระบุชื่อผู้ใช้ระบบตั้งเป็น `wh_<รหัสสาขา>` (ไม่แนะนำ) สาขานำร่อง 4 แห่งมีตัวย่อในตัว (`ubon` `udon` `khonkaen` `rayong`) และสาขาที่มีบัญชีสาขาอยู่แล้วจะไม่ถูกสร้างบัญชีที่สอง ยกเว้นการเปลี่ยนบัญชีนำร่องตามหัวข้อ “เปลี่ยนบัญชีสาขานำร่องเป็น wh_*” ด้านล่าง

## ขั้นตอน

### 1. สร้างไฟล์รายชื่อ 30 สาขา

```powershell
py -3.12 scripts\branch_handout.py --template --out D:\onboarding
```

ได้ไฟล์ `D:\onboarding\branch_list_template.xlsx` ที่มีสาขานำร่อง 4 แถวพร้อมตัวย่อเป็นตัวอย่าง ให้เปิดแล้วกรอกครบ 30 สาขา (ชื่อสาขาและตัวย่อ) แล้วบันทึกเป็น `D:\onboarding\branches.xlsx`

- ชื่อสาขาต้องตรงกับที่ระบบแสดง (ดูได้จากตาราง ตั้งค่า → รอบส่งของสาขา หรือจากไฟล์แม่แบบวันส่งในขั้นตอนที่ 4)
- ตัวย่อสาขาใช้ a-z 0-9 ยาว 2–12 ตัวอักษร ระบบแปลงเป็นตัวพิมพ์เล็กและตรวจว่าไม่ซ้ำกัน
- ชื่อผู้ใช้ใช้ได้เฉพาะ a-z 0-9 `_` `.` `-` ยาว 3–40 ตัวอักษร ให้เว้นว่างไว้ ระบบตั้งเป็น `wh_<ตัวย่อ>` ให้เอง
- ช่อง `LINE/ผู้รับ` ใช้จดว่าจะส่งข้อความให้ใคร (กลุ่ม LINE ของสาขา หรือผู้จัดการสาขา) ระบบจะพิมพ์ไว้ใน README ของชุดข้อความ
- ห้ามใส่รหัสผ่านในไฟล์นี้
- จะแบ่งเป็นหลายไฟล์เพื่อทยอยเปิดทีละรุ่นก็ได้ สคริปต์ทุกตัวรับไฟล์รายชื่อใดก็ได้

### 2. สร้างบัญชีสาขา (ดูแผนก่อน แล้วจึงสร้างจริง)

สคริปต์ใช้บัญชี Management เข้าสู่ระบบ เพราะการสร้างผู้ใช้เป็นสิทธิ์ของ Management (ไม่ใช่ write token) บัญชีนี้ต้องเปลี่ยนรหัสผ่านเริ่มต้นแล้ว สคริปต์จะถามรหัสผ่านโดยไม่แสดงตัวอักษร หรืออ่านจากตัวแปร `OSHINEI_ADMIN_PASSWORD` หากกำหนดไว้ ชื่อบัญชีเริ่มต้นคือ `management1` (เปลี่ยนด้วย `--admin-user`)

```powershell
# แผนเท่านั้น ไม่สร้างบัญชี (ค่าเริ่มต้น)
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx

# ตรวจตารางสรุปแล้วจึงสร้างจริง
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx --yes
```

สิ่งที่สคริปต์ทำกับแต่ละแถว

1. ตรวจชื่อสาขากับรายชื่อสาขาที่เปิดใช้งานในระบบ (ไม่พบ = แถวนั้นไม่สำเร็จ)
2. ข้ามแถวที่มีบัญชีอยู่แล้ว หรือสาขาที่มีบัญชีสาขาอยู่แล้ว (รายงานเป็น “มีอยู่แล้ว”)
3. สร้างบัญชีบทบาท “สาขา” ผูกกับสาขานั้น โดยไม่ส่งรหัสผ่าน ระบบจึงใช้รหัสผ่านเริ่มต้นและบังคับให้ตั้งรหัสผ่านใหม่เมื่อเข้าใช้ครั้งแรก

เมื่อใช้ `--yes` สคริปต์เขียน `D:\onboarding\accounts_result.csv` (สาขา · ชื่อผู้ใช้ · ผู้รับ · ผล · หมายเหตุ) การรันซ้ำปลอดภัย: บัญชีที่สร้างไปแล้วไม่ถูกสร้างซ้ำและยังคงสถานะ “สร้างแล้ว” ในไฟล์ผลลัพธ์ หากมีแถว “ไม่สำเร็จ” ให้แก้ไขไฟล์รายชื่อแล้วรันซ้ำ

#### เปลี่ยนบัญชีสาขานำร่องเป็น wh_*

บัญชีนำร่อง 4 บัญชีที่สร้างเมื่อ 7 ต.ค. 2569 ใช้ชื่อ `branch_ubon` `branch_udon` `branch_khonkaen` `branch_rayong` ต้องการให้เป็น `wh_ubon` `wh_udon` `wh_khonkaen` `wh_rayong` ตามนี้

```powershell
# 1) สร้าง wh_* ของสาขานำร่อง (บัญชี branch_* เดิมยังใช้งานได้)
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx --yes --replace-pilot
# 2) สร้างข้อความแจก แล้วส่งให้สาขานำร่อง
py -3.12 scripts\branch_handout.py --list D:\onboarding\accounts_result.csv --out D:\onboarding\handout
# 3) หลังสาขาเข้าใช้ชื่อใหม่ได้แล้ว รันคำสั่งในข้อ 1 ซ้ำ ระบบจะปิดบัญชี branch_* เดิม (ปิดการใช้งาน ไม่ลบ)
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx --yes --replace-pilot
```

- `--replace-pilot` ใช้ได้เฉพาะพร้อม `--yes` และมีผลกับสาขานำร่อง 4 แห่งเท่านั้น หากไม่ใส่ จะไม่มีการสร้างบัญชีที่สองและไม่มีการปิดบัญชีใด
- การปิดบัญชีเดิมทำผ่านหน้าผู้ใช้ของระบบ (ตั้งค่า → ผู้ใช้งาน เปลี่ยนสถานะเป็นปิดใช้งาน) หากต้องการเปิดกลับ ทำได้ที่หน้าเดียวกัน

### 4. Sales Support ตั้งวันส่งของแต่ละสาขา

ที่ วัตถุดิบและใบสั่งซื้อ → ตั้งค่า → รอบส่งของสาขา มีการ์ด “ตั้งวันส่งหลายสาขาจากไฟล์”

1. กด “ดาวน์โหลดแม่แบบ” ได้ไฟล์ที่มีทุกสาขาที่เปิดใช้งาน พร้อมวันส่งปัจจุบันของรอบ 1 · รอบ 2 · แซลมอนสด (ชื่อวันภาษาไทย เลือกจากรายการได้) และแผ่นที่สองแสดงวันส่งคู่กับวันตัดรอบ
2. แก้ไขวันส่งของสาขาที่ต่างจากค่าเริ่มต้น (รอบ 1 ส่งวันพุธ · รอบ 2 ส่งวันเสาร์ · แซลมอนสดส่งวันจันทร์) เซลล์ที่เว้นว่างหมายถึงไม่เปลี่ยน ไม่ต้องกรอกเวลาตัดรอบ ระบบคำนวณให้: ส่งใบสั่งซื้อก่อน 13:15 น. สองวันก่อนวันส่ง (รอบส่งวันอังคาร ตัดรอบวันเสาร์ 13:15 น.)
3. เลือกไฟล์ที่แก้ไขแล้วกลับเข้ามา ระบบแสดงตัวอย่างโดยยังไม่บันทึก: รายการที่เปลี่ยนไฮไลต์พร้อมวันตัดรอบใหม่ และรายการที่ผิด (ไม่พบสาขา ชื่อวันไม่ถูกต้อง สาขาซ้ำ) แสดงเป็นรายการให้แก้ไข
4. หากไม่มีรายการผิด กด “บันทึก N สาขา” (ครั้งแรกของเบราว์เซอร์ระบบจะขอ Owner Write-Token ตามปกติ) ระบบบันทึกเฉพาะรอบที่เปลี่ยน พร้อมบันทึกประวัติการแก้ไข ไฟล์ที่มีรายการผิดบันทึกไม่ได้ ต้องแก้ไขไฟล์แล้วเลือกใหม่

การตั้งวันส่งมีผลตั้งแต่รอบถัดไป ควรทำให้เสร็จก่อนสาขาเริ่มใช้งานจริง

### 5. สาขาตรวจนับสิ้นเดือนครั้งแรก (ต้นงวด) แล้วจึงเริ่มตัดเบิกรายวัน

ระบบคำนวณ “คงเหลือตามระบบ” จากผลตรวจนับสิ้นเดือนล่าสุด บวกสินค้าที่รับเข้า ลบใบตัดเบิกที่ยืนยันแล้ว ดังนั้นสาขาที่ยังไม่มีผลตรวจนับจะไม่มีฐานคงเหลือ (ยอดแนะนำสั่งจะอิงยอดพยากรณ์อย่างเดียว ไม่หักคงเหลือ)

1. สาขาตรวจนับที่ สาขาของฉัน → ตรวจนับสิ้นเดือน ทีละโซน แล้วกด “ส่งผลตรวจนับ” ครั้งแรกระบบบันทึกเป็น **ต้นงวด** และครั้งต่อไปเป็น **ปลายงวด** ที่ใช้เป็นต้นงวดของเดือนถัดไปโดยอัตโนมัติ ปกติตรวจนับวันที่ 1 ของเดือน (หรือภายใน 2 วัน) หากเริ่มใช้งานกลางเดือนให้ตรวจนับครั้งแรกทันทีที่เริ่ม
2. หลังส่งผลตรวจนับแล้ว สาขาทำงานประจำวันตามลำดับ **ตัดเบิก** (ยืนยันใบตัดเบิกของวัน) → **สั่งสินค้า** (ส่งก่อน 13:15 น. สองวันก่อนวันส่ง) → **รับสินค้า** (แจ้งเคลมในฟอร์มเดียวกันเมื่อรับไม่ครบ)
3. ส่งใบสั่งซื้อได้เมื่อยืนยันใบตัดเบิกของวันนี้แล้วเท่านั้น

### 6. สิ่งที่ต้องดูในหน้างานสัปดาห์แรก

หน้า วัตถุดิบและใบสั่งซื้อ → หน้างาน (เจ้าของและฝ่ายบริหาร) แสดงงานค้างของทุกสาขา

| ดูอะไร | อยู่ที่ไหน | ความหมายของสัญญาณ |
|---|---|---|
| สาขาที่เข้าสู่ระบบครั้งแรกแล้วหรือยัง | ตั้งค่า → การใช้งานจริง (สถานะ “ยังไม่เคยเข้าใช้ (รหัสเริ่มต้น)” และเวลาเข้าสู่ระบบล่าสุด) | สาขาที่ยังไม่เข้าใช้งานภายใน 1–2 วัน ให้ติดตามทางผู้รับที่จดไว้ใน README |
| สาขาที่ยังไม่ตรวจนับต้นงวด | ปิดงวดเดือน → ขั้นตอน “ผลตรวจนับต้นงวด” (แสดงรายสาขา) | ไม่มีฐานคงเหลือ ยอดแนะนำสั่งยังไม่หักคงเหลือ |
| ใบตัดเบิกที่ยังไม่ยืนยัน | หน้างาน → “ติดตามสาขาที่ยังไม่ยืนยันใบตัดเบิกของเมื่อวาน” · ใบสั่งซื้อ → ใบตัดเบิกสาขา | สาขาที่ส่งใบสั่งซื้อไม่ได้เพราะยังไม่ยืนยันใบตัดเบิก มักเป็นสาขาที่ยังไม่คุ้นเคยกับขั้นตอน |
| ใบสั่งซื้อที่เลยเวลาตัดรอบ | ใบสั่งซื้อ → คิวใบสั่งซื้อ (ป้าย “ส่งล่าช้า (ค่าปรับ)”) | ค่าปรับล่าช้าเป็นของคลังสินค้าภายนอก ตรวจสาขาที่ล่าช้าซ้ำ และตรวจว่าวันส่งในปฏิทินตรงกับที่ตกลงไว้ |
| ใบสั่งซื้อที่คลังยังไม่ระบุยอดส่งจริง | หน้างาน → “ระบุยอดส่งจริงของใบสั่งซื้อที่สาขาส่งมา” | เป้าหมายคือ 14:00 ของวันตัดรอบ |
| ความเร็วของระบบช่วงตัดรอบ | ช่วงก่อน 13:15 น. และหลัง 14:00 น. ของวันตัดรอบ | ผลทดสอบ (`docs/LOAD_TEST_30_BRANCHES.md`) แสดงว่าสาขาที่กดส่งพร้อมกันตอบช้าลงเป็นหลักวินาที แต่ไม่ล้มเหลว หากสาขาแจ้งว่าช้าให้บอกให้กดส่งก่อนเวลาตัดรอบ ไม่รอจนนาทีสุดท้าย |
| รหัสผ่านที่สาขาลืมหรือเข้าสู่ระบบไม่ได้ | แจ้งจากสาขา | Management รีเซ็ตเป็นรหัสเริ่มต้นได้ที่ ตั้งค่า → ผู้ใช้งาน แล้วสร้างข้อความใหม่ด้วย `--include-existing` |

เมื่อผ่านสัปดาห์แรก ให้ดูตัวชี้วัดของสาขานำร่องใน หน้างาน → สาขานำร่อง 4 สาขา ตามเกณฑ์ใน `docs/pilot/pilot_plan.html` (ใบตัดเบิกครบทุกวัน ไม่น้อยกว่า 95% · ยืนยันภายในวัน ไม่น้อยกว่า 90%)
