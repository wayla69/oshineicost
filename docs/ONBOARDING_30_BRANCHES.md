# เริ่มใช้งานระบบ “วัตถุดิบและใบสั่งซื้อ” กับ 30 สาขา

เอกสารสำหรับเจ้าของ: ลำดับงานที่ต้องทำตั้งแต่สร้างบัญชีสาขา (`wh_*`) และบัญชีเจ้าของสาขา (`own_*`) จนถึงสัปดาห์แรกของการใช้งานจริง (PR-I, PR-L, PR-M6)
สคริปต์ทั้งหมดอยู่ในโฟลเดอร์ `scripts\` ของโปรเจกต์ รันด้วย `py -3.12` จาก `C:\Users\ASUS\Oshinei`

## หลักการ

- ตำแหน่งของหน้าในแอปเขียนเป็น `แผนก → หน้า` เช่น ประสานงานขาย → รอบส่งของสาขา: ที่หน้าแรกแตะไอคอนแผนก แล้วเลือกหน้า (หรือแตะ ค้นหา กด / หรือ Ctrl + K) บนโทรศัพท์แตะไอคอนแผนกที่หน้าแรก แล้วเลือกหน้า ส่วน ตั้งค่า และ คู่มือการใช้งาน อยู่ส่วนล่างของแถบไอคอนด้านซ้าย (โทรศัพท์: ฉัน)
- สคริปต์ **ไม่ส่งข้อความเอง** และ **ไม่แสดงรหัสผ่านบนหน้าจอ** รหัสผ่านเริ่มต้นอยู่เฉพาะในไฟล์ข้อความและบัตรที่สร้างขึ้น
- ไฟล์ที่สร้างอยู่นอกโปรเจกต์ (ตัวอย่างในเอกสารนี้ใช้ `D:\onboarding`) ห้ามนำขึ้น GitHub และให้ลบโฟลเดอร์ที่มีรหัสผ่านเมื่อแจกเสร็จ
- ทุกสาขาใช้ไฟล์รายชื่อไฟล์เดียวกันในทุกขั้นตอน: คอลัมน์ `สาขา` · `ตัวย่อ` · `ชื่อผู้ใช้` (เว้นว่างไว้ กรอกเฉพาะกรณีพิเศษ) · `LINE/ผู้รับ` (ไม่บังคับ)
- ชื่อผู้ใช้ของสาขาคือ `wh_<ตัวย่อ>` (ตัวพิมพ์เล็ก เช่น ตัวย่อ `udon` = `wh_udon`) ตัวย่อใช้ได้เฉพาะ a-z 0-9 ยาว 2–12 ตัวอักษรและห้ามซ้ำกัน สาขาที่ไม่มีตัวย่อและไม่ระบุชื่อผู้ใช้ระบบตั้งเป็น `wh_<รหัสสาขา>` (ไม่แนะนำ) สาขานำร่อง 5 แห่งมีตัวย่อในตัว (`chiangmai` `ubon` `udon` `korat` `surin`) และสาขาที่มีบัญชีสาขาอยู่แล้วจะไม่ถูกสร้างบัญชีที่สอง ยกเว้นการเปลี่ยนบัญชีนำร่องตามหัวข้อ “เปลี่ยนบัญชีสาขานำร่องเป็น wh_*” ด้านล่าง

## ขั้นตอน

### 1. สร้างไฟล์รายชื่อ 30 สาขา

```powershell
py -3.12 scripts\branch_handout.py --template --out D:\onboarding
```

ได้ไฟล์ `D:\onboarding\branch_list_template.xlsx` ที่มีสาขานำร่อง 5 แถวพร้อมตัวย่อเป็นตัวอย่าง ให้เปิดแล้วกรอกครบ 30 สาขา (ชื่อสาขาและตัวย่อ) แล้วบันทึกเป็น `D:\onboarding\branches.xlsx`

- ชื่อสาขาต้องตรงกับที่ระบบแสดง (ดูได้จากตาราง ประสานงานขาย → รอบส่งของสาขา หรือจากไฟล์แม่แบบวันส่งในขั้นตอนที่ 4)
- ตัวย่อสาขาใช้ a-z 0-9 ยาว 2–12 ตัวอักษร ระบบแปลงเป็นตัวพิมพ์เล็กและตรวจว่าไม่ซ้ำกัน
- ชื่อผู้ใช้ใช้ได้เฉพาะ a-z 0-9 `_` `.` `-` ยาว 3–40 ตัวอักษร ให้เว้นว่างไว้ ระบบตั้งเป็น `wh_<ตัวย่อ>` ให้เอง
- ช่อง `LINE/ผู้รับ` ใช้จดว่าจะส่งข้อความให้ใคร (กลุ่ม LINE ของสาขา หรือผู้จัดการสาขา) ระบบพิมพ์ไว้ใน README ของชุดข้อความ
- ห้ามใส่รหัสผ่านในไฟล์นี้
- จะแบ่งเป็นหลายไฟล์เพื่อทยอยเปิดทีละรุ่นก็ได้ สคริปต์ทุกตัวรับไฟล์รายชื่อใดก็ได้

### 2. สร้างบัญชีสาขา (ดูแผนก่อน แล้วจึงสร้างจริง)

สคริปต์ใช้บัญชีผู้บริหารเข้าสู่ระบบ เพราะการสร้างผู้ใช้เป็นสิทธิ์ของผู้บริหาร (ไม่ใช่รหัสปลดล็อก) บัญชีนี้ต้องเปลี่ยนรหัสผ่านเริ่มต้นแล้ว สคริปต์ถามรหัสผ่านโดยไม่แสดงตัวอักษร หรืออ่านจากตัวแปร `OSHINEI_ADMIN_PASSWORD` หากกำหนดไว้ ชื่อบัญชีเริ่มต้นคือ `management1` (เปลี่ยนด้วย `--admin-user`)

```powershell
# แผนเท่านั้น ไม่สร้างบัญชี (ค่าเริ่มต้น)
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx

# ตรวจตารางสรุปแล้วจึงสร้างจริง
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx --yes
```

สิ่งที่สคริปต์ทำกับแต่ละแถว

1. ตรวจชื่อสาขากับรายชื่อสาขาที่เปิดใช้งานในระบบ (ไม่พบ = แถวนั้นไม่สำเร็จ)
2. ข้ามแถวที่มีบัญชีอยู่แล้ว หรือสาขาที่มีบัญชีสาขาอยู่แล้ว (รายงานเป็น “มีอยู่แล้ว”)
3. สร้างบัญชีบทบาท “สาขา” ผูกกับสาขานั้น โดยไม่ส่งรหัสผ่าน ระบบจึงใช้รหัสผ่านเริ่มต้นและบังคับให้ตั้งรหัสผ่านใหม่เมื่อเข้าใช้ครั้งแรก

เมื่อใช้ `--yes` สคริปต์เขียน `D:\onboarding\accounts_result.csv` (สาขา · ชื่อผู้ใช้ · ผู้รับ · ผล · หมายเหตุ) การรันซ้ำปลอดภัย: บัญชีที่สร้างไปแล้วไม่ถูกสร้างซ้ำและยังคงสถานะ “สร้างแล้ว” ในไฟล์ผลลัพธ์ หากมีแถว “ไม่สำเร็จ” ให้แก้ไขไฟล์รายชื่อแล้วรันซ้ำ

#### เปลี่ยนบัญชีนำร่องเดิม 4 บัญชีเป็น wh_*

บัญชีนำร่อง 4 บัญชีที่สร้างเมื่อ 7 ต.ค. 2569 ใช้ชื่อ `branch_ubon` `branch_udon` `branch_khonkaen` `branch_rayong` ต้องการให้เป็น `wh_ubon` `wh_udon` `wh_khonkaen` `wh_rayong` ตามนี้ (สาขานำร่องชุดปัจจุบันคือ เชียงใหม่ · อุบลราชธานี · อุดรธานี · โคราช1 · สุรินทร์ ส่วนขอนแก่นและระยองไม่ได้อยู่ในชุดนำร่องแล้ว แต่บัญชี branch_khonkaen และ branch_rayong ยังถูกปิดด้วยคำสั่งนี้ได้)

```powershell
# 1) สร้าง wh_* ของสาขาที่มีบัญชีเดิม (บัญชี branch_* เดิมยังใช้งานได้)
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx --yes --replace-pilot
# 2) สร้างข้อความแจก แล้วส่งให้สาขา
py -3.12 scripts\branch_handout.py --list D:\onboarding\accounts_result.csv --out D:\onboarding\handout
# 3) หลังสาขาเข้าใช้ชื่อใหม่ได้แล้ว รันคำสั่งในข้อ 1 ซ้ำ ระบบปิดบัญชี branch_* เดิม (ปิดการใช้งาน ไม่ลบ)
py -3.12 scripts\branch_accounts.py --list D:\onboarding\branches.xlsx --yes --replace-pilot
```

- `--replace-pilot` ใช้ได้เฉพาะพร้อม `--yes` และมีผลกับบัญชีเดิม 4 บัญชี (`branch_ubon` `branch_udon` `branch_khonkaen` `branch_rayong`) เท่านั้น หากไม่ใส่ จะไม่มีการสร้างบัญชีที่สองและไม่มีการปิดบัญชีใด
- การปิดบัญชีเดิมทำผ่านหน้าผู้ใช้ของระบบ (ตั้งค่า → ผู้ใช้งาน เปลี่ยนสถานะเป็นปิดใช้งาน) หากต้องการเปิดกลับ ทำได้ที่หน้าเดียวกัน

### 3. สร้างข้อความและบัตรแจกสาขา

```powershell
py -3.12 scripts\branch_handout.py --list D:\onboarding\accounts_result.csv --out D:\onboarding\handout
```

ได้ไฟล์ `<ชื่อผู้ใช้>.txt` ต่อสาขา (ข้อความพร้อมส่ง) · `cards.html` (บัตรพิมพ์ A4 แนวตั้ง หน้าละ 4 ใบ เปิดในเบราว์เซอร์แล้วสั่งพิมพ์ ตัดตามเส้นประ) · `README.txt` (รายการไฟล์ สาขา และผู้รับ)

- ส่งไฟล์ข้อความให้เฉพาะสาขานั้นทางช่องทางที่สาขาใช้อยู่ (LINE) ไม่ส่งต่อในกลุ่มที่มีคนนอกสาขา
- สาขาที่มีบัญชีอยู่แล้ว (อาจเปลี่ยนรหัสผ่านไปแล้ว) ถูกข้าม หากต้องการสร้างข้อความให้ด้วยให้เติม `--include-existing`
- หากไม่ผ่านขั้นตอนที่ 2 แต่ต้องการสร้างข้อความจากไฟล์รายชื่อโดยตรง ให้ใช้ `--list D:\onboarding\branches.xlsx --db <สำเนาฐานข้อมูล>` (ระบบใช้ `--db` หารหัสสาขาสำหรับแถวที่เว้นชื่อผู้ใช้) หรือ `--all --db <สำเนาฐานข้อมูล>` สำหรับทุกสาขาที่เปิดใช้งาน
- ลบโฟลเดอร์ `D:\onboarding\handout` เมื่อแจกครบ

### 4. ประสานงานขายตั้งวันส่งและโซนจัดเก็บ

ที่ ประสานงานขาย → รอบส่งของสาขา มีการ์ด “ไฟล์รอบส่งของสาขา · ตั้งวันส่งหลายสาขาพร้อมกัน”

1. กด “ดาวน์โหลดแม่แบบรอบส่งของสาขา (Excel)” ได้ไฟล์ “แม่แบบ_รอบส่งของสาขา.xlsx” ที่มีทุกสาขาที่เปิดใช้งาน พร้อมวันส่งปัจจุบันของรอบ 1 · รอบ 2 · แซลมอนสด (ชื่อวันภาษาไทย เลือกจากรายการได้) และแผ่นที่สองแสดงวันส่งคู่กับวันตัดรอบ
2. แก้ไขวันส่งของสาขาที่ต่างจากค่าเริ่มต้น (รอบ 1 ส่งวันพุธ · รอบ 2 ส่งวันเสาร์ · แซลมอนสดส่งวันจันทร์) เซลล์ที่เว้นว่างหมายถึงไม่เปลี่ยน ไม่ต้องกรอกเวลาตัดรอบ ระบบคำนวณให้: ส่งใบสั่งซื้อก่อน 13:15 น. สองวันก่อนวันส่ง (รอบส่งวันอังคาร ตัดรอบวันเสาร์ 13:15 น.)
3. กด “นำเข้าไฟล์รอบส่งของสาขา” แล้วเลือกไฟล์ที่แก้ไขแล้วกลับเข้ามา ระบบแสดงตัวอย่างโดยยังไม่บันทึก: รายการที่เปลี่ยนไฮไลต์พร้อมวันตัดรอบใหม่ และรายการที่ผิด (ไม่พบสาขา ชื่อวันไม่ถูกต้อง สาขาซ้ำ) แสดงเป็นรายการให้แก้ไข
4. หากไม่มีรายการผิด กด “บันทึก N สาขา” (ครั้งแรกบนเครื่องใหม่ ปุ่มที่ปลายขวาของแถวตำแหน่งหน้าเป็น “อ่านอย่างเดียว” ให้ผู้ดูแลระบบกรอกรหัสปลดล็อกครั้งเดียว) ระบบบันทึกเฉพาะรอบที่เปลี่ยน พร้อมบันทึกประวัติการแก้ไข ไฟล์ที่มีรายการผิดบันทึกไม่ได้ ต้องแก้ไขไฟล์แล้วเลือกใหม่

การตั้งวันส่งมีผลตั้งแต่รอบถัดไป ควรทำให้เสร็จก่อนสาขาเริ่มใช้งานจริง

โซนจัดเก็บ: ที่ ประสานงานขาย → โซนจัดเก็บ ตรวจรายการโซนที่สาขาใช้แบ่งนับของและใบตัดเบิก (ค่าเริ่มต้น แช่แข็ง · แช่เย็น · ของแห้ง · บาร์น้ำ · อื่น ๆ) เพิ่ม เปลี่ยนชื่อ หรือเรียงลำดับก่อนสาขาเริ่มนับ รายละเอียดอยู่ใน `salessupport_guide.html`

### 5. สาขานับของครั้งแรก แล้วจึงเริ่มตัดเบิกรายวัน

ระบบคำนวณ “ของที่ควรเหลือ” จากผลนับล่าสุด บวกของที่รับเข้า ลบใบตัดเบิกที่ส่งแล้ว วันที่ยังไม่ส่งใบตัดเบิก ระบบหักตามค่าเฉลี่ยใบตัดเบิกของสาขาในวันเดียวกันของสัปดาห์ ย้อนหลัง 8 สัปดาห์ (ป้าย “ประมาณจากใบตัดเบิกเฉลี่ย N วัน”) สาขาที่ยังไม่มีผลนับจะไม่มีฐานของที่ควรเหลือ

จำนวนที่ควรสั่งต้องมีใบตัดเบิกที่ส่งแล้วอย่างน้อย 14 วันใน 8 สัปดาห์ล่าสุด ยังไม่ครบหน้าจอขึ้น “ใบตัดเบิกยังไม่พอ (N/14 วัน) · กรอกยอดสั่งเอง” สาขานำร่องเริ่มส่งใบตัดเบิก 1 พ.ย. 2569 จึงกรอกยอดสั่งเองประมาณ 2 สัปดาห์แรก จำนวนที่ควรสั่งเริ่มขึ้น ~15 พ.ย. เมื่อมีสาขาของบริษัทครบ 14 วันตั้งแต่ 2 สาขา สาขาที่ยังไม่ครบใช้ค่ากลางของสาขาเหล่านั้นต่อยอดขาย ฿100,000 ตามยอดขายที่คาด

1. สาขานับที่ สาขา → นับของสิ้นเดือน (บนโทรศัพท์ เป็นปุ่มใหญ่ในหน้าแรก หรือแถวงานนับของใน “ต้องทำวันนี้”) ทีละโซน ต้องนับให้ครบทุกรายการ (ใส่ 0 ถ้าไม่มีของ ช่องว่างถือว่ายังไม่ได้นับ) ระบบไม่รับผลที่ยังมีรายการไม่ได้นับ ปิดเดือนต้องนับ 100% ทุกเดือน แล้วกด “ส่งผลนับ” ครั้งแรกระบบบันทึกเป็น **นับครั้งแรก** และครั้งต่อไปเป็น **นับสิ้นเดือน** ที่ใช้เป็นการนับครั้งแรกของเดือนถัดไปโดยอัตโนมัติ ปกตินับวันที่ 1 ของเดือน (หรือภายใน 2 วัน) สาขานำร่อง 5 สาขา (เชียงใหม่ · อุบลราชธานี · อุดรธานี · โคราช1 · สุรินทร์) นับครั้งแรกวันที่ 1 พ.ย. 2569 หากเริ่มใช้งานกลางเดือนให้นับครั้งแรกทันทีที่เริ่ม
2. หลังส่งผลนับแล้ว สาขาทำงานประจำวันตามลำดับ **ตัดเบิก** (ส่งใบตัดเบิกของวัน) → **สั่งของ** (กรอกหรือตรวจจำนวนแล้วกด “ส่งใบสั่งซื้อ” ก่อน 13:15 น. สองวันก่อนวันส่ง) → **รับของ** (ตอบ “รับครบ” หรือ “มีรายการไม่ครบ” แจ้งของขาด/เสียในฟอร์มเดียวกันเมื่อรับไม่ครบ) ตามแถบล่าง 5 ปุ่มของโทรศัพท์ (หน้าแรก · ตัดเบิก · สั่งของ · รับของ · ฉัน)
3. ส่งใบสั่งซื้อได้เมื่อส่งใบตัดเบิกของวันนี้แล้วเท่านั้น
4. ตัดเบิก สั่งของ และรับของ กรอกในไฟล์ Excel ได้ด้วย (ดาวน์โหลดแบบฟอร์ม → กรอก → นำเข้าไฟล์ ตัดเบิกครั้งละไม่เกิน 7 วัน) ปลาทั้งตัว (แซลมอนสด ชั่งน้ำหนักและนับตัว) กรอกในแอปเท่านั้น

### 6. สิ่งที่ต้องดูในหน้างานสัปดาห์แรก

หน้างาน (เจ้าของและฝ่ายบริหาร: หน้าแรก → งานของฉันวันนี้ → ดูทั้งหมด) แสดงงานค้างของทุกสาขา งานที่เสร็จแล้วซ่อนไว้ ตัวกรองเริ่มที่ “ยังไม่เสร็จ”

| ดูอะไร | อยู่ที่ไหน | ความหมายของสัญญาณ |
|---|---|---|
| สาขาที่เข้าสู่ระบบครั้งแรกแล้วหรือยัง | ตั้งค่า → การใช้งานจริง (สถานะ “ยังไม่เคยเข้าใช้ (รหัสเริ่มต้น)” และเวลาเข้าสู่ระบบล่าสุด) | สาขาที่ยังไม่เข้าใช้งานภายใน 1–2 วัน ให้ติดตามทางผู้รับที่จดไว้ใน README |
| สาขาที่ยังไม่นับครั้งแรก | หน้างาน → บล็อก ปิดงวดเดือน ขั้น “ใบตรวจนับต้นงวดและปลายงวด” (แสดงรายสาขา) | ไม่มีฐานของที่ควรเหลือ จำนวนที่ควรสั่งยังไม่หักของที่ควรเหลือ |
| ใบตัดเบิกที่ยังไม่ส่ง | หน้างาน → “ติดตามสาขาที่ยังไม่ส่งใบตัดเบิกของเมื่อวาน” · ประสานงานขาย → ใบตัดเบิกสาขา | สาขาที่ส่งใบสั่งซื้อไม่ได้เพราะยังไม่ส่งใบตัดเบิก มักเป็นสาขาที่ยังไม่คุ้นเคยกับขั้นตอน |
| สาขาที่ยังไม่มีจำนวนที่ควรสั่ง | ประสานงานขาย → ยอดแนะนำรายรอบ (คอลัมน์ที่มา) | ถึง ~15 พ.ย. เป็นเรื่องปกติ (ใบตัดเบิก N/14 วัน) หลังจากนั้นดูสาขาที่ส่งใบตัดเบิกไม่ครบ |
| สาขาที่ยังไม่ใช้งานหรือใช้งานน้อย | ปฏิบัติการ → การใช้งานทุกสาขา (7 วันล่าสุด เขียวตั้งแต่ 90% · เหลือง 60–89% · แดงต่ำกว่า 60% หรือไม่มีการใช้งาน) | สาขาที่ต้องตามอยู่บนสุด แตะแถวเพื่อเปิดใบตัดเบิกของสาขานั้น หน้างานของฝ่ายกลางแสดงบรรทัดสรุปของตารางนี้ ท้ายหน้ามีลิงก์ไปความพร้อมและผลนำร่อง |
| การแจ้งเตือนบนมือถือ | ฉัน (แถบล่างของโทรศัพท์) → การ์ด “แจ้งเตือนตอนเช้า” | ผู้ใช้แต่ละเครื่องแตะ “เปิดการแจ้งเตือน” เองครั้งเดียว (iPhone ต้องเพิ่มระบบไปยังหน้าจอโฮมก่อน) ใช้กับบัญชีสาขาที่เปิดใช้งานทุกบัญชี 08:00 งานของวัน · 11:00 เตือนสาขาที่ยังไม่ส่งใบสั่งซื้อก่อนตัดรอบ · 13:15 รายชื่อสาขาที่ส่งไม่ทันถึงประสานงานขาย · Telegram เป็นช่องทางเสริม ยังไม่ได้ตั้งค่า |
| ใบสั่งซื้อที่เลยเวลาตัดรอบ | ประสานงานขาย → คิวใบสั่งซื้อ (ป้าย “ส่งล่าช้า (มีค่าปรับ)”) | ค่าปรับล่าช้าเป็นของคลังสินค้าภายนอก ตรวจสาขาที่ล่าช้าซ้ำ และตรวจว่าวันส่งในปฏิทินตรงกับที่ตกลงไว้ |
| ใบสั่งซื้อที่คลังยังไม่ระบุยอดส่งจริง | หน้างาน → “ระบุยอดส่งจริงของใบสั่งซื้อที่สาขาส่งมา” | เป้าหมายคือ 14:00 ของวันตัดรอบ |
| ความเร็วของระบบช่วงตัดรอบ | ช่วงก่อน 13:15 น. และหลัง 14:00 น. ของวันตัดรอบ | ผลทดสอบ (`docs/LOAD_TEST_30_BRANCHES.md`) แสดงว่าสาขาที่กดส่งพร้อมกันตอบช้าลงเป็นหลักวินาที แต่ไม่ล้มเหลว หากสาขาแจ้งว่าช้าให้บอกให้กดส่งก่อนเวลาตัดรอบ ไม่รอจนนาทีสุดท้าย |
| รหัสผ่านที่สาขาลืมหรือเข้าสู่ระบบไม่ได้ | แจ้งจากสาขา | ผู้บริหารรีเซ็ตเป็นรหัสเริ่มต้นได้ที่ ตั้งค่า → ผู้ใช้งาน แล้วสร้างข้อความใหม่ด้วย `--include-existing` |

เมื่อผ่านสัปดาห์แรก ให้ดูตัวชี้วัดของสาขานำร่องที่ ปฏิบัติการ → การใช้งานทุกสาขา แล้วเปิดลิงก์ความพร้อมและผลนำร่องท้ายหน้า ตามเกณฑ์ใน `docs/pilot/pilot_plan.html` (ใบตัดเบิกครบทุกวัน ไม่น้อยกว่า 95% · ส่งในวันเดียวกัน ไม่น้อยกว่า 90%)

### 7. บัญชีเจ้าของสาขาแฟรนไชส์ (หน้า “ร้านของฉัน”)

เจ้าของสาขาแฟรนไชส์ดูผลการดำเนินงานของสาขาตนเองได้ที่หน้าเดียวคือ “ร้านของฉัน” บนโทรศัพท์ (บทบาท `franchise` สิทธิ์ `franchise.view` ชื่อผู้ใช้ `own_<ตัวย่อ>`) ใช้ตัวย่อเดียวกับบัญชีสาขาในไฟล์รายชื่อ แต่ให้ทำไฟล์รายชื่อเฉพาะสาขาแฟรนไชส์ (บันทึกเป็น `D:\onboarding\owners.xlsx` ใช้คอลัมน์ `สาขา` · `ตัวย่อ` · `LINE/ผู้รับ` ส่วนคอลัมน์ `ชื่อผู้ใช้` ถ้าไม่ขึ้นต้นด้วย `own_` สคริปต์ไม่นำมาใช้)

```powershell
# แผนเท่านั้น
py -3.12 scripts\branch_accounts.py --role franchise --list D:\onboarding\owners.xlsx
# สร้างจริง (ได้ไฟล์ D:\onboarding\owner_accounts_result.csv)
py -3.12 scripts\branch_accounts.py --role franchise --list D:\onboarding\owners.xlsx --yes
# ข้อความและบัตรสำหรับเจ้าของสาขา
py -3.12 scripts\branch_handout.py --role franchise --list D:\onboarding\owner_accounts_result.csv --out D:\onboarding\owner_handout
```

- หนึ่งสาขามีบัญชีเจ้าของสาขาได้หนึ่งบัญชี สคริปต์ไม่สร้างบัญชีที่สองให้สาขาเดิม และไม่ปิดหรือแก้บัญชีสาขา `wh_*`
- บัญชีนี้ดูได้อย่างเดียวและดูได้เฉพาะสาขาของตนเอง: ไม่มีข้อมูลบิลรายใบ สูตร ราคาวัตถุดิบ สาขาอื่น ข้อมูลพนักงานหรือแคชเชียร์ ไฟล์ส่งออกของบัญชี และการตั้งค่า ไม่มีช่องเลือกสาขาในหน้านี้
- รหัสผ่านเริ่มต้นและขั้นตอนการเปลี่ยนรหัสผ่านเหมือนบัญชีสาขา ข้อความที่ได้อธิบายสิ่งที่หน้า “ร้านของฉัน” แสดงและวิธีเข้าสู่ระบบ
- เป้าของกำไรขั้นต้นตามกติกาเป้าของระบบ (`backend\targets.py`) คือกำไรขั้นต้นของสาขาเองในเดือนเดียวกันของปีก่อน (หน้าจอแสดง “เป้า = เดือนเดียวกันปีก่อน”) และใช้เดือนก่อนแทนเฉพาะเมื่อปีก่อนไม่มีข้อมูล (แสดง “เป้า = เดือนก่อน”) เพราะระบบยังไม่มีช่องกรอกเป้ากำไรขั้นต้น เกณฑ์ที่ใช้สรุป “ดี / ควรดู / ต้องแก้” อยู่ที่หัวไฟล์ `backend\routers\franchise.py`
- คู่มือเจ้าของสาขา `docs\pilot\owner_guide.html` อธิบายความหมายของแต่ละการ์ดและเกณฑ์ของสรุป ดี / ควรดู / ต้องแก้ ข้อความแจกและบัตรมีที่อยู่คู่มือนี้
- ทดสอบ: `backend\test_franchise_role.py` · `scripts\verify_pinned.py`
