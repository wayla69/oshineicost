# แผนขึ้นระบบแบบ "สต๊อกก่อน สูตรทีหลัง" (Stock-first) — อนุมัติ 2026-10-22

> ตัวเลขช่วงข้อมูล: 8 สัปดาห์ (แผนนี้เขียน 4 และ 6 สัปดาห์ไว้ก่อน H8) · คำของสาขา: [BRANCH_WORDS.md](BRANCH_WORDS.md) (สั่งของ รับของ นับของ ส่วนต่าง ฯลฯ แทนคำในแผน) · สถานะปัจจุบัน: [STOCK_FIRST_GOLIVE.md](STOCK_FIRST_GOLIVE.md)

**หลักการ:** ขึ้นระบบบริหารสต๊อก (ตัดเบิก · สั่ง · รับ · เคลม · ตรวจนับ) ก่อน โดย **ปิดส่วนสูตร (BoM) ทั้งหมด** ไว้เป็น Phase 2
- ต้นทุนต่อจาน: ฝ่ายวิเคราะห์นำเข้า **ตารางต้นทุนต่อจานรายเดือน** (price list) แทนการคำนวณจากสูตร
- ยอดแนะนำสั่งสินค้า: พยากรณ์จาก **ใบตัดเบิกที่ยืนยันแล้ว** แทนการคำนวณจากยอดขาย × สูตร
- หน้าจอ/งาน/แจ้งเตือนที่อิงสูตร: ซ่อนด้วย "โหมดระบบ" (ไม่ลบโค้ด เปิดกลับได้ใน Phase 2)

## 1. สิ่งที่มีอยู่แล้วและใช้ได้ทันที (ไม่ต้องแก้)

| งาน | หน้า | หมายเหตุ |
|---|---|---|
| ตัดเบิกรายวัน (เบิกใช้ + ของเสีย) | สาขา → ตัดเบิก | ล็อกเมื่อยืนยัน ประสานงานขายเปิดแก้ไข |
| สั่งสินค้า ตัดรอบ 13:15 สองวันก่อนส่ง | สาขา → สั่งสินค้า | ต้องยืนยันใบตัดเบิกวันนี้ก่อนส่ง |
| คิวใบสั่งซื้อ ยอดส่งจริง คีย์บัญชี | ประสานงานขาย / คลัง → คิวใบสั่งซื้อ | |
| รับสินค้า + เคลมในฟอร์มเดียว / เคลมภายหลัง | สาขา → รับสินค้า · ประสานงานขาย → เคลมสินค้า | |
| คงเหลือตามระบบ = นับสิ้นเดือน + รับ − ตัดเบิก | สาขา → สั่งสินค้า (คอลัมน์คงเหลือ) | |
| ตรวจนับสิ้นเดือน · นับรอบ (class A) | สาขา → ตรวจนับสิ้นเดือน | |
| กระทบยอด ระบบ เทียบ นับจริง | สาขา → ผลต่าง → สิ้นเดือน · บัญชี → ใบสรุปตัดเบิก | ไม่ใช้สูตร |
| ราคาวัตถุดิบรายเดือน (ไฟล์ราคาจากประสานงานขาย) | ฝ่ายวิเคราะห์ → ไฟล์ราคา / ราคารายเดือน | ใช้ตีมูลค่าสต๊อกและใบตัดเบิก ต้องคงไว้ |
| ทะเบียนวัตถุดิบ หน่วย โซน รอบส่ง ปฏิทินเทศกาล | ประสานงานขาย / ฝ่ายวิเคราะห์ | ต้องคงไว้ |

## 2. ส่วนที่อิงสูตร (ต้องซ่อนหรือเปลี่ยนแหล่งข้อมูล)

| จุด | วันนี้ใช้สูตรอย่างไร | ในโหมดสต๊อก |
|---|---|---|
| ต้นทุนต่อจานในทุกรายงาน (GP, P&L, เมนู, ต้นทุนต่อหัว) | `rules.dated_cost_sql` อ่าน `bc_sku_cost_month` ที่สร้างจากเวอร์ชันสูตรที่ประกาศใช้ | อ่านตาราง **ต้นทุนต่อจานรายเดือน** ที่ฝ่ายวิเคราะห์นำเข้าก่อน (PR-S2) |
| ยอดแนะนำสั่งสินค้า | `forecast.usage_history` = ยอดขายรายวัน × สูตร | ใบตัดเบิกที่ยืนยันแล้ว (เบิกใช้ + ของเสีย) รายวัน (PR-S3) |
| คงเหลือตามระบบ วันที่ไม่มีใบตัดเบิก | ประมาณจากยอดขาย × สูตร (`stock.estimated_use`) | ประมาณจากค่าเฉลี่ยใบตัดเบิกของสาขา 4 สัปดาห์ แยกวันในสัปดาห์ (PR-S3) |
| ผลต่างตัดเบิกรายวัน (เบิก เทียบ BoM) | `issue_reports.daily` | เปลี่ยนตัวเทียบเป็น ค่าเฉลี่ยของสาขาเอง 4 สัปดาห์ และ ค่ากลางทุกสาขาต่อยอดขาย ฿100,000 (PR-S4) |
| ผลต่างการใช้รายงวด (ใช้จริง เทียบสูตร) | `variance.period` | ซ่อนแท็บ "รายงวด" คงแท็บ "สิ้นเดือน" (ระบบ เทียบ นับจริง) |
| งานประจำเดือนสูตร: ร่าง → ส่งตรวจ → ตรวจ → ประกาศใช้ → รับทราบ | `todo._month_items`, หน้า rec/prep/rel, รับทราบสูตร | ซ่อนทั้งหมด (PR-S1) |
| ตรวจสูตรด้วยยอดซื้อ · ความพร้อมและรหัสสูตรเดิม · ต้นทุนตามสูตร · BoM รายสาขา · วิเคราะห์วัตถุดิบ | หน้าฝ่ายวิเคราะห์ | ซ่อน (PR-S1) |
| แผนก "ครัว" | มีแต่หน้าสูตร | ซ่อนแผนกจนถึง Phase 2 (ดูข้อตัดสินใจ O3) |
| แจ้งเตือน "เบิกเกินสูตรติดต่อกัน" / "เบิกต่ำกว่าสูตร" | `issue_anomaly`, `blank_class_a` | เปลี่ยนตัวเทียบตาม PR-S4 |
| ตัวชี้วัดนำร่อง MAPE | `forecast.backtest` | ใช้แหล่งข้อมูลใบตัดเบิกโดยอัตโนมัติ |

## 3. งานที่ต้องทำ — 4 PR ตามลำดับ

### PR-S1 โหมดระบบ (เล็ก · 1 วัน)
- ค่าตั้ง `app_settings.bc_mode` = `stock` | `full` (ค่าตั้งต้น `stock`) ใน `bom_center/close_settings.py` รูปแบบเดียวกับ `cycle_counts`; `GET /api/bom-center/mode` (ทุกบทบาท) · `POST` (ผู้บริหาร, ต้องปลดล็อก) ที่ ตั้งค่า
- หน้าในทะเบียน `DEPARTMENTS` / `SUPPLY_CHIPS` / `PAGE_KEYWORDS` ติดธง `bom: true` ที่ทุกรายการในข้อ 2 → ตัวกรอง `deptVisible`/`deptPageAllowed` ซ่อนเมื่อโหมด `stock`; เมนูค้นหา ป้ายจำนวน (`nav_badges`) และ `todo.build` ข้ามรายการสูตรทั้งหมด; `check-departments.js` ตรวจว่าทุกหน้าที่ติดธงมีจริง
- ไม่ลบหน้า ไม่ลบตาราง สลับโหมดกลับได้ทันที

### PR-S2 ต้นทุนต่อจานรายเดือน (2–3 วัน)
- ตารางใหม่ `bc_sku_cost_list(sku_id, month, unit_cost, note, imported_by, imported_at, PK(sku_id, month))` (คำนำหน้า `bc_` → อยู่รอดการสลับฐานข้อมูล; **ต้องแยกจาก `bc_sku_cost_month` เพราะตารางนั้นถูกล้างและสร้างใหม่จากเวอร์ชันสูตรทุกครั้งที่เริ่มระบบ** `dated.py:82`)
- `rules.dated_cost_sql`: `COALESCE(รายการจาก bc_sku_cost_list เดือนล่าสุด ≤ เดือนของแถว, รายการจาก bc_sku_cost_month …)` — ตารางนำเข้าชนะเวอร์ชันสูตรเสมอ กฎเดือนล่าสุดคงเดิม (เดือนที่ไม่นำเข้าใช้ค่าเดือนก่อนหน้า) และยังไม่แตะเดือนก่อน ก.ย. 2569
- ส่งออกให้เครื่องประมวลผล: `main._bc_sku_cost_month` และ `dated.mirror` ครอบคลุมตารางใหม่ด้วย (ไม่เช่นนั้น menu_fact บนเครื่องซิงก์จะไม่เห็นต้นทุน)
- หน้าใหม่ ฝ่ายวิเคราะห์ → **ต้นทุนต่อจาน** (`bomcenter` pane `dishcost`, module `bom.center`/`bom.prices`):
  - เลือกเดือน → นำเข้า Excel (แม่แบบ: รหัส POS · ชื่อเมนู · ต้นทุนต่อจาน (บาท) · หมายเหตุ; รับไฟล์ `BOM Grand Menu.xlsx` รูปแบบ New Item Code AL/BF + cost ได้ด้วย)
  - ตรวจก่อนบันทึก (dry run) → ตาราง: นำเข้า n รายการ · รหัสไม่พบ n · ต้นทุนเปลี่ยน > 30% จากเดือนก่อน n · **เมนูที่ขายในเดือนนี้แต่ไม่มีต้นทุน n** (คำนวณจาก `sales_sku_daily`)
  - ตารางเดือนปัจจุบัน: รหัส · เมนู · ต้นทุน · เดือนก่อน · เปลี่ยน % · จานที่ขาย · ที่มา (นำเข้า / ยกมาจากเดือน …) · แก้ไขทีละแถวได้ (ต้องปลดล็อก)
  - บันทึก audit ทุกครั้ง ย้อนดูเดือนก่อนได้
- งานในหน้างาน (`todo`): `dish_cost_month` (ฝ่ายวิเคราะห์) "นำเข้าต้นทุนต่อจานเดือน … (เมนูที่ขายแต่ไม่มีต้นทุน n)" — ครบแล้วหายไป
- รายงาน "ความครอบคลุมต้นทุน" ใช้ได้ทันทีกับตารางใหม่ (ผ่าน `dated_cost_sql`)

### PR-S3 ยอดแนะนำจากใบตัดเบิก (3–4 วัน)
- `forecast.usage_history_slips(con, bid, start, end)` → รูปเดียวกับ `usage_history`: `{code: {day: used_base + waste_base}}`, `days` = วันที่มีใบตัดเบิกยืนยัน, `stats.source = "slips"`; แคชแบบเดิม (ล้างเมื่อยืนยัน/เปิดแก้ไขใบตัดเบิก)
- ตัวเลือกแหล่งข้อมูล `forecast.demand_source(con, bid, start, end)`: โหมด `stock` → ใบตัดเบิกเมื่อมี ≥ **14 วันยืนยัน** ในช่วง 6 สัปดาห์; ต่ำกว่านั้น → ตามข้อตัดสินใจ O1; โหมด `full` → สูตร (เดิม)
- `suggest()` / `covers()` / `backtest()` / `per_sales.ratio` / `benchmark_basis` / `reference_basis` เรียกผ่านตัวเลือกนี้ (จุดเดียว) — ค่ากลางทุกสาขาต่อ ฿100,000 จึงมาจากใบตัดเบิกของสาขาอื่นด้วย
- `stock.estimated_use` ในโหมด `stock`: วันที่ไม่มีใบตัดเบิก = ค่าเฉลี่ยวันในสัปดาห์เดียวกันของสาขา 4 สัปดาห์ (ไม่มี → 0 และแจ้ง "ขาดใบตัดเบิก n วัน" เช่นเดิม)
- หน้าสั่งสินค้า: บรรทัดที่มา "**ยอดแนะนำจากใบตัดเบิก 28 วัน (ยืนยัน 26/28 วัน)**" หรือ "ยังไม่มีใบตัดเบิกพอ (7/14 วัน) — ดูข้อ O1"; ชิป "ยอดแนะนำรายรอบ" ของประสานงานขายแสดงที่มาต่อสาขา
- ของเสียรวมอยู่ในความต้องการ (สิ่งที่ต้องเติมคือสิ่งที่ออกจากชั้น) — ไม่ต้องคูณ yield อีก

### PR-S4 รายงานผลต่างแบบไม่ใช้สูตร + เอกสาร (2–3 วัน)
- "ผลต่างตัดเบิกรายวัน": คอลัมน์ "ตามสูตร BoM" → "ปกติของสาขา" (ค่าเฉลี่ยวันในสัปดาห์เดียวกัน 4 สัปดาห์ ปรับตามยอดขายวันนั้น) และ "ค่ากลางทุกสาขาต่อ ฿100,000"; สัญญาณ เบิกเกิน/ต่ำ ติดต่อกัน ≥ 3 วัน ใช้ตัวเทียบใหม่ (เกณฑ์ 20% เดิม)
- `issue_anomaly` / `blank_class_a` / แจ้งเตือนเช้า ใช้ตัวเทียบเดียวกัน
- ผลต่างการใช้รายงวด: ซ่อนแท็บ "รายงวด" ในโหมด `stock`
- เอกสาร: คู่มือ (แผนที่เมนูตามแผนก), SOP WP-SCM-001, คู่มือสาขา/ประสานงานขาย/บัญชี, ชุดฝึกอบรม → ตัดบทสูตรออกเป็นภาคผนวก "Phase 2" และเพิ่มบท "ต้นทุนต่อจานรายเดือน"

## 4. ข้อตัดสินใจ (ผู้บริหารเห็นชอบตามข้อเสนอทั้ง 5 ข้อ 2026-10-22)

| # | เรื่อง | ทางเลือก | ข้อเสนอ |
|---|---|---|---|
| O1 | ยอดแนะนำของสาขาที่ยังมีใบตัดเบิกยืนยัน < 14 วัน | (ก) ไม่แสดงยอดแนะนำ แสดงคงเหลือตามระบบ + ยอดที่สั่งครั้งก่อน ให้สาขากรอกเอง · (ข) ใช้ค่ากลางทุกสาขาต่อ ฿100,000 × ยอดขายที่คาด (กลไกสาขาใหม่ที่มีอยู่) · (ค) ใช้วิธีเดิม (ยอดขาย × สูตรเก่า) ชั่วคราว | **(ก) 7 วันแรก แล้วเป็น (ข) เมื่อมีสาขาใดครบ 14 วัน** — (ค) ขัดกับเหตุผลที่ปิดสูตร |
| O2 | ตารางต้นทุนต่อจาน | ต่อรหัส POS ต่อเดือน เดือนที่ไม่นำเข้าใช้ค่าเดือนก่อน · ฝ่ายวิเคราะห์นำเข้าเอง ไม่มีขั้นประกาศใช้/รับทราบ | ตามนี้ (ลดขั้นตอน) — หากต้องการให้ผู้บริหารรับทราบก่อนมีผล แจ้งได้ |
| O3 | แผนก "ครัว" (innovation) ในโหมดสต๊อก | (ก) ซ่อนแผนกทั้งหมด · (ข) คงหน้า "ทะเบียนวัตถุดิบ" อ่านอย่างเดียว | (ข) |
| O4 | ตัวเทียบผลต่างตัดเบิกรายวันเมื่อไม่มีสูตร | ค่าเฉลี่ยสาขาเอง 4 สัปดาห์ + ค่ากลางทุกสาขาต่อ ฿100,000 เกณฑ์ 20% / 3 วัน | ตามนี้ |
| O5 | เดือนเริ่มใช้ตารางต้นทุนต่อจาน | ย้อนหลังตั้งแต่ ก.ย. 2569 (เดือนเริ่ม Grand Menu) หรือเฉพาะ ต.ค. 2569 เป็นต้นไป | ก.ย. 2569 (ให้ GP/P&L ของ ก.ย.–ต.ค. ใช้ตัวเลขฝ่ายวิเคราะห์ชุดเดียว) |

## 6. Phase 2 (เปิดสูตรกลับ)
สลับ `bc_mode = full` → หน้าสูตร งานประจำเดือน และตัวเทียบตามสูตรกลับมา; ตารางต้นทุนต่อจานที่นำเข้ายังชนะเวอร์ชันสูตรต่อเดือนที่มีการนำเข้า (เปลี่ยนลำดับความสำคัญได้ตอนนั้นด้วยการตัดสินใจครั้งเดียว)

> หมายเหตุ 2026-10-22: ขยายช่วงข้อมูลย้อนหลังจาก 4 และ 6 สัปดาห์ เป็น 8 สัปดาห์ (2026-10-22) ตามมติเจ้าของ ค่าคงที่ `forecast.HISTORY_WEEKS`; ข้อความข้างต้นคงไว้ตามที่อนุมัติเดิม
