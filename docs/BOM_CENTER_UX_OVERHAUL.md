# วัตถุดิบและใบสั่งซื้อ — การปรับโครงเมนูและขั้นตอนงานของ BoM Center (UX overhaul)

วันที่: 2026-10-07 · สถานะ: **LIVE ครบทุกเฟส (#302–#310)** · เอกสารนี้บันทึกโครงเมนูใหม่ (IA) ข้อตัดสินใจ และสถานะงานแต่ละ PR · แผนแม่: `docs/BOM_CENTER_PLAN.md` §5.2

## 1. ที่มา

เจ้าของทดลองปิดงวดเดือน ก.ย. 2569 ครบทุกขั้นตอน (runbook 15 ขั้น) แล้วสรุปว่า **เมนูหายากและแต่ละงานหลายขั้นตอนเกินไป** หากไม่แก้ พนักงานจะไม่ใช้ ข้อเท็จจริงที่พบ

- โมดูลกระจายเป็น 3 รายการในเมนูซ้าย ("BoM Center & จัดซื้อ" · "สาขาของฉัน" · "ศูนย์สั่งสินค้า") รวม 17 หน้าใต้แถบย่อย 3 ชุด · ตัวเลือกสาขา 3 ตัว เดือน 4 ตัว ไม่เชื่อมกัน
- ไม่มีสิ่งใดบอกว่า "ต้องทำอะไรต่อ" ขั้นตอนประจำเดือนอยู่ใน runbook นอกแอป
- ระบบขอ Owner Write-Token ทั้งตอนบันทึกจริงและตอนดูตัวอย่าง และแยกไม่ได้จาก 403 เพราะสิทธิ์
- ขั้นตอนซ้ำ: อัปโหลดรายงานส่วนกลางสองครั้ง นำเข้าราคาสองครั้งเมื่อมีกฎหน่วย ปุ่มรับสินค้าตามใบสั่งซื้อหายเมื่อพ้นวันสั่ง นำเข้าผลตรวจนับอยู่ลึก 9 คลิกและ Sales Support ไม่มีสิทธิ์

## 3. โครงเมนูใหม่ — เมนูเดียว 7 ชิป 2 ระดับ

เมนูซ้าย "วัตถุดิบและใบสั่งซื้อ" เปิดที่ **หน้างาน** เสมอ · แถบด้านบนระดับ 1 = ชิป ระดับ 2 = หน้าในชิปนั้น (ซ่อนเมื่อเหลือหน้าเดียว) · ชิปแสดงเฉพาะเมื่อบทบาทเปิดหน้าในชิปนั้นได้อย่างน้อยหนึ่งหน้า (บัญชีสาขาจึงเห็น หน้างาน + สาขาของฉัน) · ชิปจำหน้าที่ใช้ล่าสุด (`localStorage supply:last:<user>`) · บัญชีสาขาบนโทรศัพท์ (≤700 px, `body.supply-phone`) ได้แถบล่าง `#supplyNav` 5 ปุ่ม (หน้างาน · ตรวจนับ · สั่งสินค้า · รับสินค้า · ผลต่าง) แทนแถวชิป (แถบชิปซ่อนทั้งหมด สถานะปลดล็อกการบันทึกเป็นไอคอนกุญแจข้างชื่อผู้ใช้ แถบบนเหลือเฉพาะชิปผู้ใช้ · session 30 วัน · ติดไอคอนแอปบนหน้าจอได้ผ่าน manifest ใน `pwa/`) และแถบปุ่มบันทึกของหน้าตรวจนับ/สั่งสินค้าเลื่อนขึ้นพ้นแถบล่าง

### 3.1 แต่ละบทบาทเริ่มที่ไหน

ทุกบทบาทที่มีโมดูลของส่วนนี้ลงที่ **หน้างาน** ซึ่งคัดงานตามโมดูลที่ถือ การ์ด "เริ่มต้นใช้งาน" ของแต่ละบทบาท (`ROLE_START`) ชี้ไปหน้าที่ใช้ประจำผ่าน `supplyGo`

| บทบาท | งานบนหน้างาน | ชิปที่ใช้ประจำ |
|---|---|---|
| สาขา (`branch`) | ตรวจนับวันนี้ · สั่งสินค้ารอบที่ถึง · ใบสั่งซื้อที่รอรับ · ผลต่างค้างเหตุผล | สาขาของฉัน (เห็นเพียง 2 ชิป) |
| Sales Support | ใบสั่งซื้อค้างคิว (แดงเมื่อเกินวันสั่ง) · นำเข้ารายงานส่วนกลาง · ผลตรวจนับ · รอบสั่งของสาขา | ใบสั่งซื้อ · ปิดงวดเดือน · ตั้งค่า · สาขาของฉัน → ผลต่างการใช้ (ยืนยันรับครบ/เหตุผลแทนสาขา ตั้งแต่ #325) |
| Ops (`operation`) | — | ใบสั่งซื้อ → ตรวจสอบการสั่ง · ปิดงวดเดือน → สรุปผลต่าง |
| ฝ่ายวิเคราะห์ (`analyst`) | ทะเบียน/ประเด็นวัตถุดิบ · รหัสสูตรเดิม · ราคาเดือนนี้ · ฉบับร่าง · ผลตรวจ · ปล่อยภายในวันที่ 25 | ข้อมูลตั้งต้น · สูตรและการปล่อย · ปิดงวดเดือน |
| บัญชี (`accounting`) | — (ไม่ถือโมดูล BoM Center ตั้งแต่ #325) | อ่านอย่างเดียว · ส่งไฟล์ราคาซื้อจริงของเดือนให้ฝ่ายวิเคราะห์นำเข้า |
| ครัว / Innovation | สูตรกึ่งสำเร็จที่ไม่ครบ | สูตรและการปล่อย (`bom.recipes`: บันทึกได้เฉพาะสูตรตาม Tier และสูตรกึ่งสำเร็จ ไม่ปล่อย) |
| ผู้บริหาร (`management`) | รับทราบเวอร์ชันที่ปล่อยแล้ว (คลิกเดียว) | ปิดงวดเดือน → สรุปผลต่าง |

### 3.2 บริบทร่วม: เดือนเดียว สาขาเดียว

`localStorage oshinei_supply_ctx = {month, branch_id}` · ตัวเลือกทุกตัว (`#bmcMonth` แถบ "เดือนราคา" ใต้หัวข้อ · `#ohbMonth` · `#ohbCloseMonth` · `#brnBranch` · `#bmcFcBranch` · `#ohbCntBranch`) อ่านค่านี้เมื่อเติมและเขียนกลับเมื่อเปลี่ยน · `supplyGo({tab, pane, month, branch, anchor, extra})` คือ deep link เดียวของทั้งโมดูล: ตั้งบริบท ตั้งหน้าใน `_SUPPLY_PANE[tab].set(pane)` แล้ว `switchTab` ครั้งเดียว (หน้าเป้าหมายเปิดถูกหน้าตั้งแต่โหลดแรก ไม่กะพริบ)

### 3.3 หน้างาน

`GET /api/bom-center/todo?month=&branch=` (`backend/bom_center/todo.py`) คืน `{items, close{steps, done, total}, release, branches}` · แต่ละงาน `{key, group, title, status: done|todo|blocked|na, detail, count, owner_modules, go, urgent}` · หน้าแสดง "งานของฉัน" (ตามโมดูลที่ผู้ใช้ถือ) · "งานของฝ่ายอื่น" พับไว้ · "ปิดงวดเดือน M" เป็นแถวสถานะ 8 ขั้น · หน้าแรก (Home) ดึงงานเร่งด่วนไม่เกิน 3 รายการเข้าคิวงานของวัน · หลังบันทึกสำเร็จทุกจุด toast "ขั้นตอนถัดไป: … →" ชี้งานถัดไป · ไม่ cache (query นับอย่างเดียว ไม่เรียก `variance.period` เมื่อไม่มีสาขาในบริบท)

### 3.4 Owner Write-Token

- `core.require_write_token` ตอบ 403 + `X-Denied: token` · การปฏิเสธเพราะสิทธิ์ (main.py) ตอบ 403 + `X-Denied: role` + `code: "role"` → หน้าเว็บถามรหัสเฉพาะกรณี token และไม่ล้าง token ที่ถูกต้องเมื่อติดสิทธิ์
- `require_write_token_unless_dry_run` บน 11 endpoint ที่มี dry run (seed/import ทะเบียน · ราคา 2 ทาง · Cost-RW · สูตร flat · กึ่งสำเร็จ 2 ทาง · ส่วนกลาง 2 ทาง · ผลตรวจนับ) · `GET /release-checks?recompute=true` ตรวจแล้ว rollback = ดูผลตรวจไม่ต้องใช้ token
- `POST /api/auth/token-check` → `{ok, gated}` · ชิป `#supplyLock` ที่ปลายขวาของแถบชิป: "ยังไม่ปลดล็อกการบันทึก" (amber) / "ปลดล็อกการบันทึกแล้ว" (green) / ซ่อนเมื่อ gate ปิด · กดเพื่อกรอกครั้งเดียวต่อเบราว์เซอร์ (test guard: `test_bom_center_token_gate.py` ยืนยันว่า dry run ทุกตัวไม่เพิ่มแถว `bc_audit`)

## 4. ขั้นตอนต่องาน ก่อน → หลัง

| งาน | เดิม | ใหม่ |
|---|---|---|
| หาเมนู | 3 รายการ (รายการที่ 11 จาก 15) หน้ากระจาย 3 ที่ | 1 รายการ → หน้างาน พร้อมรายการงาน |
| นำเข้าราคา (มีกฎหน่วยที่ระบบเสนอ) | 5–7 คลิก token ตอนดูตัวอย่าง อัปโหลด 2 ครั้ง | การ์ด → ไฟล์ → เลือกกฎ → บันทึกครั้งเดียว (`rules` ไปกับไฟล์) |
| สูตร Cost-RW | prompt 2 ครั้ง + ไฟล์ + ยืนยัน | เดือนตั้งไว้บนการ์ด ไฟล์ + ยืนยัน |
| รายงานส่วนกลางประจำเดือน | อัปโหลด 2 ครั้ง + อัปโหลดซ้ำทุกครั้งที่ติ๊กสาขา | `POST /central/month-import` อัปโหลด 1 ดูตัวอย่าง 1 ยืนยัน 1 (บัญชีสินค้า + ใบรับ transaction เดียว) |
| ผลตรวจนับจากแบบฟอร์ม | ~9 คลิก ไม่มีวันที่ Sales Support ไม่มีสิทธิ์ | สาขา/วันที่ที่ขาดเลือกให้ 4 คลิก Sales Support นำเข้าได้ |
| สาขาสั่งสินค้าต่อรอบ | 4–5 คลิก | รอบเลือกให้ (`orders.next_round`) ร่างบันทึกเอง: ส่ง + ยืนยัน |
| สาขารับสินค้าตามใบสั่งซื้อ | 5 คลิก ทำไม่ได้หลังพ้นวันสั่ง | การ์ด "ใบสั่งซื้อที่รอรับสินค้า" → เลือกใบ → ยืนยัน |
| ตรวจก่อนปล่อยสูตร | "ตรวจใหม่" (token) + prompt ต่อแถว + กระโดดไป editor | ผลตรวจแสดงทันทีเมื่อเปิด ยืนยันทั้งกลุ่มรหัสด้วยเหตุผลเดียว แก้สูตรในหน้าเดียวกัน |
| ยืนยันรับสินค้าครบ | 3 คลิกบนหน้าอื่น | ปุ่มเดียวหลังส่งผลตรวจนับปลายงวด |
| ส่งออกใบสั่งซื้อให้ผู้จำหน่าย | รวมใบส่งแล้ว/ดำเนินการแล้วเสมอ แผ่นงานรวมแผ่นเดียว | ตามชิปสถานะที่เลือก ชื่อไฟล์ระบุสถานะและช่วงวันที่ แยกแผ่นงานต่อผู้จำหน่ายได้ |
