🛡️ แนวทางตั้งค่า POS เพื่อป้องกัน "ส่วนลดรั่ว"

Easy POS · จัดทำจากผลวิเคราะห์ส่วนลดจริง · Dashboard ทำหน้าที่ ตรวจจับ + เตือน — ตัวกัน "ที่หน้างาน" จริงต้องตั้งที่ POS + กระบวนการด้านล่าง

สรุปสิ่งที่ตรวจพบ (ใช้เป็นเหตุผลของแต่ละข้อ):
  • ส่วนลดเครือ ~99% ไม่เลือกเหตุผล ("ไม่ระบุ") → คุมนโยบาย/ตรวจสอบไม่ได้
  • จุดรั่วใหญ่สุด = เงินสด + ลดหนัก ≥20% ฿2.6M, 65% อยู่อุดรธานี
  • ส่วนใหญ่ผ่าน login admin — เช่น ลดเงินสด ฿631 ซ้ำ 456 ครั้ง (รูปแบบกดลดซ้ำผิดปกติ)

ลำดับ 1 บังคับเลือก "เหตุผลส่วนลด" ทุกครั้ง

แก้ปัญหาใหญ่สุด: 99% ของส่วนลดไม่มีเหตุผล — เปิดบังคับแล้วทุกการลดจะตรวจสอบได้ทันที
  • ตั้งให้ช่องเหตุผลส่วนลดเป็น required (กดลดไม่ได้ถ้าไม่เลือกเหตุผล)
  • จัดรายการเหตุผลให้สั้น ชัด (เด็กสูง <110 · ผู้สูงอายุ · พนักงาน · โปรโมชัน · เคลม) — เลี่ยง "อื่นๆ" ที่กว้างเกินไป

ลำดับ 2 เพดาน % ส่วนลดต่อบิล + ลดเกินต้องอนุมัติ

บิลเงินสดถูกลดถึง 35–50% ของยอด — เพดาน + อนุมัติจะตัดการลดก้อนใหญ่ผิดปกติ
  • ตั้ง เพดาน % ที่พนักงานทั่วไปลดได้เอง (เช่น ≤10–15%)
  • ลดเกินเพดาน หรือเกินจำนวนเงินที่กำหนด (เช่น >฿500) → ต้องใส่รหัส manager อนุมัติ
  • ปิดการลดแบบ "กรอกตัวเลขเอง" ถ้าทำได้ — ใช้รายการส่วนลด/โปรที่กำหนดไว้แทน

ลำดับ 3 จำกัดสิทธิ์ตาม Role + เลิกใช้ login รวม "admin"

การลดส่วนใหญ่มาจาก login admin (ใช้ร่วมกัน) → ไล่ไม่ได้ว่าใครทำ
  • ให้พนักงานแต่ละคนมี login ของตัวเอง — เลิกใช้บัญชีรวม admin หน้าขาย
  • กำหนดสิทธิ์การลดตาม role (แคชเชียร์ = ลดได้จำกัด / manager = ลดได้มากกว่า)
  • ทุกการลดต้องผูกกับชื่อผู้ทำ เพื่อให้ Scorecard/Alert ไล่ที่มาได้

ลำดับ 4 คุมส่วนลดเงินสดเป็นพิเศษ

  • เงินสด + ส่วนลด = ความเสี่ยงเงินหายสูงสุด — ให้ manager สุ่มตรวจใบเสร็จเงินสดที่มีส่วนลดรายวัน
  • กระทบยอดเงินสด (cash count) เทียบยอดขาย-ส่วนลดทุกกะ

กระบวนการ รีวิว + ติดตามด้วย Dashboard

  • เปิด "ต้องดูวันนี้" / การ์ด "🚩 ส่วนลดที่ต้องระวัง" ทุกวัน — ธงด่วน (เงินสด+ลดหนัก, ลดซ้ำ, cashier เกินเกณฑ์) จะเด้งให้เห็น
  • ปรับ เกณฑ์เตือน (⚙ เกณฑ์) ให้เข้ากับนโยบายร้าน
  • เริ่มที่ อุดรธานี ก่อน (สาขารั่วอันดับ 1) แล้วใช้เป็นต้นแบบคุมสาขาอื่น
